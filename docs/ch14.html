第 14 章 · Hooks 与组件模式

副作用与 useEffect

组件的输出由 props 和 state 决定。但真实应用还要和“React 之外的世界”打交道： 读写浏览器的 localStorage、请求远程 API、设置定时器、测量元素尺寸……这些叫副作用（side-effect）。 这一章我们让搜索框记住上一次的搜索词 —— 即使关掉浏览器再打开。

本章目标

  • 理解什么是副作用，为什么不应该在渲染过程中执行它
  • 用 useEffect 把 state 同步到 localStorage
  • 彻底搞懂依赖数组的三种写法，以及清理函数
  • 对照类组件的生命周期方法，理解 useEffect 的思路转变

什么是副作用

第 3 章说过：组件函数应该像一个纯函数 —— 同样的 props 和 state，永远算出同样的 JSX，而且不改动外部任何东西。 但应用总得做点“不纯”的事，这些就是副作用：

第一版：在处理函数里写 localStorage

需求：记住最近一次搜索。思路是每次输入时存进 localStorage，启动时再读出来作为初始值：

src/App.jsx
const App = () => {
  ...

  const [searchTerm, setSearchTerm] = useState(
    localStorage.getItem('search') || 'React'
  );

  const handleSearch = (event) => {
    setSearchTerm(event.target.value);

    localStorage.setItem('search', event.target.value);
  };

  ...
};

||（逻辑或）在左边为“假值”（null、'' 等）时返回右边：localStorage 里有值就用它，否则用 'React'。 刷新浏览器试试，搜索词被记住了。

功能能用，但有个隐患：同步 localStorage 的逻辑绑在了某一个处理函数上。 将来别的地方也调用 setSearchTerm（比如一个“清空”按钮、一个“最近搜索”按钮），就得记得每处都写一遍 localStorage.setItem，漏一处就不同步。更好的方式是：不管 searchTerm 因为什么变了，都自动同步。

useEffect：状态变了就做点什么

src/App.jsx
import { useState, useEffect } from 'react';

const App = () => {
  ...

  const [searchTerm, setSearchTerm] = useState(
    localStorage.getItem('search') || 'React'
  );

  useEffect(() => {
    localStorage.setItem('search', searchTerm);
  }, [searchTerm]);

  const handleSearch = (event) => {
    setSearchTerm(event.target.value);
  };

  ...
};

useEffect 接收两个参数：

  1. 副作用函数：要执行的操作。React 会在把界面画到屏幕之后再执行它，不阻塞渲染。
  2. 依赖数组：一组值。只有当其中某个值和上一次渲染时不同，副作用才会再次执行。

现在，不论 searchTerm 在哪里、因为什么被更新，localStorage 都会自动同步。 同步逻辑集中在一个地方，这就是 useEffect 比“写在处理函数里”更健壮的原因。

依赖数组的三种写法

写法什么时候执行典型用途
useEffect(fn)每次渲染后很少需要，小心性能问题和死循环
useEffect(fn, [])只在组件第一次出现（挂载）后初始化时请求一次数据、订阅一次事件
useEffect(fn, [a, b])挂载后 + a 或 b 变化后把某个状态同步到外部（本章的 localStorage）
⚠ 依赖要写全

副作用函数里用到的所有来自组件内部的值（props、state、组件内定义的变量和函数）都应该写进依赖数组。 漏写会让副作用读到过期（stale）的值。Vite 模板自带的 ESLint 规则 react-hooks/exhaustive-deps 会自动提醒你 —— 请认真对待它的警告，不要随手关掉。

清理函数

副作用函数可以返回一个函数，React 会在下一次执行副作用之前、以及组件从页面上消失（卸载）时调用它， 用来撤销副作用：取消定时器、取消订阅、中止请求。

JSX
useEffect(() => {
  const id = setInterval(() => {
    console.log('tick');
  }, 1000);

  // 清理函数：组件卸载或依赖变化时执行
  return () => {
    clearInterval(id);
  };
}, []);
ⓘ 开发环境下 effect 跑了两次？

React 18 起，StrictMode 在开发环境会对每个组件执行一遍“挂载 → 卸载 → 再挂载”， 所以 effect 会运行两次（中间夹着一次清理）。这是故意的：如果你的 effect 缺少正确的清理，这样一跑就会暴露问题。 生产环境只运行一次。第 28 章会再次讨论这一点。

思路转变：从生命周期到“同步”

类组件时代，副作用按“时间点”来写：挂载时做什么、更新时做什么、卸载时做什么。 同一件事（比如订阅）的逻辑被拆散在三个方法里：

类组件生命周期 旧写法
JSX
class App extends React.Component {
  componentDidMount() {
    localStorage.setItem('search', this.state.searchTerm);
  }

  componentDidUpdate(prevProps, prevState) {
    // 要自己比较前后值
    if (prevState.searchTerm !== this.state.searchTerm) {
      localStorage.setItem('search', this.state.searchTerm);
    }
  }

  componentWillUnmount() {
    // 清理逻辑写在另一个方法里
  }
}
useEffect 现在
JSX
const App = () => {
  ...
  // “让 localStorage 和 searchTerm 保持同步”
  useEffect(() => {
    localStorage.setItem('search', searchTerm);

    return () => {
      // 清理逻辑和设置逻辑写在一起
    };
  }, [searchTerm]);
};

useEffect 的正确心智模型不是“在某个生命周期做某事”，而是“让某个外部系统和当前的 state 保持同步”。 你声明同步的逻辑和它依赖哪些值，React 负责在合适的时候执行和清理。

💡 你可能并不需要 Effect

useEffect 是给“和外部系统同步”准备的。下面这些情况不应该用它：

  • 根据 state 计算另一个值 → 直接在渲染时计算（第 11 章的派生值）。
  • 响应用户的某个操作（点击后发请求、提交后提示）→ 写在事件处理函数里。
  • props 变化时重置状态 → 给组件换一个 key。

React 19.2 还新增了 useEffectEvent，用来从 effect 里调用“需要读取最新值、但又不应该成为依赖”的逻辑，属于进阶话题，遇到时再查文档即可。

两个小改进

用 ?? 代替 ||

试试把搜索框清空，然后刷新页面：显示的是 “React” 而不是空的。因为 '' 是假值，|| 会跳到右边。 空值合并运算符 ?? 只在左边是 null 或 undefined 时才用右边的值：

JSX
useState(localStorage.getItem('search') ?? 'React');

惰性初始值

useState(localStorage.getItem('search') ?? 'React') 里的 localStorage.getItem 其实每次渲染都会执行 （只是结果在第一次之后被忽略）。如果初始值的计算比较昂贵，可以传一个函数，React 只在第一次渲染时调用它：

JSX
const [searchTerm, setSearchTerm] = useState(
  () => localStorage.getItem('search') ?? 'React'
);

小结

  • 副作用是和 React 外部世界打交道的操作；渲染本身应保持纯净。
  • useEffect(fn, deps) 在界面更新后执行 fn，依赖变化时重新执行；空数组表示只在挂载时执行。
  • 返回的清理函数在下次执行前和卸载时调用。
  • 把 useEffect 理解为“同步”而不是“生命周期”；派生值和用户操作的响应不需要 effect。

动手练习

  1. 在 effect 里加 console.log，分别试试不写依赖、写 []、写 [searchTerm]，观察打印时机。
  2. 清空搜索框再刷新，确认 || 的问题，然后换成 ??。
  3. 再写一个 effect：把 document.title 设置为 “搜索：xxx”。
  4. 写一个每秒打印一次的定时器 effect，先不写清理函数，观察 StrictMode 下的表现；再加上清理函数对比。

面试题

useEffect 是做什么的？

让函数组件执行副作用，并与外部系统（网络、存储、DOM、订阅等）保持同步。它在渲染提交到屏幕之后运行。

依赖数组的作用？不写、写空数组、写值有什么区别？

决定 effect 何时重新执行：不写则每次渲染后执行；空数组只在挂载后执行一次；有值则在挂载后及任一依赖变化后执行。

清理函数什么时候执行？

在下一次执行该 effect 之前，以及组件卸载时。

为什么开发环境下 effect 执行了两次？

StrictMode 会模拟“挂载-卸载-再挂载”，以检查 effect 是否正确清理；生产环境不会。

useEffect 和类组件生命周期方法是什么关系？

它可以覆盖 componentDidMount / DidUpdate / WillUnmount 的场景，但思路不同：按“同步什么”组织代码，而不是按“什么时间点”，相关的设置与清理逻辑写在一起。

一个组件可以有多个 useEffect 吗？

可以，而且推荐按关注点拆分：每个 effect 只负责一件事。
