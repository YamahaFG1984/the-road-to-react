路由：React Router

到目前为止，Hacker Stories 只有一个页面。真实应用几乎都有多个“页面”：列表页、详情页、设置页…… 而单页应用只有一个 index.html。客户端路由负责把浏览器地址栏里的 URL 映射到不同的组件， 并且切换时不刷新页面。这一章用 React 生态里最主流的路由库 React Router，给 Hacker Stories 加上文章详情页。

本章目标

  • 理解客户端路由的原理：URL 变了，页面不刷新，渲染的组件换了
  • 用 createBrowserRouter 配置路由、嵌套路由和布局
  • 用 Link 导航，用 useParams 读取 URL 参数，用 loader 加载页面数据
  • 把搜索词放进 URL（useSearchParams），让搜索结果可以分享
  • 解决部署到 GitHub Pages 子路径时的 404 问题

客户端路由是怎么回事

第 1 章说过，传统网站每个 URL 对应服务器上的一个页面，点链接就整页刷新。单页应用只有一个 HTML， 但我们仍然希望：地址栏能反映当前在看什么、能收藏和分享链接、浏览器的前进后退按钮能用。客户端路由就是做这件事的：

安装与三种用法

命令行
npm install react-router

React Router v7 起，包名统一成了 react-router（以前叫 react-router-dom，现在它只是一个转发包）。 v7 还合并了 Remix 框架，提供三种用法，从简单到完整：

模式写法特点
声明式（Declarative）<BrowserRouter> + <Routes> + <Route>最简单，只负责 URL ↔ 组件
数据式（Data）本章createBrowserRouter + <RouterProvider>在此基础上增加 loader（加载数据）、action（提交）、errorElement（错误处理）
框架式（Framework）Vite 插件 + 文件路由就是以前的 Remix：服务端渲染、代码分割、类型生成（第 49 章）

配置路由

先把现在的 App 改名为 StoriesPage（它就是列表页），再新建一个布局组件和详情页。 路由在入口文件里配置：

src/main.jsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import { createBrowserRouter, RouterProvider } from 'react-router';

import './index.css';
import { Layout } from './Layout';
import { StoriesPage } from './StoriesPage';
import { StoryPage, storyLoader } from './StoryPage';
import { NotFound } from './NotFound';

const router = createBrowserRouter(
  [
    {
      path: '/',
      element: <Layout />,
      children: [
        { index: true, element: <StoriesPage /> },
        {
          path: 'story/:storyId',
          element: <StoryPage />,
          loader: storyLoader,
        },
        { path: '*', element: <NotFound /> },
      ],
    },
  ],
  { basename: import.meta.env.BASE_URL }
);

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <RouterProvider router={router} />
  </StrictMode>
);
  • path: '/' + children：嵌套路由。所有子页面共享 Layout。
  • index: true：父路径本身（/）显示什么。
  • :storyId：动态参数，匹配 /story/42、/story/abc 等，值可以在组件里读取。
  • path: '*'：兜底，所有没匹配上的地址都显示 404 页。
  • basename：应用部署在子路径时的前缀。import.meta.env.BASE_URL 就是 vite.config.js 里的 base（第 52 章）。

用 Link 导航

在列表的每一项加一个“详情”链接：

src/StoriesPage.jsx
import { Link } from 'react-router';

const Item = ({ item, onRemoveItem }) => (
  <li>
    <span>
      <a href={item.url}>{item.title}</a>
    </span>
    <span>{item.author}</span>
    <span>{item.num_comments}</span>
    <span>{item.points}</span>
    <span>
      <Link to={`/story/${item.objectID}`}>Details</Link>
      <button type="button" onClick={() => onRemoveItem(item)}>
        Dismiss
      </button>
    </span>
  </li>
);
<a href>：整页刷新
JSX
<a href="/story/42">Details</a>
// 浏览器向服务器请求 /story/42
// 所有 JS 重新下载、所有状态丢失
<Link to>：客户端导航
JSX
<Link to="/story/42">Details</Link>
// 渲染成 <a>，但点击时被拦截
// 只改 URL、切换组件，状态保留

站内跳转用 Link，指向外部网站用普通 <a>（比如文章标题链接到原文）。 NavLink 是会自动给“当前页面”加上 active 类名的 Link，适合导航菜单； 需要在代码里跳转（比如提交成功后）时用 useNavigate()：navigate('/')、navigate(-1)（后退）。

详情页：useParams 与 loader

Hacker News API 提供了单篇文章的接口：https://hn.algolia.com/api/v1/items/42，返回文章及其评论树。 详情页需要：从 URL 拿到 storyId，再用它请求数据。按照前面学的，可以这样写：

src/StoryPage.jsx（effect 版）
import { useEffect, useState } from 'react';
import { useParams } from 'react-router';

const StoryPage = () => {
  const { storyId } = useParams();
  const [story, setStory] = useState(null);

  useEffect(() => {
    fetch(`https://hn.algolia.com/api/v1/items/${storyId}`)
      .then((response) => response.json())
      .then(setStory);
  }, [storyId]);

  if (!story) return <p>Loading ...</p>;

  return <h2>{story.title}</h2>;
};

能用，但数据要等组件渲染之后才开始请求。数据式路由提供了更好的办法：loader。 它在路由匹配上的那一刻（组件渲染之前）就开始加载数据：

src/StoryPage.jsx（loader 版）
import { Link, useLoaderData, useNavigate } from 'react-router';

const storyLoader = async ({ params }) => {
  const response = await fetch(
    `https://hn.algolia.com/api/v1/items/${params.storyId}`
  );

  if (!response.ok) {
    throw new Response('Story not found', { status: 404 });
  }

  return response.json();
};

const StoryPage = () => {
  const story = useLoaderData();
  const navigate = useNavigate();

  return (
    <article>
      <button type="button" onClick={() => navigate(-1)}>
        ← Back
      </button>

      <h2>
        <a href={story.url}>{story.title}</a>
      </h2>
      <p>
        by {story.author} · {story.points} points ·{' '}
        {story.children.length} top-level comments
      </p>

      <ul>
        {story.children.map((comment) => (
          <li key={comment.id}>{comment.author}</li>
        ))}
      </ul>

      <Link to="/">All stories</Link>
    </article>
  );
};

export { StoryPage, storyLoader };
⚠ 评论内容是 HTML

API 返回的评论正文 comment.text 是一段 HTML 字符串。直接 {comment.text} 会显示出一堆标签； 用 dangerouslySetInnerHTML 则有 XSS 风险（第 4 章）。所以示例里只显示作者。真要显示正文，应先用 DOMPurify 之类的库做净化。

URL 也是状态：useSearchParams

现在搜索 “vue” 后，地址栏还是 /。把链接发给朋友，他看到的是默认的 React 搜索结果。 如果把搜索词放进 URL 的查询参数 —— /?query=vue —— 搜索结果就可以被收藏、分享、前进后退了：

src/StoriesPage.jsx
import { useSearchParams } from 'react-router';

const StoriesPage = () => {
  const [searchParams, setSearchParams] = useSearchParams();
  const query = searchParams.get('query') ?? 'React';

  // 输入框里正在编辑的文字，仍然是普通的组件状态
  const [searchTerm, setSearchTerm] = useState(query);

  const searchAction = () => {
    // 提交时写进 URL，URL 一变，下面的请求就会重新执行
    setSearchParams({ query: searchTerm });
  };

  useEffect(() => {
    // 根据 URL 里的 query 请求数据 ...
  }, [query]);

  ...
};

这是第 45 章要讲的一个重要观点：状态有不同的“家”。“当前搜索的是什么”这种希望被分享、被收藏的状态，最适合放在 URL 里。

部署到 GitHub Pages 时的 404 问题

在本地一切正常，部署到 GitHub Pages 后，直接打开 https://用户名.github.io/hacker-stories/story/42 却是 GitHub 的 404 页面。 原因是：服务器上根本不存在 story/42 这个文件，它不知道应该返回 index.html 交给前端路由处理。

package.json
{
  "scripts": {
    "build": "vite build && cp dist/index.html dist/404.html"
  }
}

另一种办法是改用 createHashRouter：地址变成 /#/story/42，# 后面的部分不会发给服务器，永远不会 404，代价是网址不太好看。 Firebase、Netlify、Vercel 等平台则可以直接配置“所有路径重写到 index.html”。

新旧对照

React Router v5 旧写法
JSX
import {
  BrowserRouter, Switch, Route, useHistory,
} from 'react-router-dom';

<BrowserRouter>
  <Switch>
    <Route exact path="/" component={StoriesPage} />
    <Route path="/story/:storyId" component={StoryPage} />
  </Switch>
</BrowserRouter>

const history = useHistory();
history.push('/');
React Router v7 现在
JSX
import {
  createBrowserRouter, RouterProvider, useNavigate,
} from 'react-router';

const router = createBrowserRouter([
  { path: '/', element: <StoriesPage /> },
  { path: '/story/:storyId', element: <StoryPage /> },
]);

<RouterProvider router={router} />

const navigate = useNavigate();
navigate('/');
  • Switch → Routes（v6 起），不再需要 exact，匹配规则更智能。
  • component={X} → element={<X />}，可以直接传 props。
  • useHistory → useNavigate。
  • v6.4 起加入 loader / action 等数据 API；v7 合并 Remix，包名简化为 react-router。

小结

  • 客户端路由在不刷新页面的情况下，把 URL 映射到组件；React Router 是最常用的方案。
  • createBrowserRouter 定义路由表；嵌套路由 + <Outlet /> 实现共享布局；:param 定义动态参数，* 兜底。
  • 站内跳转用 Link / NavLink / useNavigate；读取参数用 useParams。
  • loader 在路由切换时就开始加载数据，组件里用 useLoaderData() 读取。
  • 可分享的状态（如搜索词）适合放进 URL：useSearchParams。
  • 部署到 GitHub Pages：设置 basename，并复制 index.html 为 404.html。

面试题

客户端路由的原理是什么？

拦截站内链接点击，用 History API（pushState）修改 URL 而不向服务器请求新页面，再根据 URL 匹配路由表渲染对应组件；监听 popstate 以支持前进后退。

Link 和 a 标签有什么区别？

Link 渲染为 a 标签，但点击时阻止默认的整页跳转，改为客户端导航，保留应用状态；外部链接仍用 a。

什么是 loader？相比在 useEffect 中请求有什么好处？

路由级的数据加载函数，在路由匹配时（组件渲染前）执行，避免“先渲染再请求”的瀑布；组件无需管理加载状态，错误可统一交给路由的错误元素处理。

为什么部署 SPA 后直接访问子路径会 404？

服务器上没有该路径对应的文件。需要配置服务器把所有路径回退到 index.html，或在 GitHub Pages 上提供与 index.html 相同的 404.html，或使用 hash 路由。

哪些状态适合放在 URL 里？

需要分享、收藏、刷新后保留、或与前进后退关联的状态，如搜索词、筛选条件、分页、当前选中的标签页。
