路由与框架选型

到目前为止，Hacker Stories 是一个用 Vite 构建的纯客户端单页应用（SPA）。这是学习 React 最好的起点，但不是所有项目的最佳形态。 需要搜索引擎收录的网站、首屏要快的电商、需要后端接口的全栈应用……可能更适合用框架。 这一章梳理几种渲染方式，比较主流的路由库和框架，帮你判断新项目该从哪里开始。

本章目标

  • 理解 CSR、SSR、SSG 和服务端组件这几种渲染方式
  • 比较 React Router 与 TanStack Router
  • 比较 Next.js、React Router 框架模式、TanStack Start、Astro
  • 根据项目需求决定：纯 SPA 还是框架，选哪个

几种渲染方式

第 1 章讲过“服务器渲染 → 浏览器渲染”的历史。今天的 React 框架可以在这两者之间自由组合：

CSRSSRSSGRSC
HTML 在哪生成浏览器服务器（每次请求）构建时服务器（组件级）
首屏速度慢快最快快
SEO弱好好好
部署任何静态托管需要 Node 等服务器任何静态托管需要支持的平台
适合后台、登录后的应用、工具类电商、动态内容博客、文档、营销页全栈应用
★ 什么时候纯 SPA 就够了

登录后才能用的应用（管理后台、SaaS 工作台、内部工具）不需要 SEO，用户也会长时间停留，首屏多等几百毫秒无所谓 —— Vite + React Router 的 SPA 简单、部署便宜（静态托管即可），完全够用。本教程的 Hacker Stories 就属于这一类。

怎么选

ⓘ React 官方的建议

react.dev 在“创建新 React 应用”中推荐优先使用框架（Next.js、React Router 等），因为它们内置了路由、数据加载、代码分割、服务端渲染等生产环境需要的能力； 同时也提供了“从零搭建”（Vite 等构建工具）的指南，适合学习、纯客户端应用或已有特殊架构的场景。本教程先用 Vite 学透 React 本身， 第 51 章再体验框架 —— 这是最稳妥的学习顺序。

小结

  • 渲染方式：CSR（浏览器）、SSR（每次请求在服务器）、SSG（构建时）、RSC（组件级服务端运行）。
  • 登录后使用的应用，Vite SPA + React Router 往往就够了；需要 SEO、首屏性能或后端逻辑时考虑框架。
  • 路由库：React Router 最通用，TanStack Router 类型安全最强。
  • 框架：Next.js 生态最大、最先支持新特性；React Router 框架模式从 SPA 升级最平滑；Astro 适合内容站。

面试题

CSR、SSR、SSG 的区别？

CSR 在浏览器中用 JS 生成页面；SSR 在每次请求时由服务器生成 HTML；SSG 在构建时预先生成静态 HTML。SSR/SSG 首屏更快、SEO 更好，CSR 部署简单。

什么是 hydration（水合 / 激活）？

服务器返回已渲染好的 HTML 后，客户端 React 加载并把事件处理和状态“附着”到这份 HTML 上，使其变得可交互。

什么时候选择纯 SPA 而不是框架？

不需要 SEO 和极致首屏（如登录后的后台、内部工具），希望部署简单（静态托管）、后端已独立存在时。

Next.js 和 React Router 框架模式怎么选？

需要服务端组件和最大生态选 Next.js；希望贴近 Web 标准、从现有 React Router SPA 平滑升级、部署平台自由度高时选 React Router 框架模式。
