接下来去哪里

作者的建议是：先别急着读下一本书。花一周时间扩展这个应用，或者用一个自己感兴趣的 API 做一个新项目，部署上线，拿给别人看。 本教程已经带你走过了路由、状态管理、数据请求、生态选型和 Next.js 入门。接下来可以按兴趣继续深入：

  • 全栈深入：第 51 章只是入门。Next.js 的缓存机制、流式渲染、中间件、部署和监控都值得系统学习。
  • 后端与数据库：让数据跨会话保存、在用户之间共享。可以从 Firebase、Supabase 这类托管服务开始，再学 Node.js、SQL 和 ORM，以及认证与授权。
  • TypeScript 进阶：泛型组件、类型推导、用 tRPC / OpenAPI 实现端到端类型安全（第 46 章）。
  • React 原理：Fiber 架构、协调（reconciliation）算法、调度与并发渲染。理解原理后，第 28、39 章的优化会更有把握。
  • 工程化：从零用 Webpack + Babel 搭一个 React 项目，理解 Vite 在背后替你做了什么；再了解 Monorepo 和 CI/CD。
  • 性能：Core Web Vitals 指标、包体积分析、虚拟列表、图片与字体优化。
  • 质量：Playwright 端到端测试、视觉回归测试、定期的可访问性审计（第 43 章）。
  • UI 组件：试着自己写一套小型组件库（按钮、下拉框、对话框），再对照 Radix 等库的实现 —— 这是理解可访问性和组件 API 设计的最好练习。
  • React Native：用 React 写 iOS / Android 应用。核心概念相同，区别在于布局组件、构建工具和平台 API。
💡 最后的建议

学框架最快的方式永远是动手做点什么。找一个你真正感兴趣的 API —— 天气、电影、股票、游戏、GitHub —— 用本教程学到的东西做一个小应用，部署出去。遇到问题回来翻对应的章节。做完一个完整的项目，胜过读十篇教程。

小结

  • React 的核心只有几条：组件是函数、UI 是状态的函数、数据向下流、事件向上传、副作用放在渲染之外。
  • 读老代码时，用新旧对照表把类组件、生命周期、forwardRef、onSubmit+preventDefault 等翻译成现代写法。
  • 选库时先问“需不需要”，再按评估清单比较；每类状态只交给一个库管理（第 44–50 章）。
  • 下一步：做自己的项目，然后按需深入全栈、后端、TypeScript、React 原理、性能等方向。
