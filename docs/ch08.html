事件处理函数

到目前为止，页面只会“显示”，不会“响应”。这一章我们给搜索框加上第一个交互： 用户每敲一个字，我们都能拿到输入框里的内容。你会学到 React 声明式的事件写法， 以及初学者踩得最多的一个坑。

本章目标

  • 在 JSX 里用 onChange、onClick 等属性绑定事件处理函数
  • 理解 React 的合成事件对象和 event.target.value
  • 分清“传函数”和“传函数调用的结果”
  • 了解 React 事件系统和原生事件、旧版本 React 的几处不同

给输入框加一个处理函数

原生 JavaScript 里，你会先找到 DOM 节点，再用 addEventListener 挂上监听器。 React 里不需要找节点 —— 直接在 JSX 上声明“发生这个事件时调用这个函数”。

先把 Search 从简洁体改回块体，这样才能在 return 之前定义函数：

src/App.jsx
const Search = () => {
  const handleChange = (event) => {
    // 合成事件对象
    console.log(event);
    // 输入框当前的值
    console.log(event.target.value);
  };

  return (
    <div>
      <label htmlFor="search">Search: </label>
      <input id="search" type="text" onChange={handleChange} />
    </div>
  );
};

打开浏览器控制台，在输入框里打字，每敲一个键就会打印一次事件对象和当前的值。 这个函数就叫事件处理函数（event handler），习惯以 handle 开头命名： handleChange、handleClick、handleSubmit。

命令式：原生 DOM
JavaScript
const input = document.getElementById('search');

input.addEventListener('input', (event) => {
  console.log(event.target.value);
});
声明式：React
JSX
const handleChange = (event) => {
  console.log(event.target.value);
};

<input id="search" onChange={handleChange} />

合成事件

你在控制台里看到的 event 不是浏览器原生事件，而是 React 包装过的 合成事件（SyntheticEvent）。它的接口和原生事件几乎一样 —— event.target、event.preventDefault()、event.stopPropagation() 都在 —— 但抹平了不同浏览器之间的差异。真的需要原生事件时，可以用 event.nativeEvent， 不过实际开发中几乎用不到。

⚠ React 的 onChange 和原生 change 事件不一样

原生 HTML 的 change 事件要等输入框失去焦点才触发； React 的 onChange 在每一次输入时都触发（行为其实等同于原生的 input 事件）。 这是 React 有意为之的设计，方便做实时搜索、实时校验。

传函数，别传调用结果

这是 React 初学者最常见的 bug 之一，一定要记牢：

❌ 错误
JSX
// 渲染时就立即调用了 handleChange，
// 把它的返回值（undefined）交给了 onChange
<input onChange={handleChange()} />
✅ 正确
JSX
// 把函数本身交给 onChange，
// 等事件发生时由 React 来调用
<input onChange={handleChange} />

唯一的例外：如果 handleChange() 本身返回的是一个函数，那加括号就是对的。 但初学阶段先记住“不加括号”。需要传额外参数的写法 onClick={() => handleRemove(item)} 会在第 18 章讲。

React 事件系统的演变

如果你读到旧代码或旧文章，可能会遇到下面这些已经过时的说法：

主题旧行为 React ≤ 16现在 React 17+
事件委托挂在哪里统一挂在 document 上挂在 React 的根容器（#root）上，多个 React 版本可以共存
事件池事件对象会被复用，异步访问要先调用 event.persist()取消事件池，event.persist() 不再需要（调用也无效果）
onScroll会冒泡不冒泡，和浏览器一致
类组件里的 this要在构造函数里 this.handleClick = this.handleClick.bind(this)函数组件没有 this，处理函数就是普通闭包
类组件的事件处理 旧写法
JSX
class Search extends React.Component {
  constructor(props) {
    super(props);
    // 不 bind 的话，this 会是 undefined
    this.handleChange = this.handleChange.bind(this);
  }

  handleChange(event) {
    console.log(event.target.value);
  }

  render() {
    return <input onChange={this.handleChange} />;
  }
}
函数组件 现在
JSX
const Search = () => {
  const handleChange = (event) => {
    console.log(event.target.value);
  };

  return <input onChange={handleChange} />;
};

小结

  • 在 JSX 上用 onXxx={函数} 声明事件处理函数，事件名是驼峰的（onClick、onChange、onBlur）。
  • 处理函数收到 React 的合成事件，用 event.target.value 读取输入框的值。
  • 传函数本身 onChange={fn}，不要传调用结果 onChange={fn()}。
  • React 的 onChange 每次输入都触发；事件池、bind(this) 都是旧时代的产物。

动手练习

  1. 给输入框再加一个 onBlur 处理函数，在输入框失去焦点时打印一句话。
  2. 在页面上加一个按钮，点击时 console.log('clicked')。然后故意写成 onClick={handleClick()}，观察什么时候打印。
  3. （选读）了解事件冒泡与捕获：给外层 div 加 onClick，点击里面的按钮，看看两个处理函数的执行顺序；再试试 onClickCapture。

面试题

React 中如何绑定事件处理函数？

在 JSX 元素上使用驼峰命名的事件属性，并传入函数引用，例如 <button onClick={handleClick}>。

什么是合成事件（SyntheticEvent）？

React 对浏览器原生事件的跨浏览器包装，提供与原生一致的接口；原生事件可通过 event.nativeEvent 获取。

如何给事件处理函数传递额外参数？

用箭头函数包一层：onClick={() => handleClick(id)}。

event.preventDefault() 和 event.stopPropagation() 分别做什么？

前者阻止浏览器默认行为（如表单提交刷新页面、链接跳转）；后者阻止事件继续冒泡到父元素。

event.target 是什么？

触发事件的那个 DOM 元素，可以读取它的属性，比如输入框的 value。
