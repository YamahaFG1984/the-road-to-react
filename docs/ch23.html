第三方库与 async/await

React 只是一个界面库，其余的事情常常交给第三方库。这一章用流行的 HTTP 库 axios 替换 fetch， 学会从 npm 安装和使用一个库；然后把 .then().catch() 链改写成更易读的 async/await。

本章目标

  • 用 npm 安装第三方库并在组件中使用
  • 对比 fetch 和 axios
  • 把 Promise 链改写为 async/await + try/catch
  • 知道为什么不能把 useEffect 的回调直接写成 async 函数

为什么考虑换掉 fetch

fetch 是浏览器原生 API，零依赖，简单场景完全够用。但它有几处不太顺手： 要手动 response.json()；HTTP 404/500 不会被当作错误（第 21 章）； 没有请求/响应拦截器、超时配置等高级功能。早些年，老浏览器和测试环境（无头浏览器）里甚至没有 fetch，还需要 polyfill。 axios 是解决这些问题最流行的库之一。

安装与使用 axios

命令行
npm install axios

安装后它会出现在 package.json 的 dependencies 里。在文件顶部导入：

src/App.jsx
import { useState, useEffect, useRef, useReducer, useCallback } from 'react';
import axios from 'axios';

用法和 fetch 几乎一样：传入地址，返回 Promise。区别是 axios 已经把 JSON 解析好，放在响应对象的 data 属性里：

src/App.jsx
const handleFetchStories = useCallback(() => {
  dispatchStories({ type: 'STORIES_FETCH_INIT' });

  axios
    .get(url)
    .then((result) => {
      dispatchStories({
        type: 'STORIES_FETCH_SUCCESS',
        payload: result.data.hits,
      });
    })
    .catch(() =>
      dispatchStories({ type: 'STORIES_FETCH_FAILURE' })
    );
}, [url]);

ⓘ 今天还需要 axios 吗？

今天所有现代浏览器和 Node.js 都内置了 fetch，“兼容性”已不再是换 axios 的理由。选择它主要是因为 API 更顺手。 很多项目直接用 fetch 再封装一个小函数，也有很多项目用 axios —— 两者都是合理的选择。 本教程跟随原书使用 axios，第 31 章的测试也会用到它。

async/await

.then().catch() 链在步骤多时会层层嵌套。async/await 让异步代码读起来像同步代码。 先不考虑错误处理：

src/App.jsx
const handleFetchStories = useCallback(async () => {
  dispatchStories({ type: 'STORIES_FETCH_INIT' });

  const result = await axios.get(url);

  dispatchStories({
    type: 'STORIES_FETCH_SUCCESS',
    payload: result.data.hits,
  });
}, [url]);

函数前加 async，就可以在里面用 await 等待 Promise。await 之后的代码会等 Promise 兑现后才执行。 错误处理用普通的 try/catch：

src/App.jsx
const handleFetchStories = useCallback(async () => {
  dispatchStories({ type: 'STORIES_FETCH_INIT' });

  try {
    const result = await axios.get(url);

    dispatchStories({
      type: 'STORIES_FETCH_SUCCESS',
      payload: result.data.hits,
    });
  } catch {
    dispatchStories({ type: 'STORIES_FETCH_FAILURE' });
  }
}, [url]);

两种写法都没错，团队统一一种即可。多数现代代码偏向 async/await，因为不需要嵌套回调。 （catch { 后面省略 (error) 是 ES2019 的写法，不需要用到错误对象时可以这样写。）

不能把 effect 回调写成 async

一个非常常见的错误写法：

❌ 错误
JSX
useEffect(async () => {
  const result = await axios.get(url);
  setData(result.data);
}, [url]);
✅ 正确
JSX
useEffect(() => {
  const fetchData = async () => {
    const result = await axios.get(url);
    setData(result.data);
  };

  fetchData();
}, [url]);

原因：async 函数总是返回一个 Promise，而 effect 的返回值必须是清理函数或 undefined。 React 会发出警告，而且你也没法再返回清理函数了。正确做法是在 effect 里面定义一个 async 函数然后调用它 —— 或者像本书这样，把 async 函数定义在 effect 外面（用 useCallback 包裹），在 effect 里调用。

小结

  • npm install 包名 安装第三方库，import 后即可使用。
  • axios 自动解析 JSON（结果在 result.data）、非 2xx 状态自动视为错误；fetch 是零依赖的原生选择。
  • async/await + try/catch 让异步代码像同步代码一样从上往下读。
  • 不要把 useEffect 的回调直接写成 async 函数，在内部定义并调用 async 函数。

面试题

axios 和 fetch 有什么区别？

fetch 是原生 API，需要手动解析 JSON，HTTP 错误状态不会 reject；axios 是第三方库，自动解析 JSON、非 2xx 自动 reject，并提供拦截器、超时等功能。

async/await 和 .then() 有什么区别？

本质相同，都基于 Promise。async/await 语法让异步代码像同步代码一样书写，用 try/catch 处理错误，可读性通常更好。

为什么 useEffect 的回调不能是 async 函数？

async 函数返回 Promise，而 effect 只能返回清理函数或 undefined。应在 effect 内部定义 async 函数并调用。

如何并发执行多个异步请求？

使用 Promise.all([...])（或 Promise.allSettled）等待多个 Promise。
