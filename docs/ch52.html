构建与部署

到目前为止，应用只运行在你电脑上的开发服务器里，别人看不到。这一章把它构建成可以发布的静态文件， 然后部署到互联网上。原书用的是 Firebase Hosting；鉴于很多读者（包括本教程本身）使用 GitHub，这里同时介绍如何部署到 GitHub Pages。

本章目标

  • 理解开发环境和生产环境的区别，用 npm run build 生成 dist/
  • 用 npm run preview 在本地验证构建结果
  • 部署到 Firebase Hosting
  • 用 GitHub Actions 自动部署到 GitHub Pages

构建

开发时，Vite 的开发服务器按需编译每个文件，方便调试、支持热更新，但文件多、体积大、没有优化。 上线前要做一次构建（build）：把所有代码打包（bundling）、去掉开发用的代码、压缩（minification）， 生成尽可能少、尽可能小的几个文件。

命令行
npm run build
控制台输出
vite vX.Y.Z building for production...
✓ 95 modules transformed.
dist/index.html                   0.46 kB │ gzip:  0.30 kB
dist/assets/index-DiwrgTda.css    1.39 kB │ gzip:  0.72 kB
dist/assets/index-C9Xk3pLq.js   234.51 kB │ gzip: 75.61 kB
✓ built in 1.02s

文件名里的哈希（C9Xk3pLq）根据内容生成，内容一变名字就变。这样服务器可以让浏览器长期缓存这些文件， 发布新版本时浏览器又会自动下载新文件。

部署之前，先在本地预览构建结果：

命令行
npm run preview

它会启动一个本地静态服务器（通常是 http://localhost:4173）来提供 dist/ 里的文件。看起来应该和 npm run dev 时一模一样。

★ 纯客户端 React 应用 = 静态文件

dist/ 里只有 HTML、JS、CSS 和图片，不需要 Node.js 服务器来运行。所以它可以部署到任何静态托管服务： GitHub Pages、Firebase Hosting、Netlify、Vercel、Cloudflare Pages，甚至任何 Nginx 服务器。 （使用了服务端组件等特性的 Next.js 应用则需要支持服务端运行的平台。）

部署到 Firebase Hosting

先全局安装 Firebase 命令行工具（以后更新也用同一条命令）：

命令行
npm install -g firebase-tools

在 Firebase 控制台 注册并创建一个项目，然后在命令行登录：

命令行
firebase login

在项目目录里初始化 Hosting：

命令行
firebase init

按提示选择：

输出
? Which Firebase features do you want to set up for this directory?
  ◉ Hosting: Configure files for Firebase Hosting ...

? Please select an option:
  ❯ Use an existing project        （或 Create a new project）

? What do you want to use as your public directory? dist
? Configure as a single-page app (rewrite all urls to /index.html)? Yes
? Set up automatic builds and deploys with GitHub? No
  • public 目录填 dist：这是 Vite 的构建输出目录（Firebase 默认是 public，千万别选错）。
  • 单页应用选 Yes：所有路径都返回 index.html，以后加了客户端路由也能正常工作。

然后构建并部署：

命令行
npm run build
firebase deploy
控制台输出
✔  Deploy complete!

Project Console: https://console.firebase.google.com/project/my-react-project-abc123/overview
Hosting URL: https://my-react-project-abc123.web.app
⚠ 打开是空白页？

检查 firebase.json 里的 "public" 是不是 "dist"；确认部署前执行过 npm run build； 再打开浏览器控制台看看是不是有 404 的资源文件。

部署到 GitHub Pages

GitHub Pages 免费托管静态网站，地址是 https://用户名.github.io/仓库名/。注意这个地址带有子路径 /仓库名/， 这是部署时最容易踩的坑。

第一步：配置 base 路径

Vite 默认假设网站部署在域名根目录，生成的资源路径是 /assets/index.js。部署在子路径下时， 浏览器会去 https://用户名.github.io/assets/index.js 找文件 —— 找不到，于是白屏。在配置里告诉 Vite 真实的基础路径：

vite.config.js
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  base: '/hacker-stories/', // ← 改成你的仓库名，前后都要有斜杠
});

第二步：用 GitHub Actions 自动构建和部署

在项目里新建 .github/workflows/deploy.yml：

.github/workflows/deploy.yml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: lts/*
          cache: npm
      - run: npm ci
      - run: npm run build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: ./dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4

第三步：在仓库设置里启用 Pages

  1. 把代码推送到 GitHub 仓库的 main 分支。
  2. 打开仓库的 Settings → Pages，把 Source 设为 GitHub Actions。
  3. 在 Actions 标签页查看运行进度。完成后，访问 https://用户名.github.io/hacker-stories/。
  4. 以后每次 git push 到 main，都会自动重新构建和部署。
ⓘ 加了客户端路由（第 36 章）之后

GitHub Pages 不支持“所有路径都回退到 index.html”的配置。如果用户直接访问 /hacker-stories/about，会得到 404。 常见的解决办法是在构建后把 index.html 复制一份为 404.html，或者使用 hash 路由。 Firebase、Netlify、Vercel 等平台可以直接配置重写规则。第 36 章有具体做法（basename 和 404.html）。

小结

  • npm run build 把源代码打包、压缩成 dist/ 里的静态文件；npm run preview 在本地验证。
  • 纯客户端 React 应用可以部署到任何静态托管平台。
  • Firebase：firebase init 时 public 目录选 dist、配置为单页应用，然后 firebase deploy。
  • GitHub Pages：在 vite.config.js 设置 base: '/仓库名/'，用 GitHub Actions 构建并部署。

动手练习

  1. 构建项目，打开 dist/ 看看生成了哪些文件，与 src/ 对比。
  2. 把 Hacker Stories 部署到 GitHub Pages（或 Firebase），把链接发给朋友看看。
  3. 在 workflow 里 npm run build 之前加一步 npm test -- --run，让测试不通过时不部署。
  4. （选读）为 Firebase 或 GitHub Pages 绑定一个自己的域名。

面试题

开发构建和生产构建有什么区别？

开发构建注重反馈速度和调试信息，不压缩、支持热更新和 StrictMode 检查；生产构建会打包、压缩、tree-shaking、去除开发代码，并为文件名加内容哈希以便缓存。

为什么构建出的文件名带有哈希？

便于长期缓存：内容不变文件名不变，浏览器可以一直用缓存；内容一变文件名就变，浏览器会下载新版本。

部署到子路径（如 GitHub Pages）时需要注意什么？

配置构建工具的基础路径（Vite 的 base），否则资源引用会指向域名根路径而 404；客户端路由还需处理刷新时的 404 回退。

什么是单页应用的“重写”（rewrite）配置？

让服务器对所有路径都返回 index.html，由前端路由根据 URL 渲染页面，避免直接访问深层路径时出现 404。
