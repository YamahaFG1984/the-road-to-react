内联处理函数：删除条目

这一章给列表加上第二个交互：每条文章旁边放一个 “Dismiss” 按钮，点击就把它从列表里移除。 实现它会用到之前学过的几乎所有知识 —— state、props、处理函数、回调 —— 还会引出一个新写法： 内联处理函数。

本章目标

  • 把文章列表变成 state，用 filter() 以不可变的方式删除一项
  • 把回调函数穿过两层组件传给 Item
  • 掌握给处理函数“夹带参数”的两种内联写法
  • 知道内联处理函数什么时候该用、什么时候该拆出去
💡 先自己试试

任务：每个列表项旁边渲染一个按钮，点击后从列表中删除该项。提示：

  • 列表需要变成 state（useState），才能被修改；
  • 每个 Item 渲染一个按钮，点击时通过回调通知 App；
  • App 根据被点击项的 id 过滤出新数组，设为新状态。

第一步：让列表成为状态

目前 stories 是 App 里的普通常量，只能被“过滤显示”，不能真正被修改。 把示例数据挪到组件外面叫 initialStories，再用它初始化一个状态：

src/App.jsx
const initialStories = [
  {
    title: 'React',
    url: 'https://react.dev/',
    author: 'Jordan Walke',
    num_comments: 3,
    points: 4,
    objectID: 0,
  },
  {
    title: 'Redux',
    url: 'https://redux.js.org/',
    author: 'Dan Abramov, Andrew Clark',
    num_comments: 2,
    points: 5,
    objectID: 1,
  },
];

const App = () => {
  const [searchTerm, setSearchTerm] = useStorageState('search', 'React');

  const [stories, setStories] = useState(initialStories);

  ...
};

页面表现和之前完全一样，只是列表的“来源”变成了一个可以修改的状态。

第二步：在 App 里写删除逻辑

src/App.jsx
const App = () => {
  ...

  const [stories, setStories] = useState(initialStories);

  const handleRemoveStory = (item) => {
    const newStories = stories.filter(
      (story) => item.objectID !== story.objectID
    );

    setStories(newStories);
  };

  ...

  return (
    <div>
      ...
      <hr />

      <List list={searchedStories} onRemoveItem={handleRemoveStory} />
    </div>
  );
};

handleRemoveStory 接收要删除的那一项，用 filter() 留下所有 id 不等于它的文章， 得到一个新数组，再设为新状态。注意我们没有用 splice 去修改原数组 —— 第 10 章说过，数组和对象状态要“替换”而不是“修改”。

第三步：把回调传到 Item

List 自己用不到 onRemoveItem，它只是个“二传手”，原样转交给每个 Item：

src/App.jsx
const List = ({ list, onRemoveItem }) => (
  <ul>
    {list.map((item) => (
      <Item
        key={item.objectID}
        item={item}
        onRemoveItem={onRemoveItem}
      />
    ))}
  </ul>
);

Item 里加一个按钮。回调需要知道“删的是哪一项”，所以再写一个处理函数，把 item 交给回调：

src/App.jsx
const Item = ({ item, onRemoveItem }) => {
  const handleRemoveItem = () => {
    onRemoveItem(item);
  };

  return (
    <li>
      <span>
        <a href={item.url}>{item.title}</a>
      </span>
      <span>{item.author}</span>
      <span>{item.num_comments}</span>
      <span>{item.points}</span>
      <span>
        <button type="button" onClick={handleRemoveItem}>
          Dismiss
        </button>
      </span>
    </li>
  );
};

点一下 Dismiss，那一项就消失了。这个功能综合运用了 state（可变的列表）、props（向下传列表和回调）、 处理函数（按钮点击）和回调处理函数（通知 App）。

内联处理函数

Item 里多写的 handleRemoveItem 只有一个目的：把 item 作为参数交给 onRemoveItem。 能不能在 JSX 里直接完成？注意不能写 onClick={onRemoveItem(item)} —— 第 8 章讲过，那样会在渲染时就立即调用。 有两种写法：

写法一：bind

src/App.jsx
<button type="button" onClick={onRemoveItem.bind(null, item)}>
  Dismiss
</button>

fn.bind(null, item) 不会调用函数，而是返回一个新函数，这个新函数被调用时会自动带上 item 参数。

写法二：内联箭头函数（更常用）

src/App.jsx
const Item = ({ item, onRemoveItem }) => (
  <li>
    <span>
      <a href={item.url}>{item.title}</a>
    </span>
    <span>{item.author}</span>
    <span>{item.num_comments}</span>
    <span>{item.points}</span>
    <span>
      <button type="button" onClick={() => onRemoveItem(item)}>
        Dismiss
      </button>
    </span>
  </li>
);

() => onRemoveItem(item) 是一个新的函数，它被交给 onClick；点击时它才执行，再去调用 onRemoveItem(item)。 Item 又变回了简洁体。

什么时候不要内联

内联函数写起来短，但如果逻辑变多，JSX 很快就会变得难读：

JSX
<button
  type="button"
  onClick={() => {
    // 做点别的事情
    // 注意：避免在 JSX 里写复杂逻辑
    onRemoveItem(item);
  }}
>
  Dismiss
</button>
★ 经验法则

内联处理函数只要一行、不掩盖重要逻辑，就可以放心用。一旦需要块体（多于一行代码）， 就把它提取成一个有名字的处理函数。三种写法（单独处理函数、bind、内联箭头函数）都是合法的，选最易读的那种。

ⓘ “内联函数会影响性能吗？”

每次渲染都会创建一个新的箭头函数，这在老文章里常被当作性能问题。实际上创建函数非常便宜， 只有在配合 memo 做渲染优化时才需要关心（第 28 章）；而如果启用了 React Compiler，它会自动帮你处理。 初学阶段完全不用担心。

小结

  • 要修改的数据必须是 state；删除一项用 filter() 返回新数组，再调用 setter。
  • 回调可以经过多层组件传递，中间组件只负责转交（这就是 prop drilling 的雏形）。
  • 给处理函数传参数：内联箭头函数 () => fn(arg)（最常用）或 fn.bind(null, arg)。
  • 内联函数只适合一行的简单逻辑；逻辑复杂就提取成单独的处理函数。

面试题

什么是内联处理函数？有什么优点？

直接写在 JSX 事件属性里的函数，如 onClick={() => remove(item)}。优点是能方便地传入额外参数，代码更紧凑。

为什么不能写 onClick={remove(item)}？

这会在渲染时立即调用 remove，把返回值传给 onClick；应传入一个函数，让 React 在点击时调用。

如何在 React 中不可变地删除数组中的一项？

用 filter() 生成不包含该项的新数组，再用 setter 更新状态；不要用 splice 修改原数组。

内联函数的替代方案是什么？

在组件内定义单独的具名处理函数，再把函数引用传给事件属性。
