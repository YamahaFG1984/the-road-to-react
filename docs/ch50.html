组合实战：搭一套技术栈

前面几章分别介绍了各类库。真正的项目里它们要一起工作：谁包着谁？数据从哪流到哪？文件怎么组织？ 这一章把 Hacker Stories 升级成一个“真实项目”的形态，用一套主流组合把路由、服务端状态、客户端状态、表单、UI 和测试串起来， 最后给出几种常见场景的技术栈模板。

本章目标

  • 理解多个库组合时的分工原则：每类状态只归一个库管
  • 按功能组织目录，用自己的模块包装第三方库
  • 正确组织入口的 Provider 层级
  • 看清一次交互中数据如何在各个库之间流动
  • 为不同类型的项目选择一套技术栈

★ 用自己的模块包一层

组件不直接调用 axios.get、不直接写 useQuery({ queryKey: … })，而是调用 features/stories/api.ts 里导出的东西。 这样 queryKey 只定义一次、URL 只写在一处，将来把 axios 换成 fetch、把 TanStack Query 换成 SWR，改动都被限制在一个文件里。

stories 功能：路由 + 查询

把 queryKey 和请求函数集中定义成 queryOptions，路由 loader 和组件共用同一份：

src/features/stories/api.ts
import { queryOptions } from '@tanstack/react-query';
import { http } from '../../lib/http';
import type { Story } from './story-schema';

type SearchResult = { hits: Story[]; page: number; nbPages: number };

export const storiesQuery = (query: string) =>
  queryOptions({
    queryKey: ['stories', query],
    queryFn: ({ signal }) =>
      http<SearchResult>('/search', { params: { query }, signal }),
  });

export const storyQuery = (id: string) =>
  queryOptions({
    queryKey: ['story', id],
    queryFn: ({ signal }) => http<Story>(`/items/${id}`, { signal }),
  });
src/routes.tsx
import { createBrowserRouter } from 'react-router';
import { queryClient } from './lib/query-client';
import { storiesQuery, storyQuery } from './features/stories/api';

export const router = createBrowserRouter(
  [
    {
      path: '/',
      element: <Layout />,
      errorElement: <RouteError />,
      children: [
        {
          index: true,
          element: <StoriesPage />,
          // 路由切换时就开始请求（已有缓存则立即返回）
          loader: ({ request }) => {
            const query = new URL(request.url).searchParams.get('query') ?? 'React';
            return queryClient.ensureQueryData(storiesQuery(query));
          },
        },
        {
          path: 'story/:storyId',
          element: <StoryPage />,
          loader: ({ params }) =>
            queryClient.ensureQueryData(storyQuery(params.storyId!)),
        },
      ],
    },
  ],
  { basename: import.meta.env.BASE_URL }
);
src/features/stories/stories-page.tsx
import { useSearchParams } from 'react-router';
import { useQuery } from '@tanstack/react-query';
import { storiesQuery } from './api';

export const StoriesPage = () => {
  const [searchParams, setSearchParams] = useSearchParams();
  const query = searchParams.get('query') ?? 'React';

  const { data, isFetching } = useQuery(storiesQuery(query));

  return (
    <>
      <SearchForm
        defaultValue={query}
        onSearch={(term) => setSearchParams({ query: term })}
      />
      {isFetching && <p role="status">Updating…</p>}
      <StoryList stories={data?.hits ?? []} />
    </>
  );
};

favorites 功能：Zustand

src/features/favorites/favorite-button.tsx
import { Star } from 'lucide-react';
import { Button } from '@/components/ui/button';
import { useFavoritesStore } from './favorites-store';
import type { Story } from '../stories/story-schema';

export const FavoriteButton = ({ story }: { story: Story }) => {
  const isFavorite = useFavoritesStore((s) =>
    s.favorites.some((f) => f.objectID === story.objectID)
  );
  const toggleFavorite = useFavoritesStore((s) => s.toggleFavorite);

  return (
    <Button
      variant="ghost"
      size="icon"
      aria-pressed={isFavorite}
      aria-label={isFavorite ? 'Remove from favorites' : 'Add to favorites'}
      onClick={() => toggleFavorite(story)}
    >
      <Star className={isFavorite ? 'fill-current' : ''} aria-hidden="true" />
    </Button>
  );
};

提交表单：RHF + Zod + useMutation

src/features/stories/submit-story-form.tsx
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { useMutation, useQueryClient } from '@tanstack/react-query';
import { toast } from 'sonner';
import { Button } from '@/components/ui/button';
import { Input } from '@/components/ui/input';
import { storyInputSchema, type StoryInput } from './story-schema';

export const SubmitStoryForm = () => {
  const queryClient = useQueryClient();

  const form = useForm<StoryInput>({
    resolver: zodResolver(storyInputSchema),
  });

  const mutation = useMutation({
    mutationFn: (input: StoryInput) =>
      http('/stories', { method: 'POST', body: JSON.stringify(input) }),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['stories'] });
      toast.success('Story submitted');
      form.reset();
    },
    onError: () => toast.error('Could not submit story'),
  });

  return (
    <form onSubmit={form.handleSubmit((values) => mutation.mutate(values))}>
      <Input placeholder="Title" {...form.register('title')} />
      <p role="alert">{form.formState.errors.title?.message}</p>

      <Input placeholder="https://…" {...form.register('url')} />
      <p role="alert">{form.formState.errors.url?.message}</p>

      <Button type="submit" disabled={mutation.isPending}>
        {mutation.isPending ? 'Submitting…' : 'Submit'}
      </Button>
    </form>
  );
};

测试：统一的 Provider 与 MSW

组件依赖了 QueryClient 和路由，测试时也要提供。写一个带 Provider 的 render 工具，每个测试用独立的 QueryClient，避免缓存互相污染：

src/test/render.tsx
import { render } from '@testing-library/react';
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { createMemoryRouter, RouterProvider } from 'react-router';

export const renderRoute = (routes, { initialEntries = ['/'] } = {}) => {
  const queryClient = new QueryClient({
    defaultOptions: { queries: { retry: false } },
  });
  const router = createMemoryRouter(routes, { initialEntries });

  return render(
    <QueryClientProvider client={queryClient}>
      <RouterProvider router={router} />
    </QueryClientProvider>
  );
};

⚠ 模板不是必选清单

上面的每一项都应该是“遇到了对应的问题才加进来”。一个只有三个页面的小应用配齐八个库，维护成本会远超它带来的收益。 回到第 44 章的决策流程：先问需不需要，再问选哪个。

小结

  • 组合的核心原则：URL、服务端、全局客户端、表单、局部 UI 五类状态，每类只归一个库管，同一份数据不存两处。
  • 按功能组织目录，用自己的模块（api.ts、store、lib/）包装第三方库，方便替换。
  • Provider 按依赖关系嵌套：被依赖的在外层；Zustand 不需要 Provider。
  • queryOptions 让路由 loader 和组件共享同一份查询定义。
  • 测试时用带 Provider 的 render 工具 + MSW。
  • 根据项目类型选择模板，但每一项都要有引入的理由。

面试题

一个 React 项目里多个状态库如何分工？

按状态类别分工：服务端数据交给 TanStack Query 等缓存库，可分享状态放 URL（路由），全局客户端状态用 Context 或 Zustand/Redux，表单状态用表单库，局部 UI 状态用 useState；避免同一份数据存在多处。

为什么要用自己的模块包装第三方库？

集中配置和约定（如 queryKey、请求地址），减少组件对具体库的依赖，将来替换或升级时只需修改一处。

Provider 的嵌套顺序有什么讲究？

被依赖的 Provider 放在外层。例如路由 loader 需要访问 queryClient，QueryClientProvider 应包在 RouterProvider 外面。

测试使用 TanStack Query 的组件需要注意什么？

为每个测试创建新的 QueryClient（避免缓存共享），关闭重试以便快速失败，并用 MSW 等方式模拟网络请求。
