分页加载更多

Hacker News API 每次只返回一页（默认 20 条）结果。仔细看它返回的数据，除了 hits 还有一个 page 字段 —— 这意味着我们可以继续请求第 1 页、第 2 页……这一章实现“加载更多”：点击按钮获取下一页，拼接到当前列表的末尾。

本章目标

  • 区分普通分页和无限分页
  • 把 API 地址拆成可组合的常量，并正确解析出搜索词
  • 在 reducer 中保存页码，并根据页码决定替换还是拼接数据
  • 调整条件渲染，避免加载更多时列表闪烁

两种分页

💡 任务

不再只获取第一页，而是实现“点击按钮加载下一页”的无限分页。提示：

  • 给 API 地址加上分页参数；
  • 请求成功后把返回的 page 存进状态；
  • 每次新搜索都从第 0 页开始；点击新按钮时请求 page + 1。

拆分 API 地址

把原来一整个字符串的 API 地址拆成几个可组合的部分：

src/App.jsx
const API_BASE = 'https://hn.algolia.com/api/v1';
const API_SEARCH = '/search';
const PARAM_SEARCH = 'query=';

// 小心：中间有个 ?
const getUrl = (searchTerm) =>
  `${API_BASE}${API_SEARCH}?${PARAM_SEARCH}${searchTerm}`;

幸亏上一章把 URL 拼接提取成了 getUrl，其他地方都不用改。但 extractSearchTerm 原来是靠“去掉 API_ENDPOINT 前缀”实现的， URL 多了参数以后就不行了：

输出
https://hn.algolia.com/api/v1/search?query=react
https://hn.algolia.com/api/v1/search?query=react&page=0

改成截取 ? 和 & 之间的部分，再去掉 query=：

src/App.jsx
const extractSearchTerm = (url) =>
  url
    .substring(url.lastIndexOf('?') + 1, url.lastIndexOf('&'))
    .replace(PARAM_SEARCH, '');
ⓘ 更稳妥的做法：URL / URLSearchParams

手工截取字符串很脆弱（参数顺序变了、搜索词里有 & 就会出错）。浏览器内置的 URL API 能正确地构造和解析地址，也会自动编码特殊字符：

JavaScript
const getUrl = (searchTerm, page) => {
  const url = new URL(`${API_BASE}${API_SEARCH}`);
  url.searchParams.set('query', searchTerm);
  url.searchParams.set('page', page);
  return url.toString();
};

const extractSearchTerm = (url) =>
  new URL(url).searchParams.get('query');

正文沿用原书的字符串写法以便对照，实际项目推荐用 URL。

把页码存进状态

请求成功时，除了文章列表，也把 API 返回的页码交给 reducer：

src/App.jsx
const handleFetchStories = useCallback(async () => {
  dispatchStories({ type: 'STORIES_FETCH_INIT' });

  try {
    const lastUrl = urls[urls.length - 1];
    const result = await axios.get(lastUrl);

    dispatchStories({
      type: 'STORIES_FETCH_SUCCESS',
      payload: {
        list: result.data.hits,
        page: result.data.page,
      },
    });
  } catch {
    dispatchStories({ type: 'STORIES_FETCH_FAILURE' });
  }
}, [urls]);

请求下一页

给 URL 加上页码参数：

src/App.jsx
const API_BASE = 'https://hn.algolia.com/api/v1';
const API_SEARCH = '/search';
const PARAM_SEARCH = 'query=';
const PARAM_PAGE = 'page=';

// 小心：中间有 ? 和 &
const getUrl = (searchTerm, page) =>
  `${API_BASE}${API_SEARCH}?${PARAM_SEARCH}${searchTerm}&${PARAM_PAGE}${page}`;

ⓘ 为什么从 URL 里取搜索词，而不是用 searchTerm 状态？

用户可能在搜索框里又输入了别的文字，但还没提交。“加载更多”应该继续的是上一次真正请求的搜索，而它记录在最后一个 URL 里。

拼接而不是替换

点 More 确实能拿到下一页，但列表被替换成了新的 20 条，而不是在后面追加。 在 reducer 里修正：第 0 页（新搜索）替换，其他页拼接：

src/App.jsx
case 'STORIES_FETCH_SUCCESS':
  return {
    ...state,
    isLoading: false,
    isError: false,
    data:
      action.payload.page === 0
        ? action.payload.list
        : state.data.concat(action.payload.list),
    page: action.payload.page,
  };

消除闪烁

列表会增长了，但每次点 More，整个列表都会消失一下：加载期间 List 被 “Loading ...” 整个替换掉了。 分页时我们希望列表一直显示，只把 More 按钮换成加载提示：

加载时替换整个列表
JSX
{stories.isLoading ? (
  <p>Loading ...</p>
) : (
  <List list={stories.data} ... />
)}

<button onClick={handleMore}>More</button>
列表常驻，只替换按钮
JSX
<List list={stories.data} ... />

{stories.isLoading ? (
  <p>Loading ...</p>
) : (
  <button type="button" onClick={handleMore}>
    More
  </button>
)}

从“单个列表”演进到“分页列表”时，条件渲染的位置经常要这样调整。至此，我们可以一直往下浏览热门文章了。

💡 多看看 API 文档

每个第三方 API 返回的数据结构都不一样，功能也各有不同。Hacker News API 还支持 hitsPerPage（每页条数）、按时间排序的 search_by_date 等参数 —— 花几分钟读文档，常常能发现现成的功能。

小结

  • 无限分页：保存当前页码，每次请求 page + 1，把结果拼接到已有列表后面。
  • 把 API 地址拆成可组合的常量和一个 getUrl 函数；解析 URL 更推荐用 URL / URLSearchParams。
  • reducer 根据页码判断：第 0 页替换，之后的页拼接。
  • 分页时让列表常驻，只把“加载更多”按钮替换成加载提示，避免闪烁。

面试题

普通分页和无限分页有什么区别？

普通分页每次只显示一页并替换内容；无限分页把新一页追加到已有列表后面，通过按钮或滚动到底部触发。

为什么在 reducer 里判断 page === 0？

第 0 页意味着一次新搜索，应替换数据；其余页是加载更多，应拼接到现有数据之后。

如何实现无限滚动？

在列表底部放一个哨兵元素，用 IntersectionObserver 监听它进入视口时触发加载下一页，并在 effect 清理函数中断开观察。

为什么加载更多时列表会闪烁？如何避免？

因为加载状态下整个列表被替换成加载提示。应让列表常驻，只把“加载更多”按钮替换为加载提示。
