状态管理库选型

“React 用什么做状态管理？” 大概是被问得最多、争论最多的问题。Redux、MobX、Zustand、Jotai、Recoil、Valtio…… 这一章先回答一个更根本的问题：你说的“状态”是哪一种？分清类别后，你会发现大多数状态根本不需要状态管理库。 然后我们用同一个“收藏夹”功能，分别用 Zustand、Redux Toolkit 和 Jotai 实现一遍，直观地比较它们。

本章目标

  • 把应用状态分成五类，并为每类找到合适的“家”
  • 理解状态管理库解决的核心问题：共享 + 精确订阅
  • 用 Zustand、Redux Toolkit、Jotai 实现同一个功能并比较
  • 根据项目情况做出选择

先分清状态的种类

★ 最重要的一句话

很多项目之所以觉得“状态管理很复杂、必须上 Redux”，是因为把服务端数据也塞进了全局 store，自己处理加载、缓存、同步。 把服务端数据交给 TanStack Query、把可分享的状态放进 URL 之后，剩下真正的全局客户端状态通常很少 —— Context 可能就够了。

状态管理库解决什么问题

第 37 章说过，Context 只是“传递”机制，而且没有选择性订阅：值一变，所有消费者都重新渲染。 状态管理库的核心价值是：把状态存在 React 组件外面的一个 store 里，组件通过选择器（selector）只订阅自己需要的那一小块。

Zustand：最轻量的 store

Zustand（德语“状态”）是近几年增长最快的状态库：API 极少、不需要 Provider、几乎没有样板代码。

命令行
npm install zustand
src/favorites-store.js
import { create } from 'zustand';
import { persist } from 'zustand/middleware';

const useFavoritesStore = create(
  persist(
    (set) => ({
      favorites: [],

      toggleFavorite: (story) =>
        set((state) => ({
          favorites: state.favorites.some((s) => s.objectID === story.objectID)
            ? state.favorites.filter((s) => s.objectID !== story.objectID)
            : [...state.favorites, story],
        })),

      clearFavorites: () => set({ favorites: [] }),
    }),
    { name: 'favorites' } // 自动持久化到 localStorage 的这个键
  )
);

export { useFavoritesStore };
JSX
// 不需要 Provider，任何组件直接使用；传入选择器只订阅需要的部分
const Header = () => {
  const count = useFavoritesStore((state) => state.favorites.length);
  return <span>★ {count} saved</span>;
};

const Item = ({ item }) => {
  const isFavorite = useFavoritesStore((state) =>
    state.favorites.some((s) => s.objectID === item.objectID)
  );
  const toggleFavorite = useFavoritesStore((state) => state.toggleFavorite);

  return (
    <button type="button" aria-pressed={isFavorite} onClick={() => toggleFavorite(item)}>
      {isFavorite ? '★' : '☆'}
    </button>
  );
};
⚠ 选择器不要每次返回新对象

useFavoritesStore((s) => ({ a: s.a, b: s.b })) 每次都返回一个新对象，Zustand 会认为值变了，导致无限重新渲染（v5 中会直接报错）。 要么分开调用两次，要么用 useShallow 包一层：useFavoritesStore(useShallow((s) => ({ a: s.a, b: s.b })))。

Redux Toolkit：规范与工具最完善

Redux 是最老牌的状态库。“经典” Redux 以样板代码多著称，官方后来推出的 Redux Toolkit（RTK）大幅简化了写法， 是今天使用 Redux 的唯一推荐方式。它的核心就是第 20 章学过的 reducer + action + dispatch。

命令行
npm install @reduxjs/toolkit react-redux
src/store.js
import { configureStore, createSlice } from '@reduxjs/toolkit';

const favoritesSlice = createSlice({
  name: 'favorites',
  initialState: [],
  reducers: {
    // 看起来像直接修改，其实 RTK 内置的 Immer 会生成不可变的新状态
    toggleFavorite(state, action) {
      const index = state.findIndex(
        (s) => s.objectID === action.payload.objectID
      );
      if (index >= 0) state.splice(index, 1);
      else state.push(action.payload);
    },
    clearFavorites: () => [],
  },
});

export const { toggleFavorite, clearFavorites } = favoritesSlice.actions;

export const store = configureStore({
  reducer: {
    favorites: favoritesSlice.reducer,
  },
});
src/main.jsx
import { Provider } from 'react-redux';
import { store } from './store';

<Provider store={store}>
  <App />
</Provider>
JSX
import { useDispatch, useSelector } from 'react-redux';
import { toggleFavorite } from './store';

const Item = ({ item }) => {
  const isFavorite = useSelector((state) =>
    state.favorites.some((s) => s.objectID === item.objectID)
  );
  const dispatch = useDispatch();

  return (
    <button type="button" onClick={() => dispatch(toggleFavorite(item))}>
      {isFavorite ? '★' : '☆'}
    </button>
  );
};
经典 Redux 不再推荐
JavaScript
// action type 常量
const TOGGLE_FAVORITE = 'favorites/toggle';
// action creator
const toggleFavorite = (story) => ({
  type: TOGGLE_FAVORITE, payload: story,
});
// reducer：手写不可变更新
const favoritesReducer = (state = [], action) => {
  switch (action.type) {
    case TOGGLE_FAVORITE: /* … */
    default: return state;
  }
};
// createStore + combineReducers + applyMiddleware(thunk)
// 组件里用 connect(mapStateToProps, mapDispatchToProps)
Redux Toolkit 现在
JavaScript
const favoritesSlice = createSlice({
  name: 'favorites',
  initialState: [],
  reducers: {
    toggleFavorite(state, action) { /* 直接“修改” */ },
  },
});
// action type、action creator 自动生成
// configureStore 自带 DevTools 和 thunk
// 组件里用 useSelector / useDispatch

Redux 的强项在于规范：所有状态变化都经过 action，配合 Redux DevTools 可以看到每一次变化的前后差异，甚至“时间旅行”回放。 RTK 还自带 RTK Query（第 46 章）处理服务端数据。大团队、复杂业务逻辑、需要严格可追踪时，它依然是很好的选择。

Jotai：原子化的状态

Jotai（日语“状态”）换了一个思路：状态不是一个大对象，而是很多小小的原子（atom），用法和 useState 几乎一样， 原子之间还可以派生：

命令行
npm install jotai
src/favorites-atoms.js
import { atom } from 'jotai';
import { atomWithStorage } from 'jotai/utils';

// 一个原子：会持久化到 localStorage
const favoritesAtom = atomWithStorage('favorites', []);

// 派生原子：只读，自动跟随 favoritesAtom
const favoritesCountAtom = atom((get) => get(favoritesAtom).length);

export { favoritesAtom, favoritesCountAtom };
JSX
import { useAtom, useAtomValue } from 'jotai';

const Header = () => {
  const count = useAtomValue(favoritesCountAtom);
  return <span>★ {count} saved</span>;
};

const Item = ({ item }) => {
  const [favorites, setFavorites] = useAtom(favoritesAtom);
  // …和 useState 的用法一样
};

Jotai 适合状态之间有大量派生关系、或者状态天然是“很多独立小块”的场景（比如画板上的每个图形、表格的每个单元格）。

怎么选

ⓘ 其他你可能听说过的
  • MobX：基于可观察对象的响应式方案，写法像直接修改对象，老项目中较常见。
  • Valtio：和 Zustand、Jotai 同一作者团队，基于 Proxy 的“可变写法”。
  • XState：状态机 / 状态图，适合流程复杂、状态转换规则严格的场景（第 20 章的“不可能状态”问题的终极解法）。
  • Recoil：Meta 推出的原子化状态库，已停止维护，新项目请用 Jotai。

小结

  • 状态分五类：局部 UI、服务端、URL、表单、全局客户端。状态管理库只负责最后一类。
  • 先把服务端数据交给 TanStack Query、把可分享状态放进 URL，剩下的全局状态往往很少。
  • 状态库的核心价值：store 放在组件外 + 选择器精确订阅。
  • Zustand 轻量无样板；Redux Toolkit 规范严格、工具最强；Jotai 原子化、适合细粒度派生。
  • 不确定时：少量低频用 Context，否则用 Zustand。

面试题

什么时候需要引入状态管理库？

当有大量组件需要共享、且变化较频繁的客户端状态，Context 导致过多重新渲染或代码难以组织时。服务端数据应交给数据请求库，而不是全局 store。

Zustand 和 Redux Toolkit 的主要区别？

Zustand 极简、无需 Provider、直接定义修改函数；RTK 基于 action/reducer 模式，结构规范、DevTools 强大，并提供 RTK Query，适合大型团队。

为什么状态管理库比 Context 性能更好？

它们支持选择器订阅，组件只在所选的状态片段变化时重新渲染；Context 在 value 变化时通知所有消费者。

Redux Toolkit 里为什么可以“直接修改” state？

createSlice 内部使用 Immer，把对草稿对象的修改转换成不可变的新状态。
