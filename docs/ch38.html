错误边界与 Suspense

前面的章节里，“加载中”和“出错了”都是用状态变量手动处理的。React 还提供了两种声明式的“边界”： Suspense 负责“内容还没准备好时显示什么”，错误边界负责“渲染出错时显示什么”。 它们让你像写 try/catch 一样，给界面的某一块区域兜底。

本章目标

  • 理解为什么一个组件出错会导致整个应用白屏
  • 用错误边界（类组件写法和 react-error-boundary）隔离错误，并提供重试
  • 知道错误边界捕获不到哪些错误，以及怎么处理它们
  • 用 lazy + Suspense 做代码分割，用 use() + Suspense 读取数据
  • 处理 React Router 中 loader 抛出的错误

一个错误，整页白屏

假设 API 返回的某篇文章没有 title，而 Item 里写了：

JSX
<span>{item.title.toUpperCase()}</span>
// TypeError: Cannot read properties of null (reading 'toUpperCase')

结果不是“这一条显示不出来”，而是整个页面变成空白。从 React 16 起，渲染过程中抛出的错误如果没有被捕获， React 会卸载整棵组件树 —— 因为显示一个可能是错的界面，比什么都不显示更危险（想象一个显示错金额的支付页）。

错误边界

错误边界是一个能捕获子树渲染错误的组件。有点特别的是：到今天为止，React 仍然只能用类组件来写错误边界 （没有对应的 Hook）。这是现代 React 代码里几乎唯一还需要类组件的地方：

src/ErrorBoundary.jsx
import { Component } from 'react';

class ErrorBoundary extends Component {
  state = { error: null };

  // 渲染出错时调用：返回新的 state，让下一次渲染显示后备界面
  static getDerivedStateFromError(error) {
    return { error };
  }

  // 可以在这里把错误上报到监控服务
  componentDidCatch(error, info) {
    console.error(error, info.componentStack);
  }

  render() {
    if (this.state.error) {
      return this.props.fallback;
    }

    return this.props.children;
  }
}

export { ErrorBoundary };
JSX
<ErrorBoundary fallback={<p>Something went wrong with the list.</p>}>
  <List list={stories.data} onRemoveItem={handleRemoveStory} />
</ErrorBoundary>

用 react-error-boundary 库

自己写的版本不能“重试”，也处理不了异步错误。实际项目里通常直接用社区标准库：

命令行
npm install react-error-boundary
src/StoriesPage.jsx
import { ErrorBoundary } from 'react-error-boundary';

const ListFallback = ({ error, resetErrorBoundary }) => (
  <div role="alert">
    <p>Could not display the stories: {error.message}</p>
    <button type="button" onClick={resetErrorBoundary}>
      Try again
    </button>
  </div>
);

const StoriesPage = () => {
  ...
  return (
    <>
      <SearchForm ... />

      <ErrorBoundary
        FallbackComponent={ListFallback}
        resetKeys={[stories.data]}
      >
        <List list={stories.data} onRemoveItem={handleRemoveStory} />
      </ErrorBoundary>
    </>
  );
};
  • FallbackComponent 会收到 error 和 resetErrorBoundary，点击“重试”会清除错误、重新渲染子树。
  • resetKeys：数组里的值变化时自动重置。新搜索拿到了新数据，就不必再显示旧的错误。

错误边界接不住什么

错误发生在能被错误边界捕获吗怎么处理
子组件渲染过程中✅ 能—
子组件的 useEffect 里（同步抛出）✅ 能—
事件处理函数里❌ 不能自己 try/catch，存进状态；或调用 showBoundary(error)
异步代码里（Promise、setTimeout）❌ 不能.catch / try/catch；或 showBoundary
错误边界组件自身❌ 不能由更外层的边界捕获
form action / transition 中✅ 能（React 19）action 抛出的错误会交给最近的错误边界

react-error-boundary 提供的 Hook 可以把事件和异步代码里的错误“转交”给边界：

JSX
import { useErrorBoundary } from 'react-error-boundary';

const RefreshButton = () => {
  const { showBoundary } = useErrorBoundary();

  const handleClick = async () => {
    try {
      await refreshStories();
    } catch (error) {
      showBoundary(error); // 交给最近的 ErrorBoundary 显示
    }
  };

  return <button type="button" onClick={handleClick}>Refresh</button>;
};
ⓘ React 19 的错误处理改进
  • 开发环境下，一个错误不再被重复抛出、打印两三次；控制台信息更精简，并带有组件栈。
  • createRoot 新增了全局回调：onCaughtError（被边界捕获的错误）、onUncaughtError（未捕获的错误）、onRecoverableError，方便统一接入错误监控。
src/main.jsx
createRoot(document.getElementById('root'), {
  onUncaughtError: (error, errorInfo) => {
    reportToMonitoring(error, errorInfo.componentStack);
  },
  onCaughtError: (error, errorInfo) => {
    reportToMonitoring(error, errorInfo.componentStack);
  },
}).render(<App />);

路由里的错误：errorElement

第 36 章的 storyLoader 在文章不存在时 throw new Response(…, { status: 404 })。 React Router 内置了路由级的错误边界：给路由配置 errorElement，loader 或组件抛出的错误都会显示它：

src/main.jsx
const router = createBrowserRouter([
  {
    path: '/',
    element: <Layout />,
    errorElement: <RouteError />, // 兜底：整个应用的错误页
    children: [
      { index: true, element: <StoriesPage /> },
      {
        path: 'story/:storyId',
        element: <StoryPage />,
        loader: storyLoader,
        errorElement: <RouteError />, // 只替换详情区域，保留 Layout
      },
    ],
  },
]);
src/RouteError.jsx
import { isRouteErrorResponse, useRouteError, Link } from 'react-router';

const RouteError = () => {
  const error = useRouteError();

  if (isRouteErrorResponse(error) && error.status === 404) {
    return (
      <div>
        <h2>Story not found</h2>
        <Link to="/">Back to all stories</Link>
      </div>
    );
  }

  return <h2>Something went wrong: {error.message}</h2>;
};

export { RouteError };

Suspense：还没准备好时显示什么

<Suspense fallback={…}> 包住的子树里，只要有组件“暂停”（suspend，即表示“我还没准备好”）， 整个边界就先显示 fallback，准备好后再换成真正的内容。什么会让组件暂停？主要有两种： 懒加载的代码和还没兑现的数据。

1. 代码分割：lazy

详情页不是每个用户都会打开，没必要把它的代码塞进首屏的 JS 包里。用 lazy + 动态 import()， Vite 会把它打包成一个单独的文件，第一次用到时才下载：

src/main.jsx
import { lazy, Suspense } from 'react';

const StoryPage = lazy(() => import('./StoryPage'));
// 注意：lazy 需要模块有 default export

...
{
  path: 'story/:storyId',
  element: (
    <Suspense fallback={<p>Loading page ...</p>}>
      <StoryPage />
    </Suspense>
  ),
}

2. 读取数据：use(promise)

第 25 章介绍过 use 可以读取 Promise。和 Suspense、错误边界组合起来，加载和出错都变成了声明式的：

JSX
import { use, Suspense } from 'react';
import { ErrorBoundary } from 'react-error-boundary';

// Promise 必须在组件外创建或被缓存，不能在渲染时新建
const storiesPromise = fetch(`${API_ENDPOINT}react`).then((r) => r.json());

const Stories = () => {
  const result = use(storiesPromise); // 没好就暂停；失败就抛给错误边界
  return <List list={result.hits} />;
};

const App = () => (
  <ErrorBoundary fallback={<p>Something went wrong ...</p>}>
    <Suspense fallback={<p>Loading ...</p>}>
      <Stories />
    </Suspense>
  </ErrorBoundary>
);
⚠ 实践中通常不自己管理 Promise

上面的 storiesPromise 在模块加载时就创建了，搜索词变了怎么办？需要缓存、按参数区分、失效重取…… 这些正是 TanStack Query（useSuspenseQuery，第 40 章）和框架（服务端组件，第 51 章）替你做的事。 use(promise) 更适合作为这些工具的底层机制来理解。

手动管理 第 19–23 章
JSX
const [data, setData] = useState(null);

声明式边界 Suspense + ErrorBoundary
JSX
<ErrorBoundary FallbackComponent={ErrorMessage}>

    <Stories />  {/* 内部 use() 或 useSuspenseQuery() */}
  </Suspense>
</ErrorBoundary>

两种方式都正确。手动管理最直观、不依赖任何工具；声明式边界让组件更干净，加载与错误界面可以在上层统一编排。 在 React 18 之前，Suspense 只能用于 lazy 代码分割；现在它已经是数据加载的一等公民。

小结

  • 未捕获的渲染错误会卸载整棵组件树；错误边界把错误限制在局部并显示后备界面。
  • 错误边界目前只能用类组件实现，实际项目中通常用 react-error-boundary（支持重试、resetKeys、showBoundary）。
  • 事件处理函数和异步代码中的错误不会被自动捕获，需要 try/catch 或 showBoundary。
  • React Router 用 errorElement + useRouteError 处理路由级错误。
  • Suspense 在子树“暂停”时显示 fallback：用于 lazy 代码分割和 use(promise) / Suspense 查询等数据加载。

面试题

什么是错误边界？为什么需要它？

能捕获子组件树渲染错误并显示后备 UI 的组件。没有它时，未捕获的渲染错误会导致整个应用卸载白屏。

错误边界能用函数组件写吗？

目前不能，需要类组件实现 getDerivedStateFromError / componentDidCatch；可以使用 react-error-boundary 等库在函数组件中方便地使用。

哪些错误不能被错误边界捕获？

事件处理函数中的错误、异步代码（setTimeout、Promise 回调）中的错误、服务端渲染中的错误，以及边界自身的错误。

Suspense 的作用是什么？

当子树中的组件因为代码或数据未就绪而暂停时，显示指定的 fallback，就绪后再显示实际内容。常用于 lazy 代码分割和数据加载。

React.lazy 有什么好处？

实现按需加载：组件代码被拆成独立文件，只有渲染到时才下载，减少首屏 JS 体积。
