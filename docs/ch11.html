第 11 章 · 交互与数据流

回调与状态提升

现在 Search 自己管着 searchTerm，能显示它，但别人用不到它。 我们真正想做的是：用这个搜索词去过滤 App 里的文章列表。 问题来了 —— props 只能往下传，子组件怎么把数据“告诉”父组件？

本章目标

  • 用回调处理函数让子组件向父组件通信
  • 学会状态提升：把状态放到所有需要它的组件的共同祖先里
  • 用 filter() 根据搜索词派生出过滤后的列表
  • 理解“派生值不要存成状态”

回调处理函数

既然 props 可以传任何值，那当然也可以传函数。父组件定义一个函数，通过 props 交给子组件； 子组件在合适的时机调用它；函数真正执行的代码却在父组件里 —— 这样信息就“回”到了父组件。 这个函数叫回调处理函数（callback handler）。

src/App.jsx
const App = () => {
  const stories = [ ... ];

  // A：在父组件里定义
  const handleSearch = (event) => {
    // D：最终在这里执行，App 拿到了输入的值
    console.log(event.target.value);
  };

  return (
    <div>
      <h1>My Hacker Stories</h1>

      {/* B：通过 props 传给子组件 */}
      <Search onSearch={handleSearch} />

      <hr />

      <List list={stories} />
    </div>
  );
};

const Search = (props) => {
  const [searchTerm, setSearchTerm] = useState('');

  const handleChange = (event) => {
    setSearchTerm(event.target.value);

    // C：子组件调用它
    props.onSearch(event);
  };

  return ( ... );
};
★ 一句话记住

数据通过 props 向下流；事件通过回调函数向上流。 回调函数本身依然是“向下”传的 props，只是它被调用时，执行的是父组件里的逻辑。 按惯例，作为 prop 的回调命名为 onXxx（onSearch），父组件里的实现命名为 handleXxx（handleSearch）。

状态提升

现在 App 能收到输入的值了，可以用它来过滤列表。但怎么存？如果在 App 里再建一个状态， Search 和 App 就各有一份 searchTerm —— 两份数据，迟早会不同步。

换个角度想：既然 App 需要 searchTerm，那为什么不一开始就把状态放在 App 里？ 这就是状态提升（lifting state up）：

把 useState 从 Search 挪到 App，回调函数里改为更新 App 的状态：

src/App.jsx
const App = () => {
  const stories = [ ... ];

  const [searchTerm, setSearchTerm] = useState('');

  const handleSearch = (event) => {
    setSearchTerm(event.target.value);
  };

  return (
    <div>
      <h1>My Hacker Stories</h1>

      <Search onSearch={handleSearch} />

      <hr />

      <List list={stories} />
    </div>
  );
};

const Search = (props) => (
  <div>
    <label htmlFor="search">Search: </label>
    <input id="search" type="text" onChange={props.onSearch} />
  </div>
);

Search 变回了一个没有状态的简单组件：它只是把 change 事件交给父组件。 状态统一由 App 管理。

用 filter() 过滤列表

状态在 App 里了，就可以在把列表交给 List 之前先过滤一遍。 先复习一下数组的 filter()：回调返回 true 的项留下，返回 false 的项被丢掉，结果是一个新数组：

JavaScript
const words = ['spray', 'limit', 'elite', 'exuberant', 'destruction', 'present'];

const filteredWords = words.filter((word) => word.length > 6);

console.log(filteredWords); // ['exuberant', 'destruction', 'present']

应用到文章列表上：

src/App.jsx
const App = () => {
  const stories = [ ... ];

  const [searchTerm, setSearchTerm] = useState('');

  const handleSearch = (event) => {
    setSearchTerm(event.target.value);
  };

  const searchedStories = stories.filter((story) =>
    story.title.includes(searchTerm)
  );

  return (
    <div>
      <h1>My Hacker Stories</h1>

      <Search onSearch={handleSearch} />

      <hr />

      <List list={searchedStories} />
    </div>
  );
};

还有个小问题：搜 “react” 找不到 “React”，因为 includes 区分大小写。两边都转成小写再比：

src/App.jsx
const searchedStories = stories.filter((story) =>
  story.title.toLowerCase().includes(searchTerm.toLowerCase())
);

现在输入 “eact”“React”“react” 都能找到对应文章。恭喜，你完成了第一个真正的交互功能 —— 它同时用到了 state（保存搜索词）和 props（向下传列表、向下传回调）。

派生值不要存成状态

注意 searchedStories 并不是状态，它只是每次渲染时由 stories 和 searchTerm 算出来的普通变量。 这是一个非常重要的习惯：

❌ 把派生值也存成状态
JSX
const [searchTerm, setSearchTerm] = useState('');
const [searchedStories, setSearchedStories] =
  useState(stories);

const handleSearch = (event) => {
  setSearchTerm(event.target.value);
  // 必须记得同步更新另一个状态……
  setSearchedStories(stories.filter(...));
};
✅ 渲染时直接算出来
JSX
const [searchTerm, setSearchTerm] = useState('');

// 每次渲染自动计算，永远不会不同步
const searchedStories = stories.filter((story) =>
  story.title.toLowerCase()
    .includes(searchTerm.toLowerCase())
);
💡 判断标准

如果一个值可以从已有的 props 或 state 计算出来，它就不应该是 state。 state 越少，出现“两份数据不一致”的 bug 就越少。担心每次都算太慢？绝大多数情况下都不慢；真慢了再看第 28 章的 useMemo。

状态应该放在哪里？

★ 状态放置的经验法则
  • 找出所有需要读取或修改这个状态的组件；
  • 把状态放在它们最近的共同祖先里；
  • 需要读的子组件，通过 props 拿到值；需要改的子组件，通过 props 拿到回调函数。

放得太低，别的组件用不到；放得太高，无关的组件也会跟着重新渲染。学会判断状态放在哪里，是 React 开发者最重要的技能之一。

小结

  • 回调处理函数：父组件把函数作为 prop 传给子组件，子组件调用它来通知父组件。
  • 状态提升：把状态放到所有需要它的组件的最近共同祖先中，避免重复的、不同步的状态。
  • filter() + toLowerCase().includes() 实现了不区分大小写的搜索。
  • 能算出来的值不要存成状态，在渲染时直接计算。

面试题

什么是回调处理函数？子组件如何与父组件通信？

父组件定义函数并通过 props 传给子组件，子组件在事件发生时调用它（可带参数），从而让父组件执行相应逻辑。

什么是状态提升？为什么需要它？

把状态移动到需要共享它的多个组件的最近共同祖先中，由祖先通过 props 分发值和修改函数。这样只有一份数据源，避免重复与不同步。

子组件能通过回调直接修改父组件的状态吗？

子组件只是调用回调来“通知”父组件，怎样更新状态由父组件决定。

是否应该把所有状态都提升到顶层组件？

不应该。只提升到需要共享的层级即可；无关状态放在顶层会导致不必要的重新渲染和更高的耦合。

什么是派生状态？应该怎么处理？

可以由现有 props/state 计算出来的值。应在渲染时直接计算，而不是另存为 state 并手动同步。
