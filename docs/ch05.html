渲染列表与 key

真实应用里的数据几乎总是“一组对象组成的数组”。这一章我们把一组文章渲染成列表 —— 这是 Hacker Stories 的雏形 —— 并弄明白 React 为什么总是追着你要一个叫 key 的属性。

本章目标

  • 用数组的 map() 把数据变成一组 JSX 元素
  • 理解 key 的作用，知道应该用什么当 key
  • 看清用数组下标当 key 会引发的真实 bug

先复习：数组的 map()

map() 遍历数组，对每一项调用你给的函数，把返回值收集成一个新数组，原数组不变：

JavaScript
const numbers = [1, 2, 3, 4];

const squares = numbers.map(function (number) {
  return number * number;
});

console.log(squares); // [1, 4, 9, 16]

在 React 里，我们让回调函数返回的不是数字，而是 JSX。上一章说过， 花括号里放一个数组，React 会依次渲染每一项 —— 两件事一结合，就是列表渲染。

渲染文章列表

先在组件外定义一些示例数据。字段名模仿了后面要接入的 Hacker News API 返回的真实数据 （所以才有 num_comments 这种下划线命名和 objectID 这种写法）：

const list = [

];

function App() { ... }

export default App;
ⓘ 关于 ...

本教程的代码片段里，... 表示“这部分和之前一样，省略不写”。

然后在 JSX 里用 map() 渲染每一项的标题：

src/App.jsx
function App() {
  return (
    <div>
      <h1>My Hacker Stories</h1>

      <label htmlFor="search">Search: </label>
      <input id="search" type="text" />

      <hr />

      <ul>
        {list.map(function (item) {
          return <li>{item.title}</li>;
        })}
      </ul>
    </div>
  );
}

页面上出现了两个标题。但打开控制台，你会看到一条警告：

控制台输出
Warning: Each child in a list should have a unique "key" prop.

key：给每一项一个身份证

修复很简单 —— 给列表里的每个元素加一个 key 属性，值用数据里稳定且唯一的标识：

src/App.jsx
<ul>
  {list.map(function (item) {
    return <li key={item.objectID}>{item.title}</li>;
  })}
</ul>

为什么需要它？每次重新渲染，React 都会拿新的元素列表和旧的对比，找出需要改动的最少 DOM 操作。 对列表来说，React 需要知道“新列表里的这一项，是旧列表里的哪一项”。 没有 key，React 只能按位置一一对应。

用下标当 key 会怎样

如果数据没有 id，很多人会顺手用 map 回调的第二个参数 index 当 key。 这等于告诉 React“按位置对比” —— 和不写 key 效果一样（只是把警告压下去了）：

JSX
<ul>
  {list.map(function (item, index) {
    return (
      <li key={index}>
        {/* 下标只能作为最后的选择 */}
        {/* 顺便一提：这就是 JSX 里写注释的方式 */}
        {item.title}
      </li>
    );
  })}
</ul>

动手体验一下区别：在每个输入框里写点备注，然后点“在开头插入一项”。

交互演示 · key 的作用

key={index}
    key={item.objectID}

      左边：输入框按位置复用，你写给 “React” 的备注会留在第一行，而第一行的文字已经变成了新插入的那一项。右边：备注跟着数据走。

      ★ key 的选择顺序
      1. 数据自带的 id（数据库主键、API 返回的 objectID）—— 首选。
      2. 其他唯一且不会变的字段，比如在列表里不会重复的标题。
      3. 下标 index —— 只有在列表永远不会重新排序、插入、删除时才可以用。

      千万不要用 Math.random() 或 crypto.randomUUID() 在渲染时生成 key：每次渲染 key 都不同，React 会把整个列表销毁重建。

      显示完整信息

      把每篇文章的链接、作者、评论数和点数都显示出来。标题用 <a> 包起来， href 用花括号动态赋值：

      src/App.jsx
      function App() {
  return (
    <div>
      ...
      <ul>
        {list.map(function (item) {
          return (
            <li key={item.objectID}>
              <span>
                <a href={item.url}>{item.title}</a>
              </span>
              <span>{item.author}</span>
              <span>{item.num_comments}</span>
              <span>{item.points}</span>
            </li>
          );
        })}
      </ul>
    </div>
  );
}

      JavaScript 在 JSX 里不仅能决定显示什么内容，也能决定属性的值。 整个列表没有用到任何“模板语法”，全是你已经会的 JavaScript。

      ⓘ key 不会传给组件

      key 是给 React 自己用的特殊属性，不会出现在 DOM 上，也不能在组件内部通过 props 读到。 它只需要在兄弟元素之间唯一，不需要全局唯一。

      小结

      • 用 array.map(item => <li>…</li>) 把数据数组渲染成列表。
      • 列表中的每个元素都需要一个稳定、唯一的 key，让 React 在更新时按身份匹配元素。
      • 下标当 key 在列表会增删、排序时会导致状态错位，只能作为最后选择。
      • JSX 的花括号既能用于内容，也能用于属性值（如 href={item.url}）。

      面试题

      在 React 中如何渲染一个列表？

      用数组的 map() 方法把每一项数据映射成 JSX 元素，并给每个元素一个唯一的 key。

      key 的作用是什么？

      帮助 React 在重新渲染时识别列表中哪些元素被添加、删除或移动，从而正确复用 DOM 节点和组件状态，并减少不必要的 DOM 操作。

      为什么不推荐用数组下标作为 key？

      当列表发生插入、删除或排序时，下标与数据的对应关系会改变，导致 React 错误复用节点，出现输入框内容、勾选状态等错位的 bug，并带来多余的更新。

      组件返回 null 会怎样？

      什么都不渲染。这是合法的，常用于“在某些条件下不显示”。
