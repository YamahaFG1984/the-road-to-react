你好，React

在写第一行 React 代码之前，先花十分钟弄明白一件事：React 到底解决了什么问题？ 理解了网页从“服务器拼好 HTML”走到“浏览器里用 JavaScript 画界面”的这段历史， 后面所有概念 —— 组件、状态、重新渲染 —— 都会显得顺理成章。

本章目标

  • 分清多页应用（服务器渲染）和单页应用（SPA）的区别
  • 理解 React 的核心思想：组件和声明式
  • 知道 2025 年之后开始一个 React 项目的正确姿势（以及为什么不再用 Create React App）
  • 装好 Node.js、npm 和编辑器

从前：服务器负责一切

早期的网站是这样工作的：你在浏览器里输入网址，浏览器向服务器发一个请求， 服务器把整页 HTML 拼好返回，浏览器把它画出来。点一个链接？再来一遍 —— 每次换页都要整页重新加载。

在这种模式里，服务器干了绝大部分的活；浏览器只负责显示。JavaScript（通常是 jQuery） 只做一些点缀：展开个下拉菜单、弹个提示框。

后来：单页应用（SPA）

随着网页越来越像“应用”（邮箱、地图、在线文档），整页刷新的体验就不够用了。 于是出现了单页应用（Single-Page Application，SPA）： 服务器第一次只返回一个几乎是空的 HTML 和一个比较大的 JavaScript 文件。 浏览器运行这段 JavaScript，由它在页面上“画”出整个界面。之后切换页面、更新内容， 都由 JavaScript 在浏览器里完成，需要数据时才去服务器取一点 JSON。

React 就是在这个浪潮里诞生的。2013 年 Facebook 开源了 React， 它和 Angular、Ember、Backbone 等“第一代 SPA 框架”竞争，最终凭借一个简单而强大的想法胜出： 组件。

多页应用（服务器渲染）单页应用（SPA）
谁生成 HTML服务器浏览器里的 JavaScript
首次加载快，直接有内容要先下载并运行 JS，稍慢
页面切换整页刷新局部更新，不刷新
服务器返回完整 HTML第一次是 JS，之后是 JSON
典型技术PHP、Rails、Express + 模板React、Vue、Angular
🔎 深入一点：钟摆又摆回来了

纯 SPA 的缺点是首屏慢、对搜索引擎不友好。所以今天的 React 生态又把一部分渲染搬回了服务器： Next.js 这类框架会先在服务器上把 React 组件渲染成 HTML（SSR），再在浏览器里“激活”。 React 19 更进一步，正式引入了只在服务器上运行的服务端组件（Server Components）。 这些是进阶话题，第 25 章会带你认识。本教程前面的内容是纯客户端 SPA —— 它是理解一切的基础。

React 的核心思想：组件

在 React 里，你不再按“页面”去思考，而是按组件（Component）去思考。 组件是一块自带结构（HTML）、样式（CSS）和行为（JavaScript）的界面积木。 小积木拼成大积木，大积木拼成整个应用：

组件带来的好处：

  • 复用：写一次 Item，给它不同的数据，就能显示一百条文章。
  • 隔离：改 Search 不会不小心弄坏 List。
  • 可读：看组件树就能看懂一个应用的结构。

声明式：描述“是什么”，而不是“怎么做”

React 另一个关键词是声明式（declarative）。对比一下：用原生 DOM / jQuery 写一个计数按钮， 和用 React 写同一个按钮。

命令式：一步步告诉浏览器怎么改 jQuery 时代
JavaScript
let count = 0;
const button = document.querySelector('#btn');

button.addEventListener('click', () => {
  count = count + 1;
  // 手动找到节点、手动改文字
  button.textContent = `点了 ${count} 次`;
});
声明式：描述在某个状态下界面长什么样 React
JSX
function Counter() {
  const [count, setCount] = useState(0);

  // 只描述结果，React 负责更新 DOM
  return (
    <button onClick={() => setCount(count + 1)}>
      点了 {count} 次
    </button>
  );
}

左边你要记住“先找节点，再改文字”；页面复杂之后，哪些地方要跟着改、改的顺序对不对， 全靠你自己记着，很容易漏。右边你只说“按钮的文字是 点了 {count} 次”， count 一变，React 自动算出需要改的地方并更新。这就是首页那句 UI = f(state)。

★ 记住这个区别

命令式：“找到按钮，把文字改成 3。”
声明式：“按钮的文字等于 count。”
React 的几乎所有 API 都是声明式的；少数需要“命令式”操作 DOM 的场景（比如让输入框获得焦点）， 第 17 章会讲怎么安全地做。

React 是库还是框架？

严格说，React 本身只是一个界面库：它只管“把组件渲染成界面”。 路由、数据请求、样式、构建工具都不在 React 的核心里，需要从生态里挑选。 这让 React 很灵活，但也意味着“怎么开始一个项目”一直是个问题。

过去 已废弃
命令行
# Create React App（CRA）曾是官方推荐的脚手架
npx create-react-app my-app
现在 2025+
命令行
# 纯客户端应用：用 Vite（本教程）
npm create vite@latest my-app -- --template react

# 需要服务端渲染 / 路由 / 全栈：用框架
npx create-next-app@latest

2025 年 2 月，React 官方正式宣布弃用 Create React App。今天的官方建议是： 要做完整的产品，优先考虑 Next.js、React Router 这类“React 框架”； 想从零学习、或者做纯客户端应用，用 Vite 这样的构建工具。本教程选择 Vite —— 它几乎零配置，让我们把注意力全部放在 React 本身。

准备工作：你需要的工具

编辑器与终端

推荐 Visual Studio Code（VS Code）：免费、自带终端、React 插件生态最好。 本教程里说的“命令行”“终端”都指同一个东西 —— VS Code 里按 Ctrl+` 就能打开。

不想在本地装环境，也可以先用在线的 CodeSandbox 或 StackBlitz 体验。但长期学习建议本地开发，迟早用得上。

Node.js 与 npm

React 代码最终在浏览器里跑，但开发工具（Vite、测试工具、包管理器）跑在 Node.js 上。 到 nodejs.org 下载 LTS（长期支持）版本， 安装后会同时得到 npm（Node Package Manager，用来安装第三方库）。检查一下：

命令行
node --version
# v22.x.x（新版 Vite 需要 Node 20.19+ 或 22.12+）
npm --version
# 10.x.x
💡 关于 yarn 和 pnpm

你会在别的教程里看到 yarn add 或 pnpm add，它们和 npm install 作用一样， 只是另一种包管理器。初学阶段用 npm 就好，知道它们存在即可。

Git（推荐）

建议每学完一章就 git commit 一次。改坏了能回退，也方便对照每一步的变化。 最后部署到 GitHub Pages 时（第 36 章）也会用到 GitHub。

小结

  • 多页应用由服务器渲染整页 HTML；单页应用把渲染搬到浏览器，由 JavaScript 画界面。
  • React 是构建界面的库，核心思想是组件（可复用的积木）和声明式（UI = f(state)）。
  • Create React App 已被官方弃用；学习和纯客户端项目用 Vite，完整产品可以考虑 Next.js 等框架。
  • 开发前需要 Node.js（LTS）、npm 和一个编辑器。

动手练习

  1. 打开任意一个你常用的网站（比如 GitHub），在纸上把首页拆成组件树：哪些部分是重复出现的同一种组件？
  2. 在终端运行 node --version 和 npm --version，确认版本满足要求。
  3. 打开浏览器开发者工具的 Network 面板，分别访问一个传统网站和一个 SPA（比如 Gmail），对比点链接时的请求有什么不同。
  4. （选读）看看纪录片 React.js: The Documentary，了解 React 诞生时被多少人质疑。

面试题

什么是单页应用（SPA）？它和传统多页应用的主要区别是什么？

SPA 首次加载一个小 HTML 和一个 JS 包，之后由 JavaScript 在浏览器中渲染界面并处理页面切换，只向服务器请求数据；多页应用每次跳转都由服务器返回完整的 HTML 页面并整页刷新。

“声明式 UI”是什么意思？

开发者描述在某个状态下界面应该是什么样子（UI = f(state)），而不是一步步写出如何修改 DOM；框架负责计算差异并更新 DOM。

React 是框架还是库？

React 本身是专注于 UI 渲染的库，路由、数据获取等需要生态中的其他库补充；Next.js、React Router 等在 React 之上构建了完整框架。

为什么今天不再推荐 Create React App？

CRA 已停止维护并在 2025 年被官方弃用，它构建慢、配置难扩展。官方建议使用框架（Next.js、React Router 等）或 Vite 等现代构建工具。
