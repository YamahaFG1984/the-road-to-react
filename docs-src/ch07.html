函数组件就是函数，而 JavaScript 里声明函数的方式不止一种。 这一章把组件改写成箭头函数，并认识“块体”和“简洁体（隐式返回）”两种形式 —— 从下一章开始，书中代码会在这两种形式之间频繁切换，提前熟悉可以少很多困惑。

本章目标

  • 会用函数声明和箭头函数两种方式写组件
  • 理解箭头函数的块体（显式 return）和简洁体（隐式 return）
  • 知道什么时候必须用块体

函数声明 vs 箭头函数

```jsx // 函数声明 function App() { ... } // 箭头函数表达式 const App = () => { ... }; ```

两种写法对函数组件来说效果一样。把项目里的三个组件都改成箭头函数：

```jsx src/App.jsx const App = () => { return ( ... ); }; const Search = () => { return ( ... ); }; const List = () => { return ( ... ); }; ```

不只是组件，map() 里的回调函数也可以改：

```jsx src/App.jsx const List = () => { return (
    {list.map((item) => { return (
  • ...
    • ); })}
); }; ```

块体与简洁体

如果一个箭头函数只是返回一个值，中间没有别的逻辑，就可以去掉花括号和 return， 这叫简洁体（concise body），返回是隐式的：

把 Search 改成简洁体：

```jsx src/App.jsx const Search = () => (
); ```

App、List 以及 map() 里的回调也都只是返回 JSX，同样可以精简：

```jsx src/App.jsx const App = () => (
...
); const List = () => (
    {list.map((item) => (
  • ...
    • ))}
); ```
⚠ 最常见的错误：花括号里忘了 return

list.map((item) => { <li>{item.title}</li> }) 用了花括号却没写 return， 每一项都返回 undefined，列表什么也不显示，而且不会报错。 看到列表莫名其妙是空的，先检查这里。

什么时候用哪种

一旦需要在 return 之前做点事（定义变量、写处理函数、调用 Hook），就必须用块体。 这在后面会非常频繁：

```jsx const App = () => { // 在返回之前执行一些逻辑 const title = 'React'; return (
...
); }; ```
★ 经验法则
  • 函数声明和箭头函数都可以，团队里统一一种即可。react.dev 官方文档多用函数声明，本书（和本教程）多用箭头函数。
  • 简洁体更短，但组件一旦需要逻辑就得改回块体，来回改很烦。所以很多人组件一律用块体，只在 map() 之类的小回调里用简洁体。
  • 本教程接下来会根据需要在两者间切换：看到 => ( 是简洁体，看到 => { 是块体。

小结

  • 组件可以用 function Name() {} 或 const Name = () => {} 声明。
  • 箭头函数块体 => { return … } 需要显式 return；简洁体 => (…) 隐式返回。
  • 需要在返回前写逻辑时必须用块体。

动手练习

  1. 把项目里所有组件和回调都改成箭头函数，并尽量使用简洁体。
  2. 故意写一个“花括号但没 return”的 map()，观察现象并修复。
  3. （选读）复习 MDN 上的“箭头函数”文档，特别是“返回对象字面量要用圆括号包裹”这一条：() => ({ a: 1 })。

面试题

如何用函数声明和箭头函数分别定义函数组件？

function MyComponent() { ... } 或 const MyComponent = () => { ... };。

箭头函数的隐式返回是什么？

省略花括号时，箭头后的单个表达式会自动作为返回值；多行 JSX 通常用圆括号包裹。

两种声明方式在组件上有功能差异吗？

对函数组件没有实质差别（组件不用 this）。区别在于函数声明会被提升，可以先使用后定义；箭头函数赋给 const 后必须先定义再在运行时使用。
