什么时候该拆出新组件？初学者常常拿不准。两个信号：

  • 组件太大了：一屏看不完、名字已经概括不了它在做什么。
  • 出现了自然的边界：一块界面有独立的职责（“显示列表”“搜索表单”），或者同样的结构重复出现。

通常的做法是先写在一个组件里，等它长大了再拆 —— 不必一开始就设计好完美的组件树。

声明、元素与实例

写 function List() {...} 是声明一个组件；在 JSX 里写 <List /> 是使用它。 用 JavaScript 的类来类比最好理解（注意：只是类比，函数组件和类没有技术上的关系）：

类：声明一次，new 很多次
```js // 类声明：蓝图 class Person { constructor(firstName, lastName) { this.firstName = firstName; this.lastName = lastName; } getName() { return this.firstName + ' ' + this.lastName; } } // 实例化：用蓝图造出具体对象 const robin = new Person('Robin', 'Wieruch'); const dennis = new Person('Dennis', 'Wieruch'); ```
组件：声明一次，使用很多次
```jsx // 组件声明：蓝图 function List() { ... } function App() { return (
{/* 两个 List 元素 → 两个独立的实例 */}
); } ```
术语是什么例子
组件声明一个返回 JSX 的函数function List() {...}
元素JSX 编译出的普通对象，描述“要渲染什么”<List />，即 { type: List, props: {} }
实例React 内部为页面上每一个组件维护的记录，保存它的状态页面上每出现一次 List，就有一个实例

React DOM：把组件树挂到页面上

我们一直在声明 App，却从没写过 <App />。它在哪里被使用？打开 src/main.jsx：

```jsx src/main.jsx import { StrictMode } from 'react'; import { createRoot } from 'react-dom/client'; import './index.css'; import App from './App.jsx'; createRoot(document.getElementById('root')).render( ); ```

这里用到了两个库：

  • react：组件、Hooks、JSX 相关的一切，你日常写代码用的都是它。
  • react-dom：把 React 连接到浏览器 DOM 的“渲染器”。整个应用通常只在入口处用它一次。

render() 的参数不一定是 <App />，任何 JSX 都行：

```jsx import { createRoot } from 'react-dom/client'; const title = 'React'; createRoot(document.getElementById('root')).render(

Hello {title}

); ```

从零开始的 React 应用通常只有一个 createRoot。但如果你在给一个老网站逐步引入 React， 可能会看到页面上有好几个 createRoot，分别接管不同区域 —— 这正是 React 能“渐进式采用”的原因。

旧写法：ReactDOM.render

React 17 及以前 React 19 已移除
```jsx import React from 'react'; import ReactDOM from 'react-dom'; import App from './App'; ReactDOM.render( , document.getElementById('root') ); ```
React 18 / 19 现在
```jsx import { StrictMode } from 'react'; import { createRoot } from 'react-dom/client'; import App from './App'; createRoot(document.getElementById('root')).render( ); ```

差别不只是写法：createRoot 开启了 React 18 引入的并发渲染能力 （React 可以中断、推迟不紧急的渲染，让界面保持响应）以及自动批处理。 旧的 ReactDOM.render 在 React 18 中被标记为废弃，在 React 19 中彻底移除， 同时被移除的还有 ReactDOM.hydrate（服务端渲染用，改为 hydrateRoot） 和 unmountComponentAtNode（改为 root.unmount()）。

StrictMode：开发时的“体检”

<StrictMode> 不渲染任何可见内容，它只在开发环境里帮你做额外检查：

  • 每个组件渲染两次：用来发现“渲染函数不纯”的问题（第 3 章说过，渲染应该没有副作用）。
  • 每个 Effect 挂载 → 卸载 → 再挂载：用来发现忘记清理的副作用（第 14 章）。
  • 对使用了过时 API 的代码给出警告。

小结

  • 把一块有独立职责的 JSX 搬进新函数，就提取出一个组件；在 JSX 里用 <Name /> 使用它。
  • 组件构成一棵树：根组件在最上面，没有子组件的是叶子。
  • 组件声明是蓝图；每个 <List /> 元素都会产生一个独立的实例。
  • createRoot(el).render(<App />) 是 React 应用的入口；ReactDOM.render 已在 React 19 中移除。
  • StrictMode 在开发时会故意重复调用渲染和 Effect，帮你提早发现问题。

面试题

为什么要把大组件拆分成小组件？

提升可读性、可维护性和复用性；每个组件职责单一，改动影响范围更小，也更容易测试。

React 元素和组件有什么区别？

组件是返回元素的函数（或类）；元素是描述“要渲染什么”的不可变普通对象，由 JSX 编译产生。

createRoot 和 ReactDOM.render 有什么区别？

createRoot 是 React 18 引入的新根 API，启用并发特性和自动批处理；ReactDOM.render 是旧 API，React 18 废弃，React 19 已移除。

StrictMode 有什么作用？会影响生产环境吗？

它在开发环境中对子树做额外检查（重复渲染、重复执行 Effect、过时 API 警告）以暴露潜在问题；生产构建中不做任何事。
