React 是声明式的：你描述界面应该是什么样，React 负责让 DOM 变成那样。 但总有少数事情只能“命令”DOM 去做：让输入框获得焦点、测量一个元素有多宽、调用第三方图表库。 这一章学习 React 提供的“逃生舱”—— ref，以及 React 19 在 ref 上的几处重要变化。

本章目标

  • 分清声明式和命令式，知道什么时候需要命令式
  • 用 useRef + useEffect 让输入框自动聚焦
  • 理解 ref 和 state 的区别
  • 掌握 React 19 的 ref 新写法：ref 作为普通 prop、不再需要 forwardRef

声明式 vs 命令式

命令式编程是一步步告诉计算机怎么做；声明式编程是描述想要的结果。 你已经在用 React 的声明式写法了：

命令式：JavaScript + DOM API
```js element.addEventListener('click', () => { // do something }); ```
声明式：React
```jsx const App = () => { const handleClick = () => { // do something }; return ( ); }; ```

但有些场景只能用命令式，最常见的有：

  • 读写 DOM：测量元素的宽高（读）、设置输入框焦点（写）、滚动到某个位置；
  • 复杂动画：设置和编排过渡动画；
  • 集成第三方库：比如 D3 这样的命令式图表库，需要你把一个真实 DOM 节点交给它。

useRef：拿到真实的 DOM 节点

```jsx src/App.jsx import { useState, useEffect, useRef } from 'react'; const InputWithLabel = ({ id, value, type = 'text', onInputChange, isFocused, children, }) => { // A：创建一个 ref const inputRef = useRef(null); // C：渲染完成后执行副作用 useEffect(() => { if (isFocused && inputRef.current) { // D：命令式地调用 DOM 方法 inputRef.current.focus(); } }, [isFocused]); return ( <>   {/* B：把 ref 交给 JSX 元素 */} ); }; ```
  1. A：useRef(null) 返回一个 ref 对象 { current: null }。这个对象在组件的整个生命周期里是同一个，它的 current 属性可以随意修改。
  2. B：把 ref 传给元素的 ref 属性。React 创建出真实的 DOM 节点后，会把节点赋给 ref.current。
  3. C：用 useEffect 进入“渲染之后”的阶段。
  4. D：此时 ref.current 就是真实的 <input>，可以调用它的 focus() 方法。

ref 和 state 的区别

ref 不只能存 DOM 节点，它可以存任何值。它和 state 都能“跨渲染保留数据”，区别在于：

state（useState）ref（useRef）
改变时触发重新渲染不触发重新渲染
怎么改调用 setter，下次渲染才生效直接赋值 ref.current = x，立即生效
能否在渲染时读取可以，这就是它的用途不建议（渲染结果不应依赖它）
适合存会影响界面显示的数据DOM 节点、定时器 id、上一次的值等“幕后”数据

React 19 的 ref 变化

1. ref 可以作为普通 prop 传给函数组件

如果父组件想拿到子组件内部的 DOM 节点（比如 App 想直接控制 InputWithLabel 里的 input）， 以前必须用 forwardRef 把组件包一层，因为 ref 是一个特殊属性，不会出现在 props 里。 React 19 起，ref 对函数组件来说就是一个普通 prop：

forwardRef React ≤ 18
```jsx import { forwardRef } from 'react'; const MyInput = forwardRef((props, ref) => ( )); // 父组件 const inputRef = useRef(null); ; ```
ref 作为 prop React 19
```jsx const MyInput = ({ ref, ...props }) => ( ); // 父组件（写法不变） const inputRef = useRef(null); ; ```

forwardRef 仍然可用，但已不再需要，未来版本会被废弃。

2. ref 回调可以返回清理函数

除了 ref 对象，ref 也可以接收一个函数，React 会在节点创建时用节点调用它。 React 19 起，这个函数可以返回清理函数，在节点被移除时调用 —— 和 useEffect 的清理如出一辙：

```jsx { // 节点挂载时 node.focus(); return () => { // 节点卸载时（React 19 新增） }; }} /> ```
⚠ 箭头函数的隐式返回会“意外”变成清理函数

ref={(node) => (instance = node)} 这种写法会隐式返回 node， React 19 会以为你返回了一个清理函数而报错（TypeScript 也会拒绝）。改成块体：ref={(node) => { instance = node; }}。

3. 更早以前的写法

写法年代现状
字符串 ref：ref="myInput" + this.refs.myInput类组件早期React 19 已移除
React.createRef()类组件（React 16.3+）遗留 API，函数组件请用 useRef
forwardRefReact 16.3 – 18React 19 中不再需要
useRef / ref 回调现在推荐
★ 能声明式就别命令式

ref 是逃生舱，不是日常工具。能用 props 和 state 解决的问题（比如本章的 autoFocus）， 就不要去直接操作 DOM。只有当声明式确实做不到时，才打开这个舱门。

小结

  • React 默认是声明式的；聚焦、测量、第三方库集成等场景需要命令式地访问 DOM。
  • useRef(null) + ref={inputRef} 拿到 DOM 节点，在 useEffect 里访问 inputRef.current。
  • ref 可以存任何值，修改不会触发重新渲染；影响界面的数据应该用 state。
  • React 19：ref 是函数组件的普通 prop，不需要 forwardRef；ref 回调可返回清理函数；字符串 ref 已移除。

面试题

useRef 是什么？有哪些用途？

返回一个在组件生命周期内保持不变的可变对象 { current }。常用于引用 DOM 节点，或保存不需要触发渲染的可变值（定时器 id、上一次的值等）。

useRef 和 useState 的区别？

修改 state 会触发重新渲染；修改 ref.current 不会，且立即生效。影响 UI 的数据用 state，幕后数据用 ref。

为什么要在 useEffect 里访问 ref.current？

渲染阶段 DOM 尚未创建或更新，ref.current 可能为 null；effect 在 DOM 提交之后执行，此时可以安全访问。

React 19 中 forwardRef 还需要吗？

不需要。函数组件可以直接通过 props 接收 ref，forwardRef 将在未来被废弃。
