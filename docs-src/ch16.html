这一章把三个互相关联的话题放在一起：用 Fragment 去掉多余的包裹元素； 把专门的 Search 组件改造成可复用的 InputWithLabel； 再用 组合（children）让组件像 HTML 标签一样可以在开闭标签之间放内容。

本章目标

  • 用 <>…</> 返回多个并列元素而不产生多余的 DOM
  • 把业务专用组件改造成通用组件，理解“通用 vs 专用”的取舍
  • 用 children prop 实现组件组合

Fragment：不产生 DOM 的包裹

第 4 章说过，组件只能返回一个根元素。所以 Search 里的 label 和 input 外面包了个 <div>。 可这个 div 只是为了满足 React 的语法要求，对页面结构和样式毫无用处，有时还会破坏 flex / grid 布局。

一种很少用的办法是返回数组（每项都得加 key，很啰嗦）：

```jsx const Search = ({ search, onSearch }) => [ , , ]; ```

更好的办法是 Fragment：

```jsx src/App.jsx import { Fragment } from 'react'; const Search = ({ search, onSearch }) => ( ); ```

它还有一个更常用的简写形式：

```jsx src/App.jsx const Search = ({ search, onSearch }) => ( <> ); ```
ⓘ 什么时候必须写完整的 <Fragment>

简写 <> 不能带任何属性。在列表里需要给 Fragment 加 key 时，要写完整形式： <Fragment key={item.id}>…</Fragment>。 旧代码里常见的 <React.Fragment> 就是同一个东西。

可复用组件

仔细看 Search：它其实就是“一个标签 + 一个输入框”，没有任何真正的“搜索”功能。 可名字、id、文字全都写死成了 search。这带来两个问题：

  • 想在别处放一个“带标签的输入框”（比如输入用户名），没法复用它。
  • 如果页面上放两个 Search，它们的 id="search" 重复了 —— 点击第二个标签，焦点会跳到第一个输入框。

组件组合与 children

到目前为止，我们的组件都是自闭合的：<List />。可 HTML 元素是可以有开闭标签、在中间放内容的： <button>点我</button>。React 组件也可以：

```jsx src/App.jsx const App = () => { ... return (

Search: ...
); }; ```

写在开闭标签之间的内容，会作为一个特殊的 prop —— children —— 传给组件。用它取代原来的 label prop：

```jsx src/App.jsx const InputWithLabel = ({ id, value, type = 'text', onInputChange, children, }) => ( <>   ); ```

children 可以是字符串，也可以是任意 JSX。比如想让标签加粗，调用方直接这样写，组件本身一行都不用改：

```jsx src/App.jsx Search: ```
🔎 深入一点：不止一个“插槽”

children 只有一个。需要多个插槽时，直接用普通 prop 传 JSX 就行： <Layout sidebar={<Nav />} content={<List />} />。 组合还有一个重要用途：减少 prop drilling。与其把数据穿过好几层中间组件， 不如在上层直接把渲染好的子组件作为 children 传进去，中间组件只负责“摆放”。

小结

  • <>…</>（或 <Fragment>）可以包裹多个元素而不产生多余的 DOM；需要 key 时用完整写法。
  • 把写死的值改成 props、把业务名字改成通用名字，专用组件就变成了可复用组件；组件设计是通用与专用之间的取舍。
  • 写在组件开闭标签之间的内容会作为 children prop 传入，这就是组件组合。

面试题

什么是 Fragment？为什么使用它？

一种不渲染任何 DOM 节点的包裹组件，用于在满足“单一根元素”要求的同时，不引入多余的 DOM 元素。

Fragment 可以有属性吗？

只能有 key（且必须使用 <Fragment> 完整写法），不能有 className、style 等。

什么是 children prop？

写在组件开闭标签之间的内容，React 会以 props.children 的形式传给组件。

如何让一个组件更可复用？

用 props 参数化可变部分，使用通用命名，不耦合具体业务；需要自定义内容的地方用 children 或 JSX 类型的 props。

是不是所有组件都应该做成可复用的？

不是。很多组件只在一个地方使用，承载具体业务，做成专用组件更简单。
