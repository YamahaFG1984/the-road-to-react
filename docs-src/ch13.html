props 只是一个普通 JavaScript 对象，所以所有处理对象的现代 JavaScript 技巧都能用在它身上。 这一章介绍几种让 props 写起来更简洁的写法：解构、默认值、嵌套解构、展开和剩余运算符。 它们不是必需的，但你在任何一个真实 React 项目里都会天天看到。

本章目标

  • 在函数签名里直接解构 props
  • 用参数默认值代替已被移除的 defaultProps
  • 理解嵌套解构、展开运算符 {...obj}、剩余运算符 ...rest
  • 知道每种写法适合什么场景

对象解构

先复习 JavaScript 的对象解构：一次从对象里取出多个属性。

```js const user = { firstName: 'Robin', lastName: 'Wieruch', }; // 不用解构 const firstName = user.firstName; const lastName = user.lastName; // 用解构 const { firstName, lastName } = user; ```

用在 Search 的 props 上：

```jsx src/App.jsx const Search = (props) => { const { search, onSearch } = props; return (
); }; ```

但为了写这一行解构，组件又得从简洁体改回块体。更好的办法是直接在函数参数里解构：

```jsx src/App.jsx const Search = ({ search, onSearch }) => (
); ```

组件内部几乎从不直接使用 props 这个容器本身，所以这种写法非常普遍。List 和 Item 也改一下：

```jsx src/App.jsx const List = ({ list }) => (
    {list.map((item) => ( ))}
); const Item = ({ item }) => (
  • {item.title} {item.author} {item.num_comments} {item.points}
    • ); ```

    默认值

    解构时可以顺便给默认值，父组件没传这个 prop 时就用它：

    ```jsx const Search = ({ search = '', onSearch, label = 'Search' }) => ( ... ); ```
    defaultProps React 19 中对函数组件已移除
    ```jsx const Search = (props) => ( ... ); Search.defaultProps = { label: 'Search', }; ```
    参数默认值 推荐
    ```jsx const Search = ({ label = 'Search' }) => ( ... ); ```

    嵌套解构

    item 本身也是个对象，可以在参数里继续往下解构：

    ```js const user = { firstName: 'Robin', pet: { name: 'Trixi', }, }; // 嵌套解构 const { firstName, pet: { name }, } = user; console.log(firstName + ' has a pet called ' + name); // "Robin has a pet called Trixi" ``` ```jsx src/App.jsx（写法 1：嵌套解构） const Item = ({ item: { title, url, author, num_comments, points, }, }) => (
  • {title} {author} {num_comments} {points}
    • ); ```

    能用，但函数签名一下子变得又长又深。嵌套解构在数据结构很深的场景里有用，在这里反而降低了可读性。

    展开运算符

    另一种思路：不传 item 对象，而是把它的每个属性都作为单独的 prop 传给 Item：

    ```jsx src/App.jsx（写法 2 · 第一步） const List = ({ list }) => (
      {list.map((item) => ( ))}
    ); const Item = ({ title, url, author, num_comments, points }) => ( ... ); ```

    Item 的签名清爽了，List 却变啰嗦了。用展开运算符 ... 解决。先复习：

    ```js const profile = { firstName: 'Robin', lastName: 'Wieruch' }; const address = { country: 'Germany', city: 'Berlin' }; const user = { ...profile, gender: 'male', ...address, }; console.log(user); // { firstName: 'Robin', lastName: 'Wieruch', gender: 'male', // country: 'Germany', city: 'Berlin' } ```

    在 JSX 里，{...item} 会把对象的每个键值对展开成一个个属性：

    ```jsx src/App.jsx（写法 2 · 第二步） const List = ({ list }) => (
      {list.map((item) => ( ))}
    ); ```

    剩余运算符

    最后一步。objectID 只用作 key，Item 并不需要它。 用剩余运算符把它从对象中“拆”出来，剩下的再展开：

    ```js const user = { id: '1', firstName: 'Robin', lastName: 'Wieruch', country: 'Germany', city: 'Berlin', }; const { id, country, city, ...userWithoutAddress } = user; console.log(userWithoutAddress); // { firstName: 'Robin', lastName: 'Wieruch' } console.log(id); // '1' ``` ```jsx src/App.jsx（写法 2 · 最终版） const List = ({ list }) => (
      {list.map(({ objectID, ...item }) => ( ))}
    ); ```
    ⚠ 不要把 key 展开进去

    如果写成 {list.map((item) => <Item {...item} key={item.objectID} />)} 而 item 里恰好有个叫 key 的字段， 或者把一个包含 key 的 props 对象整体展开，React 18.3 / 19 会警告 “A props object containing a "key" prop is being spread into JSX”。key 请始终显式地单独写。

    该用哪种？

    写法 2 最精简，但用到了不少进阶语法；写法 1 增加了缩进却没带来好处。 本教程接下来继续使用最初的版本 —— 传 item 对象、在签名里解构一层 —— 它不是最短的，却是最容易读懂的：

    ```jsx src/App.jsx（后续章节使用的版本） const List = ({ list }) => (
      {list.map((item) => ( ))}
    ); const Item = ({ item }) => (
  • {item.title} {item.author} {item.num_comments} {item.points}
    • ); ```
    ★ 经验法则
    • 几乎总是在函数签名里解构 props。例外：props 只是原样转交给下一个子组件时。
    • 要把一个对象的全部键值对传给子组件时，用展开 {...obj}，例如 <Child {...props} />。
    • 只想从 props 中分离出某几个属性时，用剩余 { a, ...rest }。
    • 只有在能提高可读性时才用嵌套解构。
    • 团队协作时，可读性永远比少写几个字符重要。
    🔎 深入一点：为什么 useState 返回数组，而 props 是对象？

    数组解构按位置取值，所以你可以随意命名：const [searchTerm, setSearchTerm] = useState('')、 const [count, setCount] = useState(0)。如果 useState 返回对象，就得写成 const { state: count, setState: setCount } = useState(0)，一个组件里用好几次就很烦。 props 则天然是“按名字”的，用对象最合适。

    小结

    • 在函数签名里解构 props：({ list, onRemove }) => …，并用参数默认值代替 defaultProps。
    • 展开 {...obj} 把对象的键值对作为属性传给元素；剩余 { a, ...rest } 把对象拆成“指定属性 + 其余部分”。
    • key 要单独显式书写，不要混在展开的对象里。
    • 选择写法时优先考虑可读性。

    动手练习

    1. 把项目中所有组件都改成在签名里解构 props。
    2. 分别实现“写法 1”和“写法 2”，确认效果一样，再改回推荐版本。
    3. 写一个 Button 组件：({ children, ...rest }) => <button {...rest}>{children}</button>，用它渲染一个 type="button"、带 onClick 的按钮 —— 体会“把剩下的 props 原样转交”的用法。

    面试题

    如何在函数组件的参数中解构 props？

    function MyComponent({ prop1, prop2 }) { ... }，也可以同时给默认值：{ prop1 = 'default' }。

    展开运算符在 React props 中怎么用？

    <MyComponent {...obj} /> 把对象的所有属性作为单独的 props 传入；也可以和其他属性组合：<C {...props} extra={x} />，后写的覆盖先写的。

    展开运算符是深拷贝还是浅拷贝？

    浅拷贝。嵌套对象仍然是对原对象的引用。

    剩余运算符在 React 中有什么用途？

    从 props 中取出部分属性，其余收集到一个新对象里，常用于“自己处理几个 prop，其余原样传给内部元素”。

    什么是 prop drilling？

    为了把数据传给深层组件，不得不经过多层并不使用它的中间组件逐层传递 props。Context（第 25 章）或组件组合（第 16 章）可以缓解。
