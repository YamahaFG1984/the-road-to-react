到目前为止，所有组件都挤在 src/App.jsx 一个文件里。这对学习很方便 —— 所有东西一眼可见 —— 但应用长大后就不行了。这一章把组件拆到不同的文件里，并介绍几种常见的目录组织方式。 先说结论：没有唯一正确的项目结构，结构应该随着项目一起演进。

本章目标

  • 用 ES 模块的 import / export 把组件拆到多个文件
  • 判断哪些组件该单独成文件，哪些该放在一起
  • 了解“按技术分”和“按功能分”两种目录组织思路

    ★ 拆分的判断依据
    • 一个组件会被多处使用（如 InputWithLabel）→ 独立文件。
    • 一个组件只为另一个组件服务（如 Item 之于 List）→ 放在同一个文件里；哪天别处也要用了，再拆出来。
    ⓘ 具名导出还是默认导出？

    本章用的是具名导出 export { List } + import { List } from './list'。 好处是名字固定，编辑器自动导入和全局重命名更可靠。export default 允许导入时随意起名，也很常见（比如 App）。 团队统一一种即可。

    目录结构的演进

    项目继续变大时，可以让每个组件拥有自己的文件夹，把实现、样式、测试、类型放在一起：

    ```tree src/ ├── list/ │ ├── index.jsx ← 组件实现 │ ├── style.css ← 样式（或 CSS Modules / styled 组件的 style.js） │ ├── test.jsx ← 测试 │ └── types.js ← 类型（TypeScript 时是 types.ts） ├── search-form/ │ └── ... └── input-with-label/ └── ... ```

    再往后，按“技术类型”分（所有组件一个目录、所有 Hook 一个目录……）会越来越难找东西。 这时通常转向按功能 / 领域组织：和某个功能相关的所有东西放在一起，真正通用的放进 shared/：

    ```tree src/ ├── messages/ │ ├── index.jsx │ ├── style.css │ ├── test.jsx │ └── types.js ├── users/ │ ├── index.jsx │ └── ... └── shared/ ├── button/ │ ├── index.jsx │ └── ... └── input/ ├── index.jsx └── ... ```
    💡 使用框架时

    如果使用 Next.js、React Router 等框架，目录结构的一部分会由框架的路由约定决定（比如 app/ 下的文件夹即路由）。 上面的原则仍然适用于路由之外的组件和功能代码。

    小结

    • 用 export / import 把组件拆到不同文件；每个文件只导入自己直接用到的东西。
    • 可复用组件单独成文件；只服务于某个组件的子组件和它放在一起。
    • 结构演进：单文件 → 多文件 → 组件文件夹 → 按功能分 → 功能模块。
    • 没有标准答案，按需演进；觉得一个文件放得下，就不必急着拆。

    面试题

    如何组织一个 React 项目的文件结构？

    没有唯一标准。小项目可以按组件拆文件；变大后可以每个组件一个文件夹（实现、样式、测试、类型放一起）；再大可以按功能/领域组织，并把通用组件放进 shared。

    具名导出和默认导出有什么区别？

    具名导出导入时必须使用相同名字（可用 as 重命名），一个文件可以有多个；默认导出每个文件只能有一个，导入时可任意命名。

    什么时候应该把组件拆到单独的文件？

    当它被多处复用，或者文件变得过大、职责过多时。只被一个组件使用的小组件可以留在同一个文件中。
