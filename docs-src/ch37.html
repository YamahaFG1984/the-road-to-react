接下来去哪里

作者的建议是：先别急着读下一本书。花一周时间扩展这个应用，或者用一个自己感兴趣的 API 做一个新项目，部署上线，拿给别人看。之后再按兴趣挑选方向：

  • 框架：Next.js 是掌握 React 这个“库”之后最自然的下一步，你会接触服务端渲染、文件路由、服务端组件和服务端函数。
  • 路由：应用有多个页面时，用 React Router 在不刷新页面的情况下切换 URL 和界面。
  • 代码组织：回顾第 32 章，把 Hacker Stories 按功能重新组织一遍。
  • 构建工具：从零用 Webpack + Babel 搭一个 React 项目，理解 Vite 在背后替你做了什么。
  • 数据库与认证：让数据跨会话保存、在用户之间共享。Firebase、Supabase 能让你不写后端就用上数据库和登录。
  • 自己的后端：写一个连接数据库、处理认证授权的后端，用 REST 或 GraphQL 和前端通信。
  • 状态管理：大多数应用用组件状态 + Context 就够了；真正需要全局状态时再看 Zustand 或 Redux Toolkit。
  • 测试：深入 React Testing Library 的组件测试，以及 Playwright 的端到端测试。
  • TypeScript：越用越离不开，很多人最后会全面切换过去。
  • UI 组件：初学者常常太早引入组件库。先用普通 HTML 和 React 状态写出下拉框、复选框、对话框，再用组件库会轻松得多。
  • React Native：用 React 写 iOS / Android 应用。核心概念相同，区别在于布局组件、构建工具和平台 API。
💡 最后的建议

学框架最快的方式永远是动手做点什么。找一个你真正感兴趣的 API —— 天气、电影、股票、游戏、GitHub —— 用本教程学到的东西做一个小应用，部署出去。遇到问题回来翻对应的章节。做完一个完整的项目，胜过读十篇教程。

小结

  • React 的核心只有几条：组件是函数、UI 是状态的函数、数据向下流、事件向上传、副作用放在渲染之外。
  • 读老代码时，用新旧对照表把类组件、生命周期、forwardRef、onSubmit+preventDefault 等翻译成现代写法。
  • 下一步：做自己的项目，然后按需学习框架、路由、数据、状态管理、测试等方向。
