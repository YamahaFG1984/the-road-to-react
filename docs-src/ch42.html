调试的流程

读懂常见报错

React 的报错信息通常已经告诉你答案了。下面是初学者最常遇到的几条：

报错 / 警告通常的原因章节
Each child in a list should have a unique "key" propmap() 返回的元素缺少 key，或 key 重复5
Objects are not valid as a React child把一个对象直接放进了 JSX：{user} 应为 {user.name}4
Too many re-renders渲染时直接调用了 setState，常见于 onClick={setOpen(true)}8

💡 看报错的正确姿势

① 读完第一行的错误描述；② 看组件栈（component stack）—— 它告诉你错误发生在哪个组件里、这个组件被谁渲染； ③ 点击控制台里的文件链接直接跳到源码（Vite 自带 source map，看到的是你写的代码而不是打包后的代码）。 React 19 的开发版报错更精简，同一个错误不再重复打印好几次；19.1 起还会附带更完整的“所有者栈”（owner stack），能看出是哪个组件一路把出问题的组件渲染出来的。

console.log 的正确用法

```jsx // 给日志加标签，打印对象时用对象简写，能看到变量名 console.log('Item render', { item, isFavorite }); // 只在条件满足时打印 if (item.points > 100) console.log('hot story', item); // 数组对象用表格看更清楚 console.table(stories.map(({ title, points }) => ({ title, points }))); ```

Network 面板

数据相关的问题先看 Network：请求发了没有？发了几次？URL 和参数对不对？状态码是多少？返回的 JSON 结构和代码里假设的一样吗？ 一半以上的“数据显示不出来”在这里就能找到答案。还可以把网速调成 Slow 3G，复现加载状态和竞态问题。

React DevTools

安装浏览器扩展 React Developer Tools 后，开发者工具里会多出两个面板：

Components 面板

  • 组件树：看到的是 React 组件而不是 HTML 元素。用左上角的选择工具点页面上的元素，可以直接定位到对应组件。
  • props / state / hooks：选中组件后右侧显示它当前的所有数据。可以直接修改 state，立即看到界面变化 —— 用来验证“是不是数据的问题”非常快。
  • rendered by：这个组件是被谁渲染的，props 从哪来一目了然。
  • 选中组件后，在控制台输入 $r 可以访问它的数据。
  • 设置里勾选 “Highlight updates when components render”：每次重新渲染的组件会闪一下边框（第 28 章）。

Profiler 面板

  • 录制一段交互，看每次提交（commit）中有哪些组件渲染了、各花多少时间。
  • 在设置中开启 “Record why each component rendered while profiling”，选中组件就能看到它为什么重新渲染：是 props 变了（哪个）、state 变了、还是父组件渲染了。
  • 性能问题只在这里找到证据后再优化（第 28 章“先测量”）。

四类典型 bug

1. 过期闭包（stale closure）

```jsx const Timer = () => { const [count, setCount] = useState(0); useEffect(() => { const id = setInterval(() => { setCount(count + 1); // count 永远是 0！ }, 1000); return () => clearInterval(id); }, []); // 依赖为空：effect 只运行一次，闭包捕获的是第一次渲染的 count return

{count}

; // 显示 1 之后就不动了 }; ```

解决办法：用函数形式 setCount((c) => c + 1)；或者把 count 加进依赖数组；或者用 ref 保存最新值。 ESLint 的 exhaustive-deps 规则能提前发现大多数这类问题。

2. 直接修改状态

```jsx // ❌ 界面不更新：数组还是同一个引用，React 认为没变 stories.push(newStory); setStories(stories); // ✅ setStories([...stories, newStory]); ```

3. effect 死循环

```jsx // ❌ 每次渲染 options 都是新对象 → effect 每次都运行 → setData → 再渲染 … const options = { query }; useEffect(() => { fetchData(options).then(setData); }, [options]); // ✅ 依赖基本类型的值 useEffect(() => { fetchData({ query }).then(setData); }, [query]); ```

4. “状态没更新”

```jsx const handleClick = () => { setCount(count + 1); console.log(count); // 还是旧值 —— 这不是 bug，是快照（第 10 章） }; ```

进阶：在 VS Code 里调试

VS Code 可以直接连接浏览器调试：在编辑器里打断点、查看变量，而不用切换到浏览器的 Sources 面板。 在 .vscode/launch.json 中添加：

```json .vscode/launch.json { "version": "0.2.0", "configurations": [ { "type": "chrome", "request": "launch", "name": "Debug Hacker Stories", "url": "http://localhost:5173", "webRoot": "${workspaceFolder}" } ] } ```

先 npm run dev，再在 VS Code 的“运行和调试”里启动这个配置即可。

小结

  • 调试流程：稳定复现 → 缩小范围 → 提出假设 → 验证，不要随机改代码。
  • React 报错通常已经指出原因，结合组件栈定位到具体组件。
  • 浏览器工具：带标签的日志、debugger 断点、Network 面板。
  • React DevTools：Components 看并修改 props / state / hooks；Profiler 看渲染耗时和重新渲染的原因。
  • 典型 bug：过期闭包、直接修改状态、effect 依赖不稳定导致死循环、误以为 setState 立即生效。

面试题

什么是过期闭包？在 React 中怎么避免？

函数捕获了创建时那次渲染的变量，之后变量更新了它仍使用旧值。可以通过正确填写依赖数组、使用 setState 的函数形式、或用 ref 保存最新值来避免。

“Too many re-renders” 通常是什么原因？

在渲染过程中无条件调用 setState，例如把函数调用 onClick={setX(1)} 而不是函数传给事件属性，导致无限渲染循环。

如何找出组件为什么重新渲染？

使用 React DevTools Profiler，开启“记录每个组件渲染原因”，可以看到是哪个 props、state 或 hook 发生了变化，或是父组件渲染导致。

为什么修改数组后界面没有更新？

直接修改（push、splice、赋值）不会改变数组引用，React 通过 Object.is 判断状态未变；应创建新数组或新对象。
