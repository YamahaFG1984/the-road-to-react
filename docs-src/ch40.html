queryKey：缓存的“地址”

queryKey 是一个数组，唯一标识一份数据。它有两个作用： ① 作为缓存的键：['stories', 'react'] 和 ['stories', 'vue'] 是两份独立的缓存； ② 作为依赖：key 里的值变化时，自动请求新数据 —— 就像 effect 的依赖数组。 所以 queryFn 用到的所有变量都应该出现在 queryKey 里（官方 ESLint 插件会检查这一点）。

返回值含义
dataqueryFn 返回的数据（还没有时是 undefined）
isPending还没有任何数据（首次加载）
isFetching正在请求中（包括有缓存时的后台刷新）
isError / error请求失败（默认会自动重试 3 次后才算失败）
refetch()手动重新请求

搜索时避免闪烁

换一个新的搜索词时，新 key 还没有缓存，data 会变回 undefined，列表先消失再出现。用 placeholderData 保留上一次的结果：

```jsx import { keepPreviousData, useQuery } from '@tanstack/react-query'; useQuery({ queryKey: ['stories', query], queryFn: ({ signal }) => fetchStories(query, signal), placeholderData: keepPreviousData, // 新数据到达前继续显示旧列表 }); ```

修改数据：删除文章

“Dismiss” 删除文章怎么办？数据在缓存里，不在组件状态里。真实应用里，删除通常要请求服务器，然后让缓存失效、重新获取：

```jsx import { useMutation, useQueryClient } from '@tanstack/react-query'; const queryClient = useQueryClient(); const removeMutation = useMutation({ mutationFn: (story) => api.deleteStory(story.objectID), // 请求服务器 onSuccess: () => { // 让所有以 'stories' 开头的缓存失效 → 自动重新获取 queryClient.invalidateQueries({ queryKey: ['stories'] }); }, }); ```

Hacker News API 不能删除文章，我们只是在本地隐藏它，所以直接修改缓存即可：

```jsx src/App.jsx const queryClient = useQueryClient(); const handleRemoveStory = (item) => { queryClient.setQueryData(['stories', query], (oldStories) => oldStories.filter((story) => story.objectID !== item.objectID) ); }; ```
ⓘ 和第 20 章的 reducer 对比

setQueryData 的更新函数和 reducer 的 REMOVE_STORY 分支一模一样 —— 都是不可变地过滤出新数组。 区别在于数据存在哪里：以前在组件的 useReducer 里，现在在全局共享的查询缓存里，任何用同一个 key 的组件都会看到变化。

小结

  • 服务端状态有缓存、同步、过期等特殊问题，适合交给专门的库，而不是 useState / useReducer。
  • useQuery({ queryKey, queryFn }) 返回 data、isPending、isError、isFetching 等状态。
  • queryKey 既是缓存键又是依赖；queryFn 用到的变量都要放进去。
  • 修改数据：请求服务器后 invalidateQueries，或用 setQueryData 直接更新缓存。
  • useInfiniteQuery 处理“加载更多”；useSuspenseQuery 与 Suspense / 错误边界配合。

面试题

什么是服务端状态？和客户端状态有什么不同？

数据的权威来源在服务器，客户端只持有可能过时的副本，需要异步获取并处理缓存、同步、重试等问题；客户端状态完全由前端拥有，同步且始终最新。

queryKey 的作用是什么？

唯一标识查询、作为缓存键；key 中的值变化时自动重新获取，相当于依赖数组。

staleTime 和 gcTime 有什么区别？

staleTime 决定数据多久后被视为过期（过期后在合适时机后台重新获取）；gcTime 决定不再被使用的缓存多久后从内存中移除。

如何在修改数据后更新列表？

在 mutation 成功后调用 invalidateQueries 让相关缓存失效并重新获取，或用 setQueryData 直接更新缓存（也可做乐观更新）。

isPending 和 isFetching 的区别？

isPending 表示还没有任何数据；isFetching 表示有请求正在进行，包括已有缓存时的后台刷新。
