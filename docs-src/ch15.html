上一章我们用 useState + useEffect 实现了“状态自动同步到 localStorage”。 这套组合很可能在别处还要用（记住主题、记住排序方式……）。React 允许你把 Hook 的组合打包成自己的 Hook —— 自定义 Hook，这是 React 复用逻辑的主要方式。

本章目标

  • 把 useState + useEffect 提取成自定义 Hook useStorageState
  • 掌握自定义 Hook 的约定：use 前缀、返回数组、通用命名
  • 理解为什么每次调用都有独立的状态
  • 知道自定义 Hook 取代了哪些旧的复用模式

先想好怎么用

先写出理想中的用法：像 useState 一样返回“值 + 设置函数”，只是背后会自动同步到 localStorage：

```jsx src/App.jsx const App = () => { const stories = [ ... ]; const [searchTerm, setSearchTerm] = useStorageState('React'); const handleSearch = (event) => { setSearchTerm(event.target.value); }; const searchedStories = stories.filter((story) => story.title.toLowerCase().includes(searchTerm.toLowerCase()) ); return ( ... ); }; ```

App 里的 localStorage 细节全部消失了。接下来实现这个 Hook。

一步步提取

第一步：把原来的代码原封不动地搬进一个以 use 开头的函数：

```jsx src/App.jsx const useStorageState = () => { const [searchTerm, setSearchTerm] = useState( localStorage.getItem('search') ?? '' ); useEffect(() => { localStorage.setItem('search', searchTerm); }, [searchTerm]); }; ```

第二步：接收初始值参数，并把 App 需要的东西以数组形式返回：

```jsx src/App.jsx const useStorageState = (initialState) => { const [searchTerm, setSearchTerm] = useState( localStorage.getItem('search') ?? initialState ); useEffect(() => { localStorage.setItem('search', searchTerm); }, [searchTerm]); return [searchTerm, setSearchTerm]; }; ```

第三步：内部名字还带着“search”这个业务含义。把它改成通用的 value，Hook 就和具体业务无关了：

```jsx src/App.jsx const useStorageState = (initialState) => { const [value, setValue] = useState( localStorage.getItem('value') ?? initialState ); useEffect(() => { localStorage.setItem('value', value); }, [value]); return [value, setValue]; }; ```

第四步：还有个问题 —— localStorage 的键写死成了 'value'。如果在应用里用两次这个 Hook， 两者会互相覆盖。把键也作为参数传进来。因为键来自外部、可能会变，它也要加进 effect 的依赖数组：

```jsx src/App.jsx const useStorageState = (key, initialState) => { const [value, setValue] = useState( localStorage.getItem(key) ?? initialState ); useEffect(() => { localStorage.setItem(key, value); }, [value, key]); return [value, setValue]; }; const App = () => { ... const [searchTerm, setSearchTerm] = useStorageState('search', 'React'); ... }; ```

你刚刚写出了第一个自定义 Hook。

自定义 Hook 的约定

  • 名字以 use 开头。这不只是风格：React 和 ESLint 靠这个前缀识别 Hook，并对它应用 Hook 的规则（只能在顶层调用等）。
  • 可以调用其他 Hook。这正是它和普通函数的区别 —— 普通函数里不能调用 useState。
  • 返回什么由你决定。模仿 useState 返回数组，调用方可以自由命名；返回值很多时返回对象更清楚。
  • 尽量通用。内部不要出现具体业务的名字，这样才能在别处复用。

每次调用，状态各自独立

一个常见误解是“自定义 Hook 让多个组件共享状态”。并不是 —— 它共享的是逻辑， 每次调用都会得到一份全新、独立的状态：

```jsx const [searchTerm, setSearchTerm] = useStorageState('search', 'React'); const [theme, setTheme] = useStorageState('theme', 'light'); // 两份完全独立的状态，分别存在 localStorage 的 'search' 和 'theme' 下 ```
⚠ 同一个 key 会怎样？

两个组件都调用 useStorageState('search', …) 时，它们的 React 状态仍然是独立的， 只是都往 localStorage 的同一个键里写 —— 谁最后写就留下谁的值。所以 key 应当唯一。

自定义 Hook 取代了什么

在 Hooks 出现之前，React 里复用“带状态的逻辑”要靠两种比较绕的模式： 高阶组件（HOC，一个接收组件、返回新组件的函数）和 render props（通过一个函数 prop 把数据交出来）。

高阶组件（HOC） 旧模式
```jsx const withStorageState = (key, initial) => (Component) => class extends React.Component { state = { value: localStorage.getItem(key) ?? initial }; componentDidUpdate() { localStorage.setItem(key, this.state.value); } render() { return ( this.setState({ value })} /> ); } }; // 组件被一层层包起来，数据从 props 里“冒出来” export default withStorageState('search', 'React')(App); ```
自定义 Hook 现在
```jsx const useStorageState = (key, initialState) => { const [value, setValue] = useState( localStorage.getItem(key) ?? initialState ); useEffect(() => { localStorage.setItem(key, value); }, [value, key]); return [value, setValue]; }; // 在组件里直接调用，数据从哪来一目了然 const [searchTerm, setSearchTerm] = useStorageState('search', 'React'); ```

HOC 和 render props 会让组件树里多出很多“包装层”（俗称 wrapper hell），多个 HOC 之间还可能 prop 重名冲突。 自定义 Hook 就是普通函数调用，没有这些问题。今天你仍会在一些库里见到 HOC（比如一些老的路由、国际化库），知道它是什么就够了。

💡 社区里有大量现成的 Hook

搜索 “react hooks library” 会找到成百上千个现成的 Hook：useLocalStorage、useDebounce、useMediaQuery…… 自己写一遍 useStorageState 能帮你理解它们是怎么工作的。

小结

  • 自定义 Hook 是以 use 开头、内部调用其他 Hook 的函数，用来复用有状态的逻辑。
  • useStorageState(key, initialState) 封装了 useState + useEffect，返回 [value, setValue]。
  • 来自外部参数的值（如 key）要加进 effect 依赖数组。
  • 每次调用 Hook 都得到独立的状态；Hook 共享逻辑，不共享数据。
  • 自定义 Hook 取代了 HOC 和 render props 这两种旧的逻辑复用模式。

动手练习

  1. 用 useStorageState 再存一个值，比如用户是否展开了某个区域（注意 localStorage 只能存字符串，布尔值要怎么处理？）。
  2. 挑战：让 useStorageState 支持任意可序列化的值（提示：JSON.stringify / JSON.parse）。
  3. 写一个 useToggle(initial) Hook，返回 [on, toggle]。

面试题

什么是自定义 Hook？如何创建？

以 use 开头、内部使用其他 Hook 的 JavaScript 函数，用于封装和复用有状态的逻辑。

多个组件使用同一个自定义 Hook，会共享状态吗？

不会。每次调用都有独立的状态；共享的是逻辑。要共享状态需要状态提升、Context 或外部状态库。

自定义 Hook 能访问组件的 props 吗？

不能直接访问，需要通过参数把需要的数据传进去。

为什么自定义 Hook 必须以 use 开头？

这是 React 识别 Hook 的约定，linter 据此检查 Hook 规则；不以 use 开头，就无法保证它只在组件顶层被调用。

自定义 Hook 相比 HOC / render props 有什么优势？

没有额外的组件嵌套层级，数据来源清晰，不存在 prop 命名冲突，组合多个 Hook 也很自然。
