HTML 的表单元素天生就有自己的“状态”：输入框自己记着里面的字，复选框自己记着勾没勾。 当 React 也有一份状态时，就出现了“两个人各记一本账”的问题。这一章看看问题出在哪，以及怎么让 React 当唯一的账本。

本章目标

  • 发现“React 状态和输入框内容不同步”的问题
  • 用 value + onChange 写出受控组件
  • 分清受控组件和非受控组件，知道 React 19 中非受控写法的新地位

发现问题

这个输入框现在是一个受控元素（controlled element），Search 也因此成了受控组件： 它显示什么完全由外部传入的 props 决定。流程是：用户按键 → onChange → 更新状态 → 重新渲染 → 输入框显示新的 value。

⚠ 两个常见错误
  • 只写 value 不写 onChange：输入框变成只读，怎么打字都没反应（React 会在控制台警告）。只想显示初始值、之后让浏览器自己管，请用 defaultValue。
  • value 一开始是 undefined：React 会认为它是非受控的，等值变成字符串时又变成受控，于是警告 “A component is changing an uncontrolled input to be controlled”。初始值用 '' 而不是 undefined / null。

ⓘ React 19 的新情况：非受控表单“回归”了

在 React 19 之前，几乎所有教程都要求“表单一律受控”。React 19 引入了 form Actions（第 24 章）： <form action={fn}> 提交时，React 会把整个表单的 FormData 交给你的函数， 提交成功后还会自动重置非受控字段。对于“填完一次性提交”的表单（注册、留言）， 非受控 + FormData 写起来更短，也不会每敲一个键就重新渲染一次。

小结

  • 表单元素有自己的内部状态，不给 value 时它和 React 状态会不同步。
  • 受控组件：value={state} + onChange={更新 state}，React 状态是唯一数据源。
  • 非受控组件：用 defaultValue 给初始值，提交时通过 FormData 或 ref 读取。
  • 需要实时使用输入值时用受控；React 19 的 form action 让简单表单用非受控写法更方便。

面试题

什么是受控组件？

表单元素的值由 React 状态决定（通过 value/checked），并通过 onChange 更新状态的组件。React 状态是唯一数据源。

受控组件和非受控组件的区别？

受控组件的值存在 React 状态中；非受控组件的值由 DOM 自己维护，通过 defaultValue 设初值，需要时用 ref 或 FormData 读取。

如何清空一个受控输入框？

把对应的状态设为空字符串即可，例如 setValue('')。

受控组件有什么缺点？

字段多时代码冗长，每次按键都会触发重新渲染。可以用 form Actions + 非受控字段或表单库（如 React Hook Form）缓解。
