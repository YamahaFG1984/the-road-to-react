按钮、输入框、下拉菜单、对话框、表格、日期选择器……每个项目都要用，自己从零写又费时又难做好（尤其是第 43 章讲的可访问性）。 UI 组件库就是为此而生的。但 React 的组件库也分好几种“流派”，选错了，要么改不动样式，要么要写太多代码。 这一章把它们分类讲清楚，并给出不同场景的推荐。

本章目标

  • 分清三类组件库：完整设计系统、无样式组件（headless）、复制粘贴式（shadcn/ui）
  • 认识 Ant Design、MUI、Mantine、shadcn/ui、Radix、React Aria 等主流选择
  • 了解组件库与样式方案（第 26–27 章）如何搭配
  • 根据项目类型做出选择，并避开常见的坑

三种流派

完整设计系统

Ant Design

蚂蚁集团开源，国内中后台项目的事实标准。组件极其丰富（表格、表单、树、穿梭框、日期范围……）， 中文文档完善，还有 Ant Design Pro / ProComponents 提供整套后台模板和“高级组件”。

```bash npm install antd ```

看看它的 Table —— 第 33 章手写的排序，在这里只是一个配置项：

```jsx import { Table, Button } from 'antd'; const columns = [ { title: 'Title', dataIndex: 'title', render: (title, story) => {title}, sorter: (a, b) => a.title.localeCompare(b.title), }, { title: 'Author', dataIndex: 'author' }, { title: 'Comments', dataIndex: 'num_comments', sorter: (a, b) => a.num_comments - b.num_comments }, { title: 'Points', dataIndex: 'points', sorter: (a, b) => a.points - b.points }, { title: 'Actions', render: (_, story) => ( ), }, ]; ```

MUI

实现了 Google 的 Material Design，全球使用最广的 React 组件库之一，海外企业项目常见。 有免费的核心组件和付费的高级组件（MUI X：数据表格、日期选择器等）。

Mantine、Chakra UI

API 友好、上手快，Mantine 自带大量 Hooks（表单、通知、快捷键等），适合快速搭建完整应用。 国内还有 Arco Design（字节）、TDesign（腾讯）、Semi Design（抖音）等，思路和 Ant Design 类似。

shadcn/ui：复制粘贴式

shadcn/ui 近两年最火，但它严格来说不是一个 npm 包：用命令行把组件的源代码复制到你的项目里， 之后这些代码就归你所有，想怎么改就怎么改。它的组件基于 Radix（行为和可访问性）+ Tailwind（样式）。

```bash npx shadcn@latest init # 初始化（需要项目已配置 Tailwind） npx shadcn@latest add button # 把 Button 组件复制到 src/components/ui/button.jsx npx shadcn@latest add dialog table ``` ```jsx import { Button } from '@/components/ui/button'; ```

无样式组件：Radix、React Aria

如果你有自己的设计稿、不想要任何默认样式，但又不想自己处理键盘交互和 ARIA，就用无样式组件库。 例如 Radix 的对话框：焦点管理、Esc 关闭、滚动锁定、ARIA 属性全都做好了，外观完全由你的 className 决定：

```jsx import * as Dialog from '@radix-ui/react-dialog'; Delete all favorites Are you sure? This cannot be undone. Cancel ```

React Aria（Adobe）是可访问性做得最严谨的方案，适合对无障碍有严格要求的产品； Base UI 由 MUI 团队和 Radix 的原作者共同打造；Headless UI 来自 Tailwind 团队。

按场景选择

图标

  • lucide-react：简洁统一的线性图标，shadcn/ui 默认使用。
  • react-icons：把多个图标集（Font Awesome、Material、Heroicons…）打包在一起，按需导入。
  • 使用 Ant Design、MUI 时，优先用它们自带的图标包，风格一致。
⚠ 常见的坑
  • 混用多个组件库：两套设计语言、两套主题、双倍体积。一个项目选定一个。
  • 和组件库对着干：用大量 !important 覆盖 Ant Design 的样式，说明它不适合这个设计 —— 考虑换成 headless 方案。
  • 没有按需加载：确认打包后只包含用到的组件（现代组件库大多默认支持 tree-shaking）。
  • 以为用了组件库就不用管可访问性：组件本身做好了，但 label、alt、焦点顺序仍然要你负责。

小结

  • 组件库三种流派：完整设计系统（Ant Design、MUI、Mantine）、复制粘贴式（shadcn/ui）、无样式组件（Radix、React Aria、Base UI）。
  • 越偏向完整设计系统，开发越快、外观越受限；越偏向 headless，外观越自由、工作量越大。
  • 选择要考虑与样式方案的搭配：shadcn/ui 需要 Tailwind，MUI 自带 CSS-in-JS。
  • 中后台优先 Ant Design；有设计稿的 C 端产品优先 shadcn/ui 或 Radix + Tailwind。

面试题

什么是 headless 组件库？有什么优势？

只提供组件的行为、状态和可访问性（键盘交互、焦点管理、ARIA），不提供样式的库。优势是外观完全可定制，同时不必自己实现复杂的交互和无障碍细节。

shadcn/ui 和传统组件库有什么不同？

它不是作为依赖安装，而是把组件源码复制到项目中，开发者完全拥有和修改这些代码；底层依赖 Radix 等无样式组件和 Tailwind。

中后台项目为什么常用 Ant Design？

组件覆盖面广（复杂表格、表单、树形控件等），交互规范统一，中文文档和生态完善，有 Pro 系列模板，开发效率高。

一个项目中可以混用多个 UI 组件库吗？

技术上可以，但通常不推荐：设计风格不一致、主题和样式可能冲突、包体积增大、维护成本上升。
