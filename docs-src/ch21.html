认识 Hacker News API

Hacker News 是一个技术新闻社区，Algolia 为它提供了一个免费、无需密钥的搜索 API。 在浏览器地址栏里直接打开下面这个地址看看：

```text https://hn.algolia.com/api/v1/search?query=react ```

返回的是 JSON，结构大致如下（省略了很多字段）：

```json { "hits": [ { "title": "React 19 is now stable", "url": "https://react.dev/blog/...", "author": "someone", "num_comments": 312, "points": 1024, "objectID": "42345678" } ], "page": 0, "nbPages": 50, "hitsPerPage": 20 } ```

文章在 hits 数组里，每一项的字段和我们的示例数据一模一样 —— 这就是为什么一开始示例数据要用 num_comments、objectID 这种命名。

用 fetch 获取数据

💡 先自己试试

任务：删除 initialStories 和 getAsyncStories，改用浏览器的 fetch 请求上面的地址。 成功和失败的处理逻辑和之前完全一样。

```jsx src/App.jsx // A const API_ENDPOINT = 'https://hn.algolia.com/api/v1/search?query='; const App = () => { ... useEffect(() => { dispatchStories({ type: 'STORIES_FETCH_INIT' }); fetch(`${API_ENDPOINT}react`) // B .then((response) => response.json()) // C .then((result) => { dispatchStories({ type: 'STORIES_FETCH_SUCCESS', payload: result.hits, // D }); }) .catch(() => dispatchStories({ type: 'STORIES_FETCH_FAILURE' }) ); }, []); ... }; ```
  • A：API 地址存成常量，放在组件外面（它不依赖组件里的任何东西）。
  • B：fetch(url) 发起请求，返回一个 Promise。这里用模板字符串拼接地址。
  • C：fetch 得到的是一个 Response 对象，要调用 response.json() 把响应体解析成 JavaScript 对象（这也是异步的）。
  • D：真实数据的结构不一样，文章在 result.hits 里。
ⓘ 模板字符串

`${API_ENDPOINT}react` 是 ES6 的模板字符串，用反引号包裹，${} 里放表达式。 它等价于老式的 API_ENDPOINT + 'react'，但拼接多个变量时可读性好得多。

⚠ fetch 的一个坑：HTTP 错误不会进 catch

fetch 只有在网络失败时才会 reject。服务器返回 404 或 500 时，Promise 照样 resolve！ 严谨的写法要检查 response.ok： .then((r) => { if (!r.ok) throw new Error(r.status); return r.json(); })。 第 23 章换成 axios 后，它会自动把非 2xx 状态当作错误。

刷新页面，你会看到来自 Hacker News 的真实 React 相关文章。因为数据结构没变，Item 组件一行都不用改， 搜索框也照样能在这些文章里筛选标题。

从客户端搜索到服务端搜索

不过有个明显的问题：数据永远是用 “react” 查来的。在搜索框里输入 “vue”，只会在这 20 条 React 文章里找标题含 “vue” 的 —— 几乎总是空的。这叫客户端搜索：只在已经下载到浏览器的数据里过滤。

```jsx src/App.jsx {stories.isLoading ? (

第二步，用 searchTerm 拼接地址，并把它加进依赖数组 —— 这样搜索词每次变化，effect 都会重新执行，发起新请求：

```jsx src/App.jsx useEffect(() => { // searchTerm 为空（'', null, undefined）时什么也不做 if (!searchTerm) return; dispatchStories({ type: 'STORIES_FETCH_INIT' }); fetch(`${API_ENDPOINT}${searchTerm}`) .then((response) => response.json()) .then((result) => { dispatchStories({ type: 'STORIES_FETCH_SUCCESS', payload: result.hits, }); }) .catch(() => dispatchStories({ type: 'STORIES_FETCH_FAILURE' }) ); }, [searchTerm]); ```

现在输入 “vue”，就会看到真正的 Vue 相关文章。如果依赖数组还是 []，effect 只会在第一次渲染时用初始搜索词请求一次 —— 这正是第 14 章“依赖要写全”的意义所在，ESLint 也会提醒你。

⚠ 每敲一个键就发一次请求

输入 “javascript” 会依次请求 j、ja、jav、java……共 10 次。这既浪费，也可能触发 API 的限流（rate limiting： 比如每分钟最多 N 次请求，超出就返回错误）。第 22 章会改成“点按钮才搜索”。

竞态条件：后发的请求先回来

服务端搜索还埋着一个更隐蔽的 bug。快速输入 “re” 再改成 “vue”：两个请求几乎同时发出，但网络的快慢不可预测 —— 如果 “re” 的响应比 “vue” 晚到，它会覆盖掉正确的结果，搜索框里写着 vue，列表却是 re 的内容。

解决办法是 effect 的清理函数（第 14 章）。搜索词一变，React 会先运行上一次 effect 的清理函数 —— 我们在里面把上一次请求标记为“作废”，甚至直接取消它：

```jsx src/App.jsx useEffect(() => { if (!searchTerm) return; const controller = new AbortController(); dispatchStories({ type: 'STORIES_FETCH_INIT' }); fetch(`${API_ENDPOINT}${searchTerm}`, { signal: controller.signal }) .then((response) => response.json()) .then((result) => { dispatchStories({ type: 'STORIES_FETCH_SUCCESS', payload: result.hits, }); }) .catch((error) => { // 被主动取消的请求不算失败 if (error.name === 'AbortError') return; dispatchStories({ type: 'STORIES_FETCH_FAILURE' }); }); // 搜索词变化或组件卸载时，取消还没完成的旧请求 return () => controller.abort(); }, [searchTerm]); ```
ⓘ 原书没有讲这一步

为了保持简单，原书的代码没有处理竞态条件，后续章节也会继续在此基础上演进。 本教程在这里补充它，是因为这是“在 useEffect 里请求数据”最常见的真实 bug； React 官方文档也把它作为 effect 需要清理的典型例子。接下来的章节为了和原书保持一致，代码里会省略这部分，但你心里要知道它的存在。

现代应用怎么获取数据？

在 useEffect 里手写 fetch 是理解原理的最佳方式，但真实项目里你还需要处理缓存、去重、重试、竞态、后台刷新…… 所以今天的主流做法是：

手写 effect 学习用 / 小项目
```jsx useEffect(() => { dispatch({ type: 'INIT' }); fetch(url) .then((r) => r.json()) .then((data) => dispatch({ type: 'SUCCESS', payload: data })) .catch(() => dispatch({ type: 'FAILURE' })); }, [url]); ```
数据请求库 生产项目
```jsx import { useQuery } from '@tanstack/react-query'; const { data, isPending, isError } = useQuery({ queryKey: ['stories', searchTerm], queryFn: () => fetch(`${API_ENDPOINT}${searchTerm}`).then((r) => r.json()), }); // 缓存、去重、竞态、重试都已处理 ```

使用 Next.js、React Router 等框架时，数据通常在路由层（loader / 服务端组件）获取，更不需要 useEffect。 本教程继续手写，因为理解底层机制之后，你才知道这些库替你做了什么。

小结

  • fetch(url).then(r => r.json()) 获取远程 JSON；Hacker News 的文章在 result.hits 里。
  • 客户端搜索在浏览器过滤已有数据；服务端搜索把搜索词发给服务器，返回过滤后的结果。
  • 把 searchTerm 放进 effect 的依赖数组，搜索词变化时就会重新请求。
  • 并发请求可能乱序返回（竞态条件），用清理函数 + AbortController 取消过期的请求。
  • 生产项目通常用 TanStack Query 等库或框架的数据加载机制。

面试题

在 React 中如何从 API 获取数据？

基础做法是在 useEffect 中调用 fetch/axios，把结果、加载与错误状态存进 state；生产中常用 TanStack Query 等库或框架提供的数据加载机制。

客户端搜索和服务端搜索有什么区别？

客户端搜索在浏览器中过滤已加载的数据，快但受限于数据量；服务端搜索把查询发给服务器，适合大数据集但每次需要网络往返。

useEffect 的依赖数组在数据获取中起什么作用？

决定何时重新请求：依赖（如搜索词、URL）变化时 effect 重新执行，从而获取新数据。

什么是竞态条件？如何避免？

多个异步请求的响应顺序与发出顺序不一致，导致旧数据覆盖新数据。可在 effect 清理函数中用 AbortController 取消旧请求，或设置 ignore 标志忽略过期响应。

如何减少频繁的 API 请求？

防抖（debounce）、节流（throttle），或改为用户显式提交时才请求。
