现代应用离不开表单。这一章先用传统方式把输入框和按钮包进一个真正的 <form>（onSubmit + preventDefault）， 再升级为 React 19 的 form Actions：<form action={fn}>。 这是 React 19 最重要的新特性之一，也是新旧写法差异最大的地方。

本章目标

  • 用 <form onSubmit> 提交搜索，理解 preventDefault 的作用
  • 把表单提取成 SearchForm 组件
  • 改用 React 19 的 <form action={fn}>，理解它和 onSubmit 的区别
  • 认识配套的新 Hook：useActionState、useFormStatus、useOptimistic

第一步：换成真正的表单

表单就是一个“把若干输入控件的数据通过按钮提交出去”的容器。用 <form> 包住输入框和按钮， 带来的直接好处是：在输入框里按回车就能提交，键盘用户和读屏软件用户也更友好。

```jsx src/App.jsx const App = () => { ... return (

My Hacker Stories

Search:
...
); }; ```

处理函数从按钮的 onClick 挪到了表单的 onSubmit，按钮的 type 改成 "submit"， 表示“点我就提交所在的表单”。处理函数里还要加一句 event.preventDefault()：

```jsx src/App.jsx const handleSearchSubmit = (event) => { setUrl(`${API_ENDPOINT}${searchTerm}`); event.preventDefault(); }; ```

原生 HTML 表单提交时，浏览器会把数据发送到 action 属性指定的地址并刷新整个页面 —— 这是服务器渲染时代（第 1 章）的遗产。对单页应用来说刷新意味着所有状态丢失，所以要调用 preventDefault() 阻止它。

第三步：React 19 的 form Actions

HTML 的 <form> 本来就有 action 属性（提交地址）。React 19 扩展了它： 可以给 action 传一个函数，表单提交时 React 会调用这个函数。

```jsx src/App.jsx const SearchForm = ({ searchTerm, onSearchInput, searchAction }) => (
Search:
); ``` ```jsx src/App.jsx const App = () => { ... const searchAction = () => { setUrl(`${API_ENDPOINT}${searchTerm}`); // event.preventDefault(); ← 不再需要了 }; ... return (

My Hacker Stories

...
); }; ```

preventDefault 消失了：使用函数形式的 action 时，React 自己会拦截原生提交、不刷新页面。 这种写法更贴近原生表单的语义，也是 React 19 之后推荐的提交方式。

onSubmit React 18 及以前的惯例
```jsx const handleSubmit = (event) => { event.preventDefault(); // 必须手动阻止刷新 const data = new FormData(event.target); save(data.get('title')); };
```
action React 19
```jsx const saveAction = (formData) => { // 直接拿到 FormData save(formData.get('title')); };
```

action 函数能拿到 FormData

action 函数的参数就是表单的 FormData。只要输入框有 name 属性，就能按名字取值 —— 这意味着简单的表单甚至不需要为每个字段写状态（第 12 章讲的非受控写法）：

```jsx const searchAction = (formData) => { const term = formData.get('search'); // 需要 setUrl(`${API_ENDPOINT}${term}`); }; ```

我们的搜索框是受控组件，searchTerm 本来就在状态里，所以沿用原书的写法直接读状态即可。
