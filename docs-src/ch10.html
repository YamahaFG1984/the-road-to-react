props 负责把数据往下传，但它们是只读的。可界面总有会变化的东西：输入框里的字、 列表里的数据、一个开关是开是关。React 里用来保存“会随时间变化的数据”的东西叫 state（状态）。 这一章是整个 React 最核心的一章。

本章目标

  • 明白为什么普通变量不能驱动界面更新
  • 用 useState 声明状态、读取状态、更新状态
  • 理解“状态变化 → 重新渲染”的完整循环
  • 了解 Hook 的规则，以及类组件 this.setState 的旧写法

一个行不通的尝试

需求：用户在搜索框输入什么，就在下面显示“正在搜索：xxx”。很自然的第一反应是用一个变量：

```jsx src/App.jsx（不能工作的版本） const Search = () => { let searchTerm = ''; const handleChange = (event) => { searchTerm = event.target.value; }; return (

Searching for {searchTerm}.

); }; ```

在浏览器里试试：无论输入什么，下面的文字都不会变。为什么？

我们需要一种变量，它要满足两个条件：

  1. 值能在多次渲染之间保留下来（不会每次重置）；
  2. 值被改变时，能通知 React 重新渲染。

这就是 useState。

useState

```jsx src/App.jsx import { useState } from 'react'; const Search = () => { const [searchTerm, setSearchTerm] = useState(''); const handleChange = (event) => { setSearchTerm(event.target.value); }; return (

Searching for {searchTerm}.

); }; ```

现在打字，下面的文字会实时跟着变。拆开这一行看看：

  • useState(初始值) 返回一个数组：[当前值, 更新函数]。
  • 用数组解构把两项取出来，名字可以任意取，惯例是 [xxx, setXxx]。
  • 初始值只在第一次渲染时生效；之后每次渲染，useState 都返回最新的值。
ⓘ useState 还是 React.useState？

原书写的是 import * as React from 'react' 再用 React.useState， 本教程和 react.dev 官方文档一样写 import { useState } from 'react'。 两者完全等价，选一种在项目里保持一致即可。

状态更新的完整循环

这就是首页那句 UI = f(state) 的完整含义：你从不直接修改界面，你只修改状态； React 用新的状态重新调用组件函数，得到新的界面。

谁会重新渲染？

动手试试：在 App、Search、List 里各加一句 console.log('X 渲染了')。 首次加载时三个都会打印；在搜索框里打字时，只有 Search 会打印。 规则是：状态变了，拥有这个状态的组件和它的所有后代组件会重新渲染，其他组件不受影响。

ⓘ 日志打印了两次？

那是 StrictMode 在开发环境下故意双重渲染（第 6 章）。生产环境只会渲染一次。

状态存在哪里？

你可能会疑惑：组件函数每次都从头执行，useState('') 每次都会被调用，为什么没有被重置？ 答案是：状态并不存在于函数里，而是存在 React 为每个组件实例维护的一块“记忆”里。 useState 的作用是在这块记忆里按调用顺序取出属于你的那一格：

这直接引出了 Hook 的两条规则：

⚠ Hook 的规则
  1. 只在组件（或自定义 Hook）的顶层调用 Hook。不要在 if、循环、嵌套函数里调用 —— 否则调用顺序会变，状态就对不上号了。
  2. 只在 React 函数组件或自定义 Hook 里调用 Hook，不要在普通 JavaScript 函数里调用。

名字以 use 开头的函数就是 Hook。Vite 模板自带的 eslint-plugin-react-hooks 会帮你检查这两条规则。

几个值得知道的细节

一个组件可以有多个状态，状态可以是任何类型

```jsx const [searchTerm, setSearchTerm] = useState(''); // 字符串 const [count, setCount] = useState(0); // 数字 const [isOpen, setIsOpen] = useState(false); // 布尔 const [stories, setStories] = useState([]); // 数组 const [user, setUser] = useState({ name: 'Robin' }); // 对象 ```

setState 不会立刻改变当前变量

```jsx const handleChange = (event) => { setSearchTerm(event.target.value); console.log(searchTerm); // 打印的还是旧值！ }; ```

searchTerm 是这一次渲染时的值，像一张快照。setSearchTerm 只是请求 React 安排一次新的渲染，新值要到下一次渲染时才能看到。同一个事件里多次 setState 会被合并成一次渲染（批处理）。

基于旧值更新时，传一个函数

```jsx // 连续调用三次，只加了 1：三次读到的 count 都是同一个快照 setCount(count + 1); setCount(count + 1); setCount(count + 1); // 传入“更新函数”，每次拿到的是最新值：加了 3 setCount((c) => c + 1); setCount((c) => c + 1); setCount((c) => c + 1); ```

Vite 模板里的 setCount((count) => count + 1) 用的就是这种写法。

对象和数组要“替换”，不要“修改”

```jsx // ❌ 直接修改：React 发现还是同一个对象，可能不会重新渲染 user.name = 'Dennis'; setUser(user); // ✅ 创建新对象 setUser({ ...user, name: 'Dennis' }); ```

旧写法：类组件的 this.state

类组件 旧写法
```jsx class Search extends React.Component { constructor(props) { super(props); this.state = { searchTerm: '' }; this.handleChange = this.handleChange.bind(this); } handleChange(event) { // setState 会“合并”对象 this.setState({ searchTerm: event.target.value }); } render() { return (

Searching for {this.state.searchTerm}

); } } ```
函数组件 + useState 现在
```jsx const Search = () => { const [searchTerm, setSearchTerm] = useState(''); const handleChange = (event) => { // useState 的 setter 是“替换”，不是合并 setSearchTerm(event.target.value); }; return (

Searching for {searchTerm}

); }; ```
  • 类组件只有一个 this.state 对象，setState 会把新字段浅合并进去；函数组件可以有多个独立的 useState，每个 setter 是整体替换。
  • 自动批处理：React 17 及以前，只有在 React 事件处理函数里的多次 setState 会合并；在 setTimeout、Promise 回调里每次 setState 都会单独渲染一次。React 18 起（使用 createRoot）所有地方都自动批处理。

小结

  • 普通变量改变不会触发渲染，而且每次渲染都会被重置。
  • const [value, setValue] = useState(initial)：读 value，用 setValue(新值) 更新并触发重新渲染。
  • 状态变化 → 拥有状态的组件及其子树重新渲染 → 界面更新。
  • Hook 只能在组件顶层调用，不能放进条件或循环。
  • setState 后当前变量不变（快照）；依赖旧值更新时用函数形式 setX(x => …)。

面试题

什么是 useState？

让函数组件拥有状态的 Hook。const [state, setState] = useState(initialState)，返回当前值和更新函数；调用更新函数会触发重新渲染。

什么会触发组件重新渲染？

组件自身的状态改变、父组件重新渲染（进而传入的 props 可能改变）、以及它使用的 Context 值改变。

调用 setState 后状态会立即更新吗？

不会。React 会批量处理更新并安排一次重新渲染；当前渲染中的状态变量仍是旧值，新值在下一次渲染时可见。

为什么不能在 if 语句里调用 Hook？

React 依赖 Hook 的调用顺序来对应每个状态；条件调用会导致不同渲染之间顺序不一致，状态错乱。

多个 useState 和一个存对象的 useState 有什么区别？

多个 useState 是相互独立的状态；一个对象状态把多个值放在一起，但更新时需要手动展开旧对象（setter 不会合并）。相关性强的多个值也可以考虑 useReducer（第 20 章）。

可以直接修改 useState 返回的状态吗？

不可以。应始终通过 setter 并以不可变的方式（创建新对象/数组）更新，否则 React 可能检测不到变化。
