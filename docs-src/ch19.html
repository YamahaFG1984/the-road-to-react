真实应用的数据来自服务器，而网络请求需要时间 —— 数据是异步到达的。 这意味着组件必须先在“没有数据”的状态下渲染一次，等数据到了再渲染一次。 这一章先用一个假的异步函数模拟网络请求，再学习如何根据“加载中 / 出错 / 有数据”显示不同的界面。

本章目标

  • 用 Promise + setTimeout 模拟异步数据
  • 在 useEffect 中获取数据并存入状态
  • 掌握条件渲染的三种写法：提前 return、三元运算符、&&
  • 给用户展示加载中和出错的反馈

模拟一个异步 API

先写一个函数，它返回一个 Promise，Promise 兑现（resolve）后给出和真实 API 结构类似的数据：

```jsx src/App.jsx const initialStories = [ ... ]; const getAsyncStories = () => Promise.resolve({ data: { stories: initialStories } }); ```

App 里的列表状态改成以空数组开始，然后在 effect 里“请求”数据。依赖数组为空，所以只在组件第一次渲染后执行一次：

```jsx src/App.jsx const App = () => { ... const [stories, setStories] = useState([]); useEffect(() => { getAsyncStories().then((result) => { setStories(result.data.stories); }); }, []); ... }; ```

数据几乎是瞬间出现的，看不出“异步”。给它加 2 秒延迟，更像真实的网络请求：

```jsx src/App.jsx const getAsyncStories = () => new Promise((resolve) => setTimeout( () => resolve({ data: { stories: initialStories } }), 2000 ) ); ```

刷新页面：先是一个空列表，2 秒后列表出现。

ⓘ 为什么初始值是 [] 而不是 null？

List 会对列表调用 .map()，App 会调用 .filter()。 空数组上调用它们没问题（结果还是空数组）；如果初始值是 null，null.map() 会直接报错崩溃。 选一个“空但类型正确”的初始值，可以省掉很多判断。

根据状态显示不同的 JSX，叫条件渲染。异步数据是条件渲染最典型的场景：刚开始没有数据， 然后在加载，最后有了数据 —— 也可能失败。先加一个加载状态：

```jsx src/App.jsx const App = () => { ... const [stories, setStories] = useState([]); const [isLoading, setIsLoading] = useState(false); useEffect(() => { setIsLoading(true); getAsyncStories().then((result) => { setStories(result.data.stories); setIsLoading(false); }); }, []); ... }; ```

处理错误

模拟的请求不会失败，但真实网络请求会。再加一个错误状态，在 Promise 的 catch() 里设置它：

```jsx src/App.jsx const App = () => { ... const [stories, setStories] = useState([]); const [isLoading, setIsLoading] = useState(false); const [isError, setIsError] = useState(false); useEffect(() => { setIsLoading(true); getAsyncStories() .then((result) => { setStories(result.data.stories); setIsLoading(false); }) .catch(() => setIsError(true)); }, []); ... }; ```

写法三：逻辑与 &&

错误提示是“要么显示、要么什么都不显示”。这种情况用 && 比 条件 ? JSX : null 更简洁：

```jsx src/App.jsx return (
...
{isError &&

Something went wrong ...

} {isLoading ? (

Loading ...

) : ( )}
); ```

JavaScript 里，true && 'Hello' 的结果是 'Hello'，false && 'Hello' 的结果是 false。 而第 4 章说过，React 渲染 false 时什么都不显示 —— 两者配合就成了“条件为真才显示”。

⚠ && 的经典陷阱：数字 0

{stories.length && <List … />} 在列表为空时，表达式结果是数字 0， 而 React 会把 0 渲染出来（只有 false/null/undefined 不显示）。 页面上会莫名其妙多出一个 “0”。左边请写成真正的布尔值：stories.length > 0 && …。

🔎 深入一点：React 19 的 Suspense 与 use()

手动管理 isLoading / isError 是最基础、最通用的做法，也是理解数据获取的起点。 React 19 还提供了另一种声明式的思路：组件用 use(promise) 直接“读取”一个 Promise， 数据没到时由外层的 <Suspense fallback={…}> 显示加载界面，出错时由错误边界（Error Boundary）接住。 这种写法通常要配合框架或数据请求库（它们负责缓存 Promise）才好用，第 25 章会简单介绍，第 38 章会结合错误边界完整演示。

小结

  • 异步数据意味着组件先以“空数据”渲染，数据到达后再重新渲染；初始状态选空数组比 null 更安全。
  • 在 useEffect(fn, []) 里发起请求，结果用 setter 存进状态。
  • 条件渲染：提前 return、三元 ? :、逻辑与 &&。
  • 用 isLoading、isError 给用户反馈；小心 0 && 渲染出 0。

面试题

为什么在数据获取前 stories 为空数组时不需要条件渲染？

对空数组调用 map() 返回空数组，React 什么也不渲染，不会出错。

如果 stories 初始值是 null 会怎样？

对 null 调用 map() 会抛出异常，需要额外的条件判断。

React 中有哪些条件渲染的方式？

if 提前返回、三元运算符、逻辑与 &&、返回 null、先用变量存放 JSX 再渲染。

能在条件语句或循环中调用 useState 吗？

不能。Hook 必须在组件顶层调用；条件应该写在渲染逻辑里，而不是包住 Hook。

如何处理异步请求中的加载和错误状态？

用状态记录加载与错误，请求开始前设置加载，成功/失败后分别更新，并据此条件渲染；也可以用 Suspense 和错误边界的声明式方案。
