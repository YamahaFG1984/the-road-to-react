这一章我们用 Vite 创建项目 hacker-stories，把它在浏览器里跑起来， 然后逐个认识生成出来的文件：哪些要天天改，哪些永远不用碰，以及 npm run dev 背后到底发生了什么。

本章目标

  • 用一条命令创建 React + Vite 项目并启动开发服务器
  • 认识项目结构：index.html → main.jsx → App.jsx 的加载链路
  • 掌握四个 npm 脚本：dev、build、preview、lint
  • 知道开发环境和生产环境的区别

Vite 是什么

Vite（法语“快”，读作 /vit/）是一个前端构建工具。它主要做两件事：

⚡

开发服务器

在本地启动一个网站，你改代码、保存，浏览器几乎瞬间更新（热更新 HMR）。

📦

打包器

上线前把几十上百个源文件压缩合并成几个优化过的文件，放进 dist/ 目录。

浏览器不认识 JSX（第 4 章会讲），也不认识 import './App.css' 这种“导入 CSS”的写法。 Vite 在中间做翻译，让我们可以专心写 React。

创建项目

打开终端，进入你想放项目的文件夹。几个最基本的命令行操作：

然后运行：

```bash npm create vite@latest hacker-stories -- --template react ```

--template react 选择“React + JavaScript”模板。如果你已经熟悉 TypeScript， 也可以用 react-ts 模板；本教程正文用 JavaScript，第 29 章再专门讲 TypeScript。 接着按提示进入目录、安装依赖、启动：

```bash cd hacker-stories npm install # 按 package.json 安装所有依赖到 node_modules/ npm run dev # 启动开发服务器 ```

终端会打印一个地址，通常是 http://localhost:5173/。用浏览器打开，看到 Vite + React 的欢迎页就成功了。

```console VITE vX.Y.Z ready in 312 ms ➜ Local: http://localhost:5173/ ➜ Network: use --host to expose ➜ press h + enter to show help ```
ⓘ 确认 React 版本

打开 package.json，看 dependencies 里的 react 和 react-dom。 现在的 Vite 模板默认就是 React 19。如果你拿到的是旧模板（React 18），手动升级：

```bash npm install react@latest react-dom@latest # 用 TypeScript 的话，类型定义也要一起升级 npm install --save-dev @types/react@latest @types/react-dom@latest ```

项目结构

在项目目录里运行 code . 用 VS Code 打开，你会看到（不同 Vite 版本可能略有差异）：

```tree hacker-stories/ ├── node_modules/ ← npm 装的所有依赖（几百个包，别碰） ├── public/ │ └── vite.svg ← 原样复制到网站根目录的静态文件 ├── src/ ← 你的代码都在这里 │ ├── assets/ │ │ └── react.svg │ ├── App.css │ ├── App.jsx ← ★ 前 25 章几乎只改这个文件 │ ├── index.css │ └── main.jsx ← ★ 入口：把 React 挂到页面上 ├── .gitignore ├── eslint.config.js ← 代码检查规则 ├── index.html ← ★ 浏览器最先加载的文件 ├── package.json ← 项目名片：依赖列表 + 脚本命令 ├── package-lock.json ← 锁定每个依赖的精确版本（别手改） └── vite.config.js ← Vite 配置 ```
文件 / 目录作用你要做什么
package.json列出依赖（dependencies）、开发依赖（devDependencies）和脚本（scripts）偶尔看看，npm install xxx 会自动改它
package-lock.json记录依赖树的精确版本，保证团队每个人装到一样的东西提交到 Git，不要手改
node_modules/实际安装的依赖代码不提交（已写在 .gitignore），别人 npm install 就能还原
vite.config.jsVite 配置，里面启用了 React 插件加插件、改部署路径时才动（第 27、52 章）
public/不经处理、原样拷贝的静态资源，如 favicon放图标、robots.txt 等
index.html单页应用的“唯一一页”一般只改 <title>
src/main.jsxJavaScript 入口，把 App 渲染进 #root很少改
src/App.jsx根组件主战场

三个文件是怎么串起来的

这是理解整个项目最重要的一张图。浏览器只认识 HTML，所以一切从 index.html 开始：

回忆第 1 章说的“一个很小的 HTML + 一个较大的 JS”：index.html 里真的几乎什么都没有， 只有一个空的 <div id="root"> 和一个指向 main.jsx 的 script 标签。 界面上的一切，都是 JavaScript 运行后生成的。第 6 章会详细讲 createRoot。

Create React App 时代 已废弃
```text public/index.html ← HTML 在 public 里 src/index.js ← 入口叫 index.js src/App.js ← 用 .js 后缀写 JSX package.json: "start": "react-scripts start" "build": "react-scripts build" .eslintrc.json ← 旧式 ESLint 配置 ```
Vite 模板 现在
```text index.html ← HTML 在项目根目录 src/main.jsx ← 入口叫 main.jsx src/App.jsx ← 写 JSX 的文件用 .jsx package.json: "dev": "vite" "build": "vite build" eslint.config.js ← ESLint 新的 flat config ```

老教程里的 npm start、src/index.js 在 Vite 项目里分别对应 npm run dev 和 src/main.jsx。 另外，Vite 要求含 JSX 的文件使用 .jsx 后缀 —— 这让“这个文件里有 JSX”一目了然。

npm 脚本

打开 package.json，找到 scripts：

```json package.json { "scripts": { "dev": "vite", "build": "vite build", "lint": "eslint .", "preview": "vite preview" } } ```

它们都用 npm run 名字 来执行：

```bash # 本地开发：启动开发服务器，改代码自动刷新（按 Ctrl + C 停止） npm run dev # 代码检查：找出可疑写法，比如用了没定义的变量 npm run lint # 生产构建：打包优化，输出到 dist/ 目录 npm run build # 本地预览生产构建的结果（要先 build） npm run preview ```

npm run dev 和 npm run preview（在 build 之后）在浏览器里看到的效果应该一样， 但前者没有做任何生产优化，只能用于本地开发。部署时永远用 build 的产物。

💡 养成习惯

学习过程中让 npm run dev 一直开着，每改一次代码就看一眼浏览器。 再打开浏览器开发者工具（F12）的 Console 面板 —— React 的警告和报错都会显示在那里。

热更新是怎么回事

你在 App.jsx 里改一个字、保存，浏览器几乎瞬间更新，而且页面上输入框里已经输入的内容还在。 这得益于两件东西的配合：Vite 这边的 HMR（Hot Module Replacement，模块热替换）， 和 React 这边的 Fast Refresh（快速刷新）。Vite 发现文件变了，只把这个模块换掉； React 只重新渲染受影响的组件，并尽量保留组件的状态。

小结

  • 用 npm create vite@latest 名字 -- --template react 创建项目，npm install 装依赖，npm run dev 启动。
  • 启动链路：index.html 的 script 标签 → src/main.jsx → 导入 App 并渲染到 #root。
  • dev 用于开发，build 生成 dist/ 用于部署，preview 在本地预览构建产物，lint 做代码检查。
  • 老教程的 npm start / src/index.js / .js 写 JSX，是 Create React App 的习惯。

动手练习

  1. 用 npm run dev 启动项目，然后在终端按 Ctrl+C 停止它。
  2. 运行 npm run build，确认项目里多了 dist/ 目录，打开看看里面有哪些文件、文件名长什么样。
  3. 运行 npm run preview，在浏览器里访问它给出的地址。
  4. 打开 index.html，把 <title> 改成 “Hacker Stories”，观察浏览器标签页的变化。
  5. （可选）git init，把当前项目提交一次。之后每学完一章都提交一次。

面试题

package.json 和 package-lock.json 有什么区别？

package.json 声明项目依赖及其允许的版本范围和脚本；package-lock.json 记录实际安装的精确版本和完整依赖树，保证不同机器安装结果一致。两者都应提交到版本库。

为什么 node_modules 不提交到 Git？

体积巨大且可以通过 npm install 根据 lock 文件精确还原；而且部分依赖是按操作系统编译的，不适合跨机器共享。

npm run dev 和 npm run build 有什么区别？

dev 启动开发服务器，按需编译、支持热更新和详细错误信息，不做优化；build 为生产环境打包、压缩、tree-shaking，输出静态文件到 dist/。

什么是 HMR / Fast Refresh？

HMR 是构建工具在不刷新整页的情况下替换改动的模块；Fast Refresh 是 React 与之配合的机制，只重新渲染被编辑的组件并尽量保留其状态。
