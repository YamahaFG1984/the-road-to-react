JavaScript 的类型错误要等到代码运行时才会暴露：页面白屏、控制台报 “Cannot read properties of undefined”。 TypeScript 把这类错误提前到写代码的时候，在编辑器里就用红线标出来。 这一章把 Hacker Stories 迁移到 TypeScript，并总结 React 里最常用的几种类型写法。

本章目标

  • 在 Vite 项目中启用 TypeScript
  • 给函数、自定义 Hook、组件 props 加类型
  • 用联合类型给 reducer 的 action 做到真正的类型安全
  • 掌握事件、ref、children 的 React 专用类型，以及 React 19 在类型上的变化

为什么用 TypeScript

启用 TypeScript

💡 新项目：直接用 TS 模板

新项目最省事的办法是创建时就选 TypeScript 模板：npm create vite@latest my-app -- --template react-ts， 所有配置都已生成好。下面是把现有 JavaScript 项目迁移过去的步骤。

安装 TypeScript 以及 React 的类型定义：

```bash npm install --save-dev typescript @types/react @types/react-dom npm install --save-dev typescript-eslint ```

新建三个配置文件：tsconfig.app.json（浏览器端代码，也就是 src/）、 tsconfig.node.json（在 Node 中运行的配置文件，如 vite.config.ts），以及把两者合并起来的 tsconfig.json：

重启开发服务器。应用照常运行（Vite 只是去掉类型，并不做类型检查），但编辑器里会出现很多红线 —— 接下来逐个消灭它们。

入口文件

```tsx src/main.tsx createRoot(document.getElementById('root')!).render( ); ```

不加 ! 时 TypeScript 会报错：getElementById 的返回类型是 HTMLElement | null（找不到就返回 null）， 而 createRoot 不接受 null。我们确定 index.html 里有这个元素，于是用非空断言 ! 告诉 TypeScript：“我比你清楚，这里不会是 null。”

给函数和自定义 Hook 加类型

自定义 Hook 本质上就是函数，先给参数加上类型：

```tsx src/App.tsx const useStorageState = (key: string, initialState: string) => { const [value, setValue] = useState( localStorage.getItem(key) ?? initialState ); useEffect(() => { localStorage.setItem(key, value); }, [value, key]); return [value, setValue] as const; }; ```

返回类型可以不写，TypeScript 会推断出来。但数组要加 as const：否则它被推断为“由字符串和函数组成的数组”， 调用方就不知道第一项一定是字符串、第二项一定是函数了。加上 as const 后，它是一个固定长度、每一位类型确定的元组。

useState 的类型推断

```tsx const [value, setValue] = useState('React'); // value 被推断为 string；setValue 只接受 string const [user, setUser] = useState(null); // 初始值是 null 时，要用泛型告诉它将来还可能是什么 ```

给组件 props 加类型

从叶子组件 Item 开始。最直接的写法是把类型写在参数后面，但会又长又重复：

```tsx src/App.tsx const Item = ({ item, onRemoveItem, }: { item: { objectID: string; url: string; title: string; author: string; num_comments: number; points: number; }; onRemoveItem: (item: { objectID: string; url: string; title: string; author: string; num_comments: number; points: number; }) => void; }) => ( ... ); ```

```tsx src/App.tsx type Story = { objectID: string; url: string; title: string; author: string; num_comments: number; points: number; }; type ItemProps = { item: Story; onRemoveItem: (item: Story) => void; }; const Item = ({ item, onRemoveItem }: ItemProps) => (
  • ...
    • ); type ListProps = { list: Story[]; onRemoveItem: (item: Story) => void; }; const List = ({ list, onRemoveItem }: ListProps) => (
      ...
    ); ```

    Story 类型还可以用在 App 的回调里：

    ```tsx src/App.tsx const handleRemoveStory = (item: Story) => { dispatchStories({ type: 'REMOVE_STORY', payload: item, }); }; ```
    React.FC 曾经流行
    ```tsx const Item: React.FC = ({ item }) => ( ... ); ```
    直接标注参数 现在推荐
    ```tsx const Item = ({ item }: ItemProps) => ( ... ); ```

    老代码里常见 React.FC。它早期会隐式地给组件加上 children（React 18 起已去掉），写法也更绕。 今天社区普遍直接给参数标注类型，本教程也这样做。

    给 reducer 加类型

    先描述状态的结构，再描述 action。一个偷懒的写法是：

    ```tsx src/App.tsx type StoriesState = { data: Story[]; isLoading: boolean; isError: boolean; }; type StoriesAction = { type: string; payload: any; }; ```

    但 type: string 和 payload: any 太宽泛了，写错动作名、传错 payload 都不会报错。 更好的做法是为每种动作单独定义类型，再用联合类型把它们组合起来：

    ```tsx src/App.tsx type StoriesFetchInitAction = { type: 'STORIES_FETCH_INIT'; }; type StoriesFetchSuccessAction = { type: 'STORIES_FETCH_SUCCESS'; payload: Story[]; }; type StoriesFetchFailureAction = { type: 'STORIES_FETCH_FAILURE'; }; type StoriesRemoveAction = { type: 'REMOVE_STORY'; payload: Story; }; type StoriesAction = | StoriesFetchInitAction | StoriesFetchSuccessAction | StoriesFetchFailureAction | StoriesRemoveAction; const storiesReducer = ( state: StoriesState, action: StoriesAction ) => { switch (action.type) { ... } }; ```

    这叫可辨识联合：每个成员都有一个字面量类型的 type 字段，TypeScript 在 switch 的每个分支里会自动把 action 收窄到对应的成员。 拼错动作名、给 REMOVE_STORY 传一个数组，都会立刻得到编译错误。

    事件、ref 与 children 的类型

    表单相关的回调参数是 React 的事件类型，泛型参数是触发事件的元素类型：

    ```tsx src/App.tsx type SearchFormProps = { searchTerm: string; onSearchInput: (event: React.ChangeEvent) => void; searchAction: (formData: FormData) => void; }; const SearchForm = ({ searchTerm, onSearchInput, searchAction, }: SearchFormProps) => ( ... ); const App = () => { ... const handleSearchInput = ( event: React.ChangeEvent ) => { setSearchTerm(event.target.value); }; ... }; ```

    useRef 的类型推断不出来，要用泛型说明它将引用什么元素：

    ```tsx src/App.tsx const inputRef = useRef(null); ```

    最后是 InputWithLabel，注意可选 prop 用 ?，children 用 React.ReactNode：

    ```tsx src/App.tsx type InputWithLabelProps = { id: string; value: string; type?: string; onInputChange: (event: React.ChangeEvent) => void; isFocused?: boolean; children: React.ReactNode; }; const InputWithLabel = ({ id, value, type = 'text', onInputChange, isFocused, children, }: InputWithLabelProps) => { ... }; ```
    要标注的东西常用类型
    输入框 onChange 事件React.ChangeEvent<HTMLInputElement>
    按钮点击React.MouseEvent<HTMLButtonElement>
    表单 onSubmitReact.FormEvent<HTMLFormElement>
    form action(formData: FormData) => void | Promise<void>
    children / 任何可渲染的内容React.ReactNode
    DOM refuseRef<HTMLInputElement>(null)
    作为 prop 接收的 ref（React 19）ref?: React.Ref<HTMLInputElement>
    继承原生元素的所有属性React.ComponentProps<'button'>
    ⓘ React 19 在类型上的几处变化
    • useRef 现在必须传参数：useRef() 要写成 useRef(undefined) 或 useRef<T>(null)；所有 ref 对象的 current 都是可写的。
    • 全局的 JSX 命名空间被移除，需要时写 React.JSX.Element。
    • ref 回调不能隐式返回值（第 17 章）：ref={(n) => (x = n)} 会报类型错误。
    • ref 作为普通 prop：组件 props 类型里直接声明 ref?: React.Ref<…>，或用 React.ComponentProps<'input'>（已包含 ref）。
    ⚠ 示例数据和真实数据的 objectID 类型不一样

    我们手写的示例数据里 objectID 是数字 0、1，而 Hacker News API 返回的是字符串 "42345678"。 TypeScript 会立刻指出这个不一致 —— 这正是类型的价值。把 Story 里的类型定义成和真实 API 一致（string），示例数据也相应改成字符串。

    小结

    • 新项目用 react-ts 模板；老项目安装 typescript 和类型包、添加 tsconfig、把 .jsx 改为 .tsx。
    • 给函数参数加类型；自定义 Hook 返回元组时加 as const；useState 多数能推断，初始值为 null 时用泛型。
    • 用 type XxxProps 描述组件 props，直接标注在参数上。
    • reducer 的 action 用可辨识联合，获得真正的类型安全。
    • React 专用类型：React.ChangeEvent、React.ReactNode、useRef<HTMLInputElement>(null) 等。

    动手练习

    1. 完成整个 App.tsx 的类型标注，直到编辑器里没有红线。
    2. 故意 dispatch 一个不存在的动作类型，看看 TypeScript 的报错。
    3. 把 onRemoveItem 的类型提取成 type OnRemoveItem = (item: Story) => void，在两处复用。
    4. 在 package.json 的 build 脚本前加上 tsc -b &&，让构建时也做类型检查。

    面试题

    在 React 中使用 TypeScript 有什么好处？

    在编写代码时发现类型错误、编辑器智能提示更强、类型即文档、重构更安全。

    如何给组件的 props 定义类型？

    定义 type Props = {…}（或 interface），在参数解构处标注：({ a, b }: Props) => …；可选 prop 用 ?。

    children 应该用什么类型？

    通常用 React.ReactNode，它涵盖字符串、数字、元素、数组、null 等所有可渲染内容。

    什么是可辨识联合？在 reducer 中有什么用？

    由若干具有相同字面量字段（如 type）的类型组成的联合。在 switch 中根据该字段自动收窄类型，保证每个 action 的 payload 类型正确。

    为什么自定义 Hook 返回数组时要用 as const？

    让 TypeScript 推断为只读元组而不是普通数组，保留每一位的具体类型和顺序。
