这一章的任务：记住最近的 5 次搜索，把它们显示成按钮，点一下就能重新搜索。 有趣的是，我们不需要新增任何状态 —— 只要把“当前请求的 URL”升级成“所有请求过的 URL 列表”， 最近搜索就可以从中派生出来。

本章目标

  • 把单个 url 状态重构为 urls 数组
  • 从状态派生出“最近搜索”列表，用 slice、map、reduce 处理数组
  • 提取重复逻辑为工具函数和通用处理函数
  • 把新功能提取成独立组件
💡 任务

记住最近 5 个请求过 API 的搜索词，为每个显示一个按钮，点击时重新获取该搜索词的文章。 提示：不要新建状态，而是把 url / setUrl 改成 urls / setUrls； 最后一个 URL 用来请求数据，最后 5 个用来显示按钮。

从 url 到 urls

初始值从一个字符串变成只含一个元素的数组：

```jsx src/App.jsx const App = () => { ... const [urls, setUrls] = useState([`${API_ENDPOINT}${searchTerm}`]); ... }; ```

请求数据时，用数组里的最后一个 URL：

```jsx src/App.jsx const handleFetchStories = useCallback(async () => { dispatchStories({ type: 'STORIES_FETCH_INIT' }); try { const lastUrl = urls[urls.length - 1]; const result = await axios.get(lastUrl); dispatchStories({ type: 'STORIES_FETCH_SUCCESS', payload: result.data.hits, }); } catch { dispatchStories({ type: 'STORIES_FETCH_FAILURE' }); } }, [urls]); ```

提交搜索时，不再替换 URL，而是把新 URL 追加到数组末尾（concat 返回新数组，不修改原数组）：

```jsx src/App.jsx const searchAction = () => { const url = `${API_ENDPOINT}${searchTerm}`; setUrls(urls.concat(url)); }; ```

点击按钮重新搜索

既然请求总是用最后一个 URL，那么“重新搜索”就是再追加一次这个 URL：

```jsx src/App.jsx const handleLastSearch = (searchTerm) => { const url = `${API_ENDPOINT}${searchTerm}`; setUrls(urls.concat(url)); }; ```

这和 searchAction 几乎一样。把共同逻辑提取出来，URL 的拼接也提取成一个工具函数：

```jsx src/App.jsx const getUrl = (searchTerm) => `${API_ENDPOINT}${searchTerm}`; const App = () => { ... // 注意：依然要包在 [] 里 const [urls, setUrls] = useState([getUrl(searchTerm)]); const handleSearch = (searchTerm) => { const url = getUrl(searchTerm); setUrls(urls.concat(url)); }; const searchAction = () => { handleSearch(searchTerm); }; const handleLastSearch = (searchTerm) => { handleSearch(searchTerm); }; ... }; ```
★ 提取之后，再找找第三个使用者

把两处共同的逻辑提取成函数后，顺手检查一下别处还有没有同样的代码 —— 比如 useState 的初始值也可以用 getUrl。

key 冲突

同一个词搜两次，就会出现两个 key 相同的按钮，React 会警告。把下标拼进去让 key 唯一：

```jsx src/App.jsx {lastSearches.map((searchTerm, index) => ( ))} ```

第 5 章说过下标不是理想的 key；但这些按钮没有输入框之类的内部状态，这里不会造成实际问题。

三个体验改进

💡 更多任务
  1. 不要把当前搜索显示成按钮，只显示它之前的 5 个。
  2. 不要显示连续重复的搜索：连搜两次 React 只显示一个按钮。
  3. 点击历史按钮时，搜索框里的文字也要变成那个搜索词。

改进 1：取最后 6 个，再去掉最后一个（当前搜索）：

```jsx src/App.jsx const getLastSearches = (urls) => urls .slice(-6) .slice(0, -1) .map(extractSearchTerm); ```

改进 2：在截取之前，先用 reduce 把相邻的重复项合并：

```jsx src/App.jsx const getLastSearches = (urls) => urls .reduce((result, url, index) => { const searchTerm = extractSearchTerm(url); if (index === 0) { return result.concat(searchTerm); } const previousSearchTerm = result[result.length - 1]; if (searchTerm === previousSearchTerm) { return result; } else { return result.concat(searchTerm); } }, []) .slice(-6) .slice(0, -1); ```

改进 3：点击历史按钮时，同时更新搜索框的状态：

```jsx src/App.jsx const handleLastSearch = (searchTerm) => { setSearchTerm(searchTerm); handleSearch(searchTerm); }; ```

小结

  • 把 url 重构为 urls 数组，最后一个用于请求，其余构成搜索历史 —— 不需要新增状态。
  • “最近搜索”是派生数据：用 slice、map、reduce 从状态计算得到。
  • 提取工具函数（getUrl、extractSearchTerm）和通用处理函数（handleSearch），消除重复。
  • 新功能的界面提取成独立组件，保持 App 轻量。

面试题

为什么这里不需要为搜索历史新建一个状态？

搜索历史可以从已有的 urls 状态派生；新增状态会产生两份需要同步的数据，容易出错。

concat 和 push 有什么区别？在 React 状态中该用哪个？

push 修改原数组并返回新长度；concat 返回新数组不修改原数组。React 状态需要不可变更新，应使用 concat 或展开运算符 [...arr, x]。

什么时候可以用下标作为 key？

当列表项没有稳定 id、且列表项不包含内部状态、或列表不会重新排序时，作为最后手段；与内容拼接可以减少冲突。
